# EngineTests

エンジンの機能を 1 つずつ確かめるためのプロジェクトです。1 つの機能に 1 つのシーンを作ります。

- 形はエンジン組み込みの立方体・球・板だけを使います。モデルは、骨のアニメーションを確かめる箱の人形（`Application/Assets/Models/AnimRobot`）と、メッシュの当たり判定を確かめる地形（`Application/Assets/Models/MeshCourse`・`MeshGround`）と、剛体のカプセルの見た目（`Application/Assets/Models/Capsule`）だけを入れています。どれも台本で作った物です。テクスチャは確かめる機能に要るときだけ、小さいものを `Application/Assets/Textures` に置きます（VolumetricFog_Shafts の穴の開いた板・VolumetricFog_Transparent の粒・Animator_Sprite の番号入りのコマ・UI_NineSlice の枠）。
- 既定で入るもの（既定の床・空の環境光・雲・霧・自動露出・ローカル露出・ブルーム・レンズフレア）は、シーンの `_scene.json` と `_environment.json` で切ります。TAA・CAS は `Application/Config/EngineSettings/CVars.json` で切っています。AO（`r.SSAO.Enabled`）は既定のまま入れています（RTAO を確かめるため）。AO は空の環境光だけを暗くするので、空の環境光を切ったシーンには効きません。
- カメラは固定です。
- このプロジェクトでは組み合わせの不具合は見つかりません。確かめ終わったら、いつものシーン（アラハなど）も 1 回開いてください。

## RTShadow_LocalLights

点光源・スポット・エリアのレイトレーシングの影を確かめます（DXR 1.1 に対応した GPU が要ります）。

左から 5 灯並べています。どのライトの下にも 1m の箱（スポットは球）と細い柱があります。空の環境光を切っているので、影の中は真っ暗になります。

平行光源の無いシーンにはエンジンが既定の太陽を置くので、強さ 0・影を落とさない平行光源（NoDefaultSun）を置いて止めています。

| ライト | 見るところ |
|---|---|
| Point_Sharp | 光源の大きさ 0。箱と柱の影の縁がくっきりする |
| Point_Soft | 光源の大きさ 0.4m。同じ配置で、影の縁が離れるほどぼける |
| Spot | 外角 35 度。柱の影はコーンの外へ出ない |
| Area | 2m × 1m の発光面。柱の影が大きくぼける |
| Point_NoSlot | 5 灯目。影を落とす局所ライトは 4 灯までなので、カメラから最も遠いこのライトだけ影が無い |

確かめ方:

1. 4 灯に影があり、Point_NoSlot だけ影が無い。
2. Point_Sharp のインスペクタで「影を落とす」を外すと、Point_Sharp の影が消え、Point_NoSlot に影が付く。
3. ライトや箱を動かすと影が付いてくる。止めると数フレームで落ち着く。
4. レイトレーシングのデバッグ窓の影のタブに、局所ライトの行（点光源 0 など）が出る。
5. デバッグ窓の「中間結果」で、影の「生の値」（ざらつく）・「履歴」・「マスク」（なめらか）がライトごとに出る。影のノイズ取りは RTDenoiser（ほかの効果と共通の部品）が受け持つ。

## RTAO

レイトレーシングの環境光の遮り（RTAO）を確かめます（DXR 1.1 に対応した GPU が要ります）。

AO は空の環境光だけを暗くするので、このシーンは空の環境光を入れています。太陽の影の中は空の環境光だけで照らされるので、AO の差がいちばんよく見えます。

| 物 | 見るところ |
|---|---|
| Box・Ball | 床に接した根元のまわりが暗くなる |
| Corner_Back・Corner_Side | 壁の内側の隅（床との境目と縦の角）が暗くなる |
| Board_Low | 床から 0.3m 浮いた板。板の下がはっきり暗くなる |
| Board_High | 床から 1.5m 浮いた板。レイの長さ（`r.RTAO.Radius` の既定 1m）より遠いので、板の下の影は Board_Low の下より明るい |

確かめ方:

1. レイトレーシングのデバッグ窓の「概要」に「環境光の遮り（RTAO）」の行が出て、状態が撃てている（Dispatched）になる。
2. その行の「ON」を外すと SSAO に切り替わる。SSAO は画面に映った物しか見ないので、Board_Low の下や壁の隅の暗がりの形が変わる。
3. 「中間結果」で RTAO の「生の値」（ざらつく）・「履歴」・「AO」（なめらか）が出る。
4. Project Settings の Rendering Techniques で `r.RTAO.Radius` を 2 にすると、Board_High の下も暗くなる。`r.RTAO.Enabled` を外すと SSAO に、`r.SSAO.Enabled` を外すと AO が無くなる。
5. Box を動かすと暗がりが付いてくる。止めると数フレームで落ち着く。

## 画素デバッガ（レイの追跡）

レイトレーシングのデバッグ窓の「レイの追跡」で、選んだ 1 画素に効果が撃ったレイが出るかを確かめます。専用のシーンは作らず、上の 2 つのシーンを使います。

確かめ方:

1. RTShadow_LocalLights を開き、「レイの追跡」で「ゲーム画面で選ぶ」を押して、Point_Sharp の箱の影の中の床をクリックする。初めてのときは記録版のシェーダを作るので少し止まる。
2. 表に「影（点光源・枠 N）」の行が出て、そのライトへのレイの結果が「遮られた」、物の列が箱か柱になる。影の外の床を選ぶと「抜けた」になる。
3. ゲーム画面に、白いカメラのレイと、床からライトへ向かう効果の色の線が出る。「効果」で 1 つの影に絞ると、表と線がその影だけになる。
4. RTAO を開き、Board_Low の下の床を選ぶと「環境光の遮り（RTAO）」の行が出て、1m までのレイが板に「遮られた」になる。
5. RTAO.CS.hlsl の `RTRecordBeginPixel` の次の行へ一時的に `RT_DEBUG_PRINT(traceCoord);` を足し、エディタを開き直す。「シェーダの値（RT_DEBUG_PRINT）」に、選んだ画素のトレース解像度の座標（画面の座標の半分）と行番号が出る。確かめたら消す。
6. 水面のレイ（水のコースティクス・屈折・反射）は、このプロジェクトに水が無いので、アラハのシーンで水面を選んで確かめる。

## LightGizmos

シーンビュー（エディタの Game ビュー）に出るライトのアイコンと、選んだライトの届く範囲の線を確かめます。

4 種類のライトを 1 灯ずつと、コンポーネントを切った点光源を 1 灯置いています。

| ライト | 見るところ |
|---|---|
| Sun | 平行光源。右奥の太陽のアイコン。選ぶと光の進む向きの矢印が 5 本出る |
| Point | 点光源（橙・高さ 2m・届く距離 5m）。電球のアイコン。選ぶと半径 5m の球が出て、床に埋まった下半分は薄くなる |
| Spot | スポットライト（外角 35 度・内角 25 度・届く距離 6m）。アイコンは光の向きへ回る。選ぶと円すいと、内角の縁が薄い線で出る |
| Area | エリアライト（水色・2m × 1m・届く距離 5m）。アイコンは光の向きへ回る。選ぶと発光面の枠と、前側の半球が出る |
| Point_Disabled | Light のコンポーネントを切った点光源（赤）。アイコンが灰色になる |

確かめ方:

1. 5 つのアイコンがライトの位置に出て、色がライトの色（Point_Disabled だけ灰色）になる。床や物に隠れず、カメラを引いても同じ大きさのまま。
2. アイコンにカーソルを乗せると下に名前が出る。クリックするとそのライトが選ばれ、Hierarchy がその行までスクロールし、アイコンが大きくなって黄色の輪が付く。
3. 選んだライトにだけ範囲の線が出る。インスペクタで届く距離・角度・発光面の大きさ・向きを変えると線が付いてくる。Spot と Area は、向きを変えるとアイコンも回る。
4. 範囲の線は、床に埋まった所と物の後ろに回った所だけ薄くなる（アイコンは隠れない）。カメラを回しても、薄い所と濃い所の境目は床との交わりから動かない。Floor を選んで少し上げると、薄い所が増える。
5. 選んだまま移動のギズモの矢印をドラッグしても、アイコンのクリックにはならない。アイコンの無い所をクリックすると、いつものように物が選ばれる。
6. Point_Disabled を選ぶと、線も灰色で出る。コンポーネントを入れ直すと赤に戻る。
7. Console で `d.Light.Visualize 0` にすると、アイコンも線も消える。`1` で戻る。

届く距離は、光がちょうど 0 になる距離です。明るさは距離の 2 乗で弱まるので、床が目に見えて明るい所は球の線よりかなり内側になります（線が大きすぎるのではありません）。

## Light_SavedSun

保存した既定の太陽（Sun）が、ほかの平行光源と並んでいても消えないことを確かめます。

シーンに平行光源が無いとエンジンが既定の太陽 Sun を置き、Sun を保存したシーンでは保存した値を Sun へ当てます。このシーンには、保存した Sun と、もう 1 灯の平行光源 Fill を置いています。

| 物 | 見るところ |
|---|---|
| Sun | 保存した既定の太陽。左手前の上から暖色で照らし（12000 lux）、影を落とす |
| Fill | もう 1 灯の平行光源。右から青く照らす（4000 lux・影なし） |
| Floor・Ball・Block | 照らされる床・球・箱 |

確かめ方:

1. 開くと Hierarchy に Sun と Fill が両方ある。球と箱は左手前から暖色に照らされ、右奥へ影が落ちる（v0.96.0 までは開いた時点で Sun が消え、Fill だけの暗い画になった）。
2. Ctrl+S で保存し、File ▸ シーンを再読み込みしても Sun は残る。シーンのフォルダの Sun.json も残る（v0.96.0 までは保存すると Sun.json も消えた）。
3. Console の「クリア」を押すと、ログが消えて「コンソールログをクリアしました」の 1 行になる（どのシーンでも同じ。v0.96.0 までは押すとエディタが落ちた）。

## WaterFoam

白波の泡を確かめます。いま砕けている波頭の泡と、砕けた後にその場へ残って消えていく泡の 2 つです。

風速 14m/s の外洋です。カメラは原点の高さ 20m から少し見下ろしています。

残る泡はゲームのカメラのまわりの 2 枚の格子に溜めます。近い方は 256m 四方を 25cm 刻み、遠い方は 1024m 四方を 1m 刻みです。その外は、格子の中で測った残りの泡の平均の濃さで塗ります。

確かめ方:

1. 再生して水面を選ぶ。インスペクタの水面の欄の下の「水面の可視化」で「泡の内訳」を選ぶ。赤（いま砕けている泡）が出た後ろに緑（残りの泡）が尾を引き、数秒かけて消える。緑は赤が出た所にだけ出る。
2. 「白波の割合」の実測が目標に近い（目標の 80〜100%）。「実測の内訳」で、残りが砕けている最中より多い。
3. 「泡が消えるまでの時間」を 10 にすると、緑の尾が長くなる。白波の割合の実測は目標のまま変わらず、内訳の砕けている最中が減る（全体の量が目標に合うように、砕ける量の方を減らす）。
4. MainCamera の高さを 150、下向き（Transform の回転 X）を 1.2 にする。泡が 127m ごと（FFT の 2 枚目の大きさ）に同じ形で並ばない。1km より先は平均の濃さで一様になり、格子の端に段が出ない。
5. MainCamera の位置 X を 100 ずつ動かす。泡は水面のその場に残り、カメラと一緒に動かない。
6. MainCamera の高さを 5、下向きを 0.6 にする。泡は大小の網目と房の形で、同じ形が規則的に並ばない。砕けた直後の泡は白く厚く、数秒たつと薄く透けた網目になって消えていく。
7. 6 の構図から高さを 20・150 と上げる。遠くの泡は網目から平均の濃さへなだらかに変わり、ちらつかない。
8. 6 の構図で「泡の内訳」を見る。緑の尾が消える速さが場所ごとに違う（同じ長さにそろわない）。
9. 6 の構図で「表示」を「泡と気泡」にする。砕けている波頭のまわりに青（水の中の気泡）が出て、1 秒ほどで消える。白（水面の泡）の量と形は「泡が浮いてくる時間」を変えても変わらない（白波の泡は砕けたその場で白くなる）。
10. 6 の構図で「白波の泡がにじむ速さ」を 0 にすると、残りの泡が塊のまま残る。0.05 では塊が少しずつにじんで薄い筋へ割れていく（違いは小さい）。どちらでも「白波の割合」の実測はほとんど変わらない。0.05 に戻す。

## Water_FoamPattern

泡の模様の画像（`r.Water.Foam.PatternTexture`）を確かめます。白波の泡の網目を、大小の穴があいて膜が残る画像（`Engine/Assets/Textures/Water` の FoamNet と FoamGrain）で描きます。

WaterFoam と同じ外洋で、風速を 20m/s にして白波を増やしています。カメラは原点の高さ 8m から下向き 0.5（約 29°）で見下ろしています。

確かめ方:

1. 再生して 30 秒ほど待つ。近くの泡は大小の穴のあいた不揃いな欠片で、線で区切られた四角や多角形のセルの形に並ばない。
2. 水面を選び、インスペクタの「泡」の「泡の模様に画像を使う（プロジェクト）」を切る。泡が細い線で区切られたセルの網目（前の版の模様）に変わる。白い所の広さはほとんど変わらない。入れ直す。
3. MainCamera の高さを 20 にする。泡が 4m ごと（画像の大きさ）に同じ形で並ばない。
4. MainCamera の高さを 150、下向き（Transform の回転 X）を 1.2 にする。同じ形が並ばず、遠くの泡は網目から平均の濃さへなだらかに変わり、ちらつかない。
5. 高さ 8・下向き 0.5 に戻す。

## Water_FFTPond

主の水を FFT の海で描いたとき、岸の細かい格子（ゲームのカメラのまわり 256m 四方を 0.5m 間隔）が水面の範囲の中だけに出ることを確かめます。

上の面が高さ 0 の床に一辺 100m の穴を開け、そこに池（中心 (60, 0.3, 80)・一辺 100m・FFT の海・高さの倍率 0.2）を張っています。穴の底は高さ -5 です。風はシーンで指定していないので既定の 18m/s です。カメラは池の左手前の高さ 12m から池の中心の方を見ています。雲・霧・ブルーム・自動露出は切っています。

| 物 | 見るところ |
|---|---|
| Ground_West・Ground_East・Ground_South・Ground_North | 池のまわりの床。水も泡も乗らない |
| Pond_Bottom | 池の底 |
| Water | 池。穴の縁でまっすぐに切れる |
| Box_OutsideLeft・Box_OutsideNear | 池の外の床に立てた柱。根元の床に映り込みが出ない |
| Box_Inside | 池の中に立てた柱 |

確かめ方:

1. シーンを開く。水は穴の中だけに出て、手前と左の床は灰色のまま。池の外の 2 本の柱の根元に、水面の映り込みが出ない。
2. Water の「高さの倍率」を 1 にする。池の外の地平線の上に、細い水の帯が出ない。0.2 に戻す。
3. MainCamera の位置を (-100, 15, -20)、回転を X 0.08・Y 1.01 にする（カメラのまわり 256m 四方が池に一部だけ重なる）。池の外に水が出ず、池の中に隙間や段が出ない。
4. MainCamera の位置を (-330, 25, -60)、回転を X 0.06・Y 1.23 にする（256m 四方が池と重ならない）。池の外に水が出ない。
5. MainCamera を元の位置 (0, 12, -30)・回転 X 0.1069・Y 0.4636 に戻す。

## Water_Ripple

水面の波紋（`Water::AddRipple`）を確かめます。落とした石の輪が広がることと、進む物の後ろに航跡が引くこと、長い波紋が水面の形と浮力の高さに入ることです。物が水の中を進んだり、落ちたり上下したりすると、そこから波紋が起こることと、速くかき回した所に白い泡が残ることも確かめます。

一辺 100m の穏やかな水（FFT の海・高さの倍率 0.05・風 3m/s）を原点に張り、底を高さ -3.5 に置いています。カメラは高さ 6m・手前 12m から原点を見下ろしています。雲・霧・ブルーム・自動露出は切っています。

| 物 | 見るところ |
|---|---|
| Water | 波紋を描く水面 |
| Pond_Bottom | 水の底（砂の色の箱） |
| RippleProbe | 試験のスクリプト（RippleProbe）。2 秒ごとに原点へ石を落とし（半径 0.3m・深さ 5cm）、原点の周りの半径 6m の円を 2m/s で回る点の後ろに航跡を引く |
| BigDrop | RippleProbe をもう 1 つ。5 秒ごとに (-4, 0, 8) へ大きな石を落とす（半径 1.2m・深さ 30cm）。円を回る点は使わない |
| FloatBox | 浮力（Buoyancy）で浮く箱（1×0.5×1m・150kg）。BigDrop から 2.5m 右。浮力の「波紋の強さ」が 1 なので、揺れるとそこから波紋を起こす |
| HeightProbe | 水面の高さを調べる点（WaterProbe）。BigDrop から 2.5m 手前 |
| WakeBoat | 波紋を起こす（WaterRippleEmitter）白い板（0.6×0.4×1.6m）。剛体は付いていない。下半分が水に沈んだまま、試験のスクリプト（RippleBoatProbe）で (8, 0, -4) から奥へ 30m を 3m/s で往復する |
| DropBox | 浮力（Buoyancy）で浮く緑の箱（0.6m・60kg）。試験のスクリプト（RippleDropBoxProbe）で 6 秒ごとに (1.5, 1.5, 3) へ戻して落とし直す |

確かめ方:

1. 再生する。2 秒ごとに原点から輪が広がる。輪は外へ進みながら、外側に長い波・内側に短い波が並ぶ輪の列に分かれ、だんだん消える。
2. 円を回る点の後ろに、V の字に開く航跡が引く。
3. BigDrop の輪が届くたびに、FloatBox が上下に揺れる（波紋の分は ±2〜3cm で、穏やかな波の揺れに重なる）。原点の石や航跡の細かい輪では、ほとんど揺れない（細かい波紋は陰影だけで、水面の形と浮力には入らない）。HeightProbe を選ぶと、インスペクタの「水面の高さ」が輪の通るたびに大きく上下する（波紋の分は ±2cm ほど）。
4. MainCamera の位置を (-2.75, 0.5, 4.4)・回転 X を 0.12 にすると、水面すれすれから BigDrop と FloatBox が見える。BigDrop の深さを 1 にすると、石のくぼみが立体の穴になって奥の縁が手前を隠し、FloatBox が輪に乗って傾きながら揺れる。水面の線は箱に沿って一緒に上下する。深さを 0.3 に、MainCamera を元の位置 (0, 6, -12)・回転 X 0.4636 に戻す。
5. Water を選び、インスペクタの水面の欄の下の「デバッグ」で「可視化する」を入れ、「表示」を「波紋の高さ」にする。赤（上がった所）と青（下がった所）の輪が広がる。「波紋の段ごとの傾き」にすると、近くの細かい輪は赤（6.25cm 刻みの段）、外の長い輪は緑（25cm 刻みの段）に出る。1m 刻みの段（青）はこの距離ではほとんど出ない。
6. 「波紋」の「波紋の強さ」を 0 にすると、波紋が見えなくなり、FloatBox も揺れなくなる。底のコースティクスは前のフレームを混ぜているので、数秒かけて消える。1 に戻す。
7. 「消える速さ（プロジェクト）」を 2 にすると、輪が近くで消える。0.4 に戻す。
8. 再生中に「水面の真ん中に波紋を起こす」を押すと、水面の真ん中から輪が 1 つ広がる。停止中はボタンが押せない（水の時間が止まっている）。ふつうの絵で原点の印より手前に見える輪は池の底のコースティクスで、水面の輪は「波紋の高さ」で見ると原点の印に重なる。
9. MainCamera の位置 X を 20 ずつ動かす。波紋は水面のその場に残り、カメラと一緒に動かない。
10. MainCamera を元の位置に戻す。WakeBoat の後ろに V の字の航跡が引き、舟の前の水が盛り上がる。V の開きは片側 20° ほど（深い水を進む舟の航跡の角度 19.5° に近い）。端で向きを変えると、舟の周りに輪が出る。
11. DropBox が水に落ちるたびに、そこから輪が広がる。浮いて上下している間は小さな輪が出て、落ち着くと出なくなる。
12. WakeBoat を選び、「波紋を起こす」の「波紋の強さ」を 0 にすると、舟は進み続けるが航跡が出なくなる。DropBox の「浮力」の「波紋の強さ」を 0 にすると、落ちても輪が出ない。どちらも 1 に戻す。
13. 波紋を起こす物は、物が起こした波紋には乗らない。DropBox の輪や WakeBoat の航跡が FloatBox に届いても、FloatBox はほとんど揺れない（BigDrop の輪では揺れる）。HeightProbe の「水面の高さ」は、物が起こした波紋でも上下する。
14. WakeBoat の後ろに白い泡の帯が引く。舟のすぐ後ろは白く埋まり、離れるほど左右へ広がりながら網目になって薄れ、5〜6 秒で消える。帯は途切れずに続き、風下へ少しずつ流れる。
15. DropBox が水に落ちた瞬間は、白い泡はまだほとんど無い。箱の根元に網目の泡が 0.25〜0.5 秒かけて浮いてきて、外へ広がる輪になる。輪は 1 秒ほどで箱の幅の 2〜3 倍まで広がり、真ん中から薄くなって割れ、3 秒ほどで切れ端だけになる。泡のまわりの水は、気泡で少し青白く濁る。浮いて上下している間と FloatBox の揺れでは、泡はほとんど出ない。
16. WakeBoat の「波紋を起こす」と DropBox の「浮力」の「泡の強さ」を 0 にすると、波紋は出たまま泡だけが出なくなる。残っていた泡は数秒で消える。どちらも 1 に戻す。
17. Water の「デバッグ」の「表示」を「泡の内訳」にすると、WakeBoat の後ろの帯が緑に出る。
18. 「表示」を「泡と気泡」にすると、白が水面の泡、青が水の中の気泡になる。DropBox が落ちた所には先に青が出て、その中から白が育つ。WakeBoat の後ろは、舟のすぐ後ろが青く、少し離れると白くなる。
19. Water の「泡が浮いてくる時間」を 0 にすると、気泡を待たずに白い泡を出す（前のやり方）。DropBox が落ちた瞬間に、箱の根元が白く埋まる。0.25 に戻す。
20. 「表示」を「泡の流れ」にすると、物が起こした水の流れが見える（色が向き・明るさが速さ）。DropBox が落ちると、箱から外へ向かう流れが向きごとに違う色の輪になって出て、1〜2 秒で暗くなる。WakeBoat の後ろは、帯の左右で違う色（外へ押す流れ）になる。可視化を切る。
21. Water の「物が起こす流れの強さ」を 0 にすると、泡が流れで運ばれなくなる。DropBox の泡は箱の根元に留まって輪にならず、WakeBoat の後ろの帯は細いまま。1 に戻す。
22. 再生中に MainCamera の位置 X を 30 動かす。WakeBoat の泡の帯はその場に残り、カメラと一緒に動かない。元の位置に戻す。

## Water_RippleShore

水面の波紋が、陸と水の中の止まった物で跳ね返り、緩い浜では吸い込まれることを確かめます（`r.Water.Ripple.Shore`）。物がかき回した泡が、壁で止まって溜まることも確かめます。岸と物は海の範囲マップ（レイトレーシングで測る）から読むので、レイトレーシングが使える GPU で開きます。

一辺 100m の穏やかな水（FFT の海・高さの倍率 0.05）を原点に張り、底を高さ -1.5 に置いています（水深 1.5m）。カメラは高さ 13m・手前 9m から見下ろしています。雲・霧・ブルーム・自動露出は切っています。石はどれも半径 0.5m・深さ 12cm で、6 秒ごとに落ちます。

| 物 | 見るところ |
|---|---|
| Water | 波紋を描く水面 |
| Pond_Bottom | 水の底（砂の色の箱） |
| Wall | 左の岸の壁。水側の面が x = -9（厚さ 1m・z -8〜16・水面から 1m 出る。底より下まで埋めてある） |
| Beach | 右の緩い浜（砂の色）。1:10 の坂で、x = 9 で水から出る。水際は遡上（`r.Water.Shore.RunupHeight`）で波ごとに前後する |
| Rock | 水から出た岩（半径 1m の球）。(-4, 0, 8) |
| SlitWall_A・SlitWall_B | 奥の壁（z = 8・厚さ 0.4m）。x 3.4〜4.6 に 1.2m の隙間がある |
| DropWall | 試験のスクリプト（RippleProbe）。壁から 1.5m の (-7.5, 0, 0) へ石を落とす（最初は 1 秒後） |
| DropBeach | RippleProbe。浜の水際から 1.5m の (7.5, 0, 0) へ石を落とす（最初は 1 秒後） |
| DropRock | RippleProbe。岩の手前の (-4, 0, 5.5) へ石を落とす（最初は 4 秒後） |
| DropSlit | RippleProbe。隙間の手前の (4, 0, 5.8) へ石を落とす（最初は 4 秒後） |
| WallDropBox | 浮力（Buoyancy）で浮く緑の箱（0.6m・60kg）。試験のスクリプト（RippleDropBoxProbe）で 6 秒ごとに壁から 1m の (-8, 1.5, -4) へ戻して落とし直す |

確かめ方:

1. 再生し、Water を選ぶ。インスペクタの水面の欄の下の「デバッグ」で「可視化する」を入れ、「表示」を「波紋の高さ」にする（赤が上がった所・青が下がった所）。MainCamera の位置を (0, 26, 3)・回転 X を 1.5708 にすると、真上から全部が見える。
2. 左の DropWall の輪が壁に届くと、壁から跳ね返った弧が右へ戻ってくる。壁の向こう（x < -10）には輪が出ない。
3. 右の DropBeach の輪は、浜の方へ進むほど弱まって消え、跳ね返った弧が戻らない。
4. DropRock の輪は岩に当たって乱れ、岩の奥に輪の欠けた影ができる。DropSlit の輪は奥の壁で跳ね返り、隙間を抜けた分だけが、隙間から奥へ半円に広がる。
5. Water の「波紋」の「岸と物で跳ね返す（プロジェクト）」を切る。輪が壁と岩を素通りして、壁の向こうと奥の壁の奥にも広がり、跳ね返った弧が出ない。入れ直す（プロジェクトの CVar なので、切ったままにしない）。
6. MainCamera を元の位置 (0, 13, -9)・回転 X 0.95 に戻し、可視化を切る。ふつうの絵でも、壁の際と浜の水際で輪の跳ね返り方が違う。
7. MainCamera の位置を (-8, 7, -4)・回転 X を 1.5708 にすると、WallDropBox を真上から見られる。箱が落ちるたびに根元の泡が外へ広がり、壁の側へ広がった泡は壁の水側の面（x = -9）で止まって溜まる。壁の上と向こうには泡が出ない。MainCamera を元の位置に戻す。

## Water_ShoreRunup

砕けた波が浜を駆け上がって引き、水際の線が波ごとに前後することを確かめます（`r.Water.Shore.RunupHeight`）。水深・浜の傾き・波が着くまでの時間は海の範囲マップ（レイトレーシングで測る）から読むので、レイトレーシングが使える GPU で開きます。

一辺 100m の穏やかな水（FFT の海・高さの倍率 0.15）を原点に張り、x = -40〜40 に 1:20 の浜を水面の幅いっぱいに置いています。浜は x = 0 で水から出て、x = -40 で水深 2m、x = 40 で高さ 2m です。その先の沖の底は高さ -2.5、浜の上（x = 39 より陸の側）は高さ 2 の台です。カメラは陸の側の高さ 9m から、浜を斜めに見下ろしています。雲・霧・ブルーム・自動露出は切っています。

水深 12m 以上の沖が無い水面なので、沖から寄せる波の峰は出ません（Water_ShoreWaves で確かめます）。波は、海のいちばん深い所（沖の底）から浜へ着く時間で寄せます。

| 物 | 見るところ |
|---|---|
| Water | 遡上を描く水面 |
| Beach | 1:20 の浜（砂の色の箱） |
| Pond_Bottom | 浜より沖の底（砂の色の箱） |
| Land | 浜の上の陸（砂の色の箱） |

確かめ方:

1. 再生する（停止中は波の時刻が進まない）。水際が約 9 秒おきと約 11 秒おきの 2 つの列で浜を上がって引く。上がる距離は波ごとに違う。
2. 水の先端はまっすぐな線にならず、弧の形に出入りする。形は波ごとに違う。先端が階段の形や、砂の上に離れた水たまりにならない。
3. 膜の先端の水深 0.15m より浅い所に岸の泡が付き、先端と一緒に動く。
4. 浅い所（水深 1.6m まで）では、浜と平行な段が岸へ進んでから水際を押し上げる。沖に波の峰は出ない。
5. Water のインスペクタの「形（プロジェクトの設定）」の「浜を駆け上がる高さ」を 0 にすると、水際は x = 0 の動かない線になる。1.5 にすると、水際が上がる距離がおよそ 2 倍になる。0.8 に戻す（プロジェクトの CVar なので、変えたままにしない）。

## Water_ShoreWaves

沖から岸へ向かう波が浅瀬で高くなって砕け、段になって進み、浜を駆け上がることと、砕けた所に泡が出て、泡の前線が岸へ進むことを確かめます（`r.Water.Shore.WaveHeight`）。沖から着くまでの時間は海の範囲マップ（レイトレーシングで測る）に書くので、レイトレーシングが使える GPU で開きます。

一辺 400m の穏やかな水（FFT の海・高さの倍率 0.15）を原点に張り、x = -140〜20 に 1:10 の浜を水面の幅いっぱいに置いています。浜は x = 0 で水から出て、x = -120 で水深 12m、x = -140 で水深 14m です。その先の沖の底は高さ -14、浜の上（x = 19 より陸の側）は高さ 2 の台です。カメラは陸の側の高さ 18m から、沖と浜を斜めに見下ろしています。雲・霧・ブルーム・自動露出は切っています。このシーンでは、泡は白ではなく明るい灰青に見えます。

| 物 | 見るところ |
|---|---|
| Water | 寄せる波を描く水面 |
| Beach | 1:10 の浜（砂の色の箱） |
| Seabed | 沖の底（砂の色の箱） |
| Land | 浜の上の陸（砂の色の箱） |

確かめ方:

1. 再生する（停止中は波の時刻が進まない）。沖（水深 12m より浅い所）に波の峰が現れて、岸へ進む。岸に近いほど遅く、高く、峰が細くなる。
2. 波は約 9 秒おきの列と、約 11 秒おきに少し斜めから来る低い列で寄せる。大きい波と小さい波が組になって来て、同じ峰でも場所によって高さと進み具合が違い、ところどころ途切れる。峰は一直線にならない。
3. 高さ 0.4m では、水深 1m のあたり（水際から約 10m 沖）で峰が消えて段に変わり、段が水際へ着くと水が浜を上がって引く。沖の峰・段・水際の上がり下がりが 1 つの波としてつながる。
4. 浜を上がる水の先端はまっすぐな線にならず、弧の形に出入りする。形は波ごとに違う。先端が階段の形や、砂の上に離れた水たまりにならない。
5. Water のインスペクタの「形（プロジェクトの設定）」の「岸へ寄せる波の高さ」を 1.0 にすると、峰が高くなり、もっと沖（水深 2m のあたり）で砕ける。0 にすると峰は出ず、段と水際の上がり下がりだけが残る。0.4 に戻す（プロジェクトの CVar なので、変えたままにしない）。
6. 峰が消える直前に、峰の頂に細い泡が出る。峰が段に変わった所から、泡の帯が段と一緒に岸へ進み、帯の後ろは 2 秒ほどで薄れて水の色が見える。帯の縁はまっすぐにならず、帯の中に濃い所と薄い所がある。
7. 同じ峰でも場所によって砕ける位置が前後し、泡の帯がところどころ途切れる。
8. 浜を上がる水は、上がり始めが泡で覆われ、引くにつれて泡が薄くなる。

## Gizmo_ChildOfParent

親のあるオブジェクトをギズモで動かしたときに、親から見た値で動くかを確かめます。

| 物 | 見るところ |
|---|---|
| Parent | 橙の箱。位置・回転・拡大を初期値から変えてある |
| Child | 青の球。Parent の子（Parent から見て X に 2） |
| Grandchild | 緑の箱。Child の子（Child から見て Y に 2） |

確かめ方:

1. Child を選び、移動のギズモの矢印を少しずつドラッグする。球はマウスに付いてくるだけで、飛んだり速くなったりしない。インスペクタの位置は Parent から見た値（はじめは X 2・Y 0・Z 0）から少しずつ変わる。
2. 回転（E）・拡縮（R）のギズモでも、球はその場で回る・伸びるだけで、位置が変わらない。
3. Grandchild でも同じ。Child を動かすと Grandchild が付いてくる。
4. Ctrl+Z で動かす前に戻る。
5. インスペクタの数値の欄（ドラッグで変える欄）やコンボにカーソルを乗せると、欄がはっきり明るくなる（スライダーの欄と同じくらい）。

## Collider_DebugDraw

ツールバーの ◍ Collider の線が、停止中も出るかを確かめます。物はどれも床から 0.1m 浮かせてあり、重なっているのは Touch_A と Touch_B だけです。

| 物 | 形 | 停止中の線の色 |
|---|---|---|
| Floor | 箱（静止） | 緑 |
| Ball | 球 | 緑 |
| Crate | 箱（Y に回してある） | 緑 |
| Pill | カプセル | 緑 |
| Touch_A・Touch_B | 重なった 2 つの箱 | 緑（再生すると赤） |
| TriggerZone | トリガーの箱（見た目なし） | 青 |

1. 停止のまま、ツールバーの ◍ Collider を押す。7 つの線が出る。もう一度押すと消える。
2. 停止のまま Crate をギズモで動かすと、線が付いてくる。Ball を削除すると線も消え、Ctrl+Z で戻すと線も戻る。

## Collider_Mesh

メッシュの当たり判定（モデルの三角形のまま当てる形）を確かめます。地形のモデル MeshCourse は、床と 6 本の通り道を三角形で組んだ物です。通り道は z = 4 から奥へ延びています。

| 通り道 | x | 中身 |
|---|---|---|
| 床 | -12.5〜12.5 | z -4〜20 を 1m の格子に割った平地（継ぎ目だらけ） |
| 1 | -10 | 30 度の坂で高さ 2m の台へ上り、30 度で下る |
| 2 | -6 | 50 度の坂（高さ 2m。登れる坂の 45 度より急） |
| 3 | -2 | 0.2m × 8 段の階段で高さ 1.6m の台へ上り、8 段で下る |
| 4 | 2 | 0.25m の段差、その奥に 0.6m の段差 |
| 5 | 6 | トンネル（内の高さ 2.3m・天井の厚さ 0.3m） |
| 6 | 10 | 30 度に傾けた厚さ 0.1m の壁と、その奥のまっすぐな厚さ 0.1m の壁 |

| 物 | 見るところ |
|---|---|
| Course | 地形の描画とメッシュの形（三角形は「同じオブジェクトのモデル」） |
| Course_Turned | 奥（z 45）に Y へ 180 度回し、大きさを (1.25, 1.1, 0.8) にした同じ地形。三角形は「モデルのファイル」で MeshCourse.gltf を指す（Course と同じ三角形の木を使い回す） |

| BoxRamp50 | 50 度に傾けた箱のコライダー（メッシュでない形と比べるため）。Course の 50 度の坂の奥にある |
| Player | カプセル・キャラクタコントローラ・人形・アニメーター・試験のスクリプト（MeshColliderProbe） |

確かめ方:

1. 再生し、コンソールの絞り込みに MeshColliderProbe と入れる。始めにレイの行が 8 つ OK で出る（Course の平地 0.0000m・30 度の坂の中ほど 1.0000m と 30.00 度・階段の踊り場 1.6000m、Course_Turned は 0.0000m・1.1000m と 38.44 度・1.7600m、板は下からは当たらず上からは 2.2000m）。
2. Player が通り道を順に自動で走る（カメラが付いてくる。約 80 秒）。Course と Course_Turned の 7 本ずつのあとに、箱の 50 度の坂と片面の板を走り、最後に「全部 OK」が出る。各行の中身は次のとおり。
   - 平地の継ぎ目: 上下の揺れ 0.000 mm・接地が切れたフレーム 0
   - 30 度の坂: 台へ上って下りきる
   - 50 度の坂（メッシュも箱も）: 登れず、坂の下で止まる
   - 階段: 踊り場まで上って下りきる
   - 段差: 0.25m には乗り、0.6m は越えない
   - トンネル: 中で跳ぶと天井で止まる（外では高く跳べる）
   - 薄い壁: 走っても抜けず、壁に沿って横へ滑る
   - 片面の板: 下から跳ぶと板を抜け、上に乗る（高さ 2.2m）
3. コンソールの絞り込みを MeshTriggerProbe に変えると、TriggerBall が高さ約 0.39 で「Course に入った」、約 0.42 で「Course から出た」をくり返す（TriggerBox も約 0.40 と 0.42）。
4. 「全部 OK」のあとは手で歩ける（WASD で歩く・Shift で走る・Space で跳ぶ・Q と E でカメラを回す・F で始めの場所へ戻る・R で自動の走りをやり直す）。
5. 停止中に Course を選ぶと、コライダーのインスペクタに三角形の数（1428）と作るのにかかった時間が出る。ツールバーの ◍ Collider を押すと、カメラの近くの三角形が線で出る。
6. 新しい空の物にコライダーを付けて「メッシュを追加」を押すと、静止でトリガーではないメッシュの形が付き、状態に「モデルがありません」と出る（三角形を「モデルのファイル」にしてモデルを選ぶと、三角形の数が出る）。剛体を付けて動く物にすると、メッシュの形は使えないという警告が出る（確かめたら Ctrl+Z で戻す）。

## Physics_MeshGround

剛体（球・箱・カプセル）とメッシュの形の当たりを確かめます。地形のモデル MeshGround は、1m の格子の床（三角形の対角線の向きを互い違いにした、継ぎ目だらけの平地）と、z = 4 から奥へ 20 度で高さ 4m まで上る坂、坂の上の台でできています。床の手前の端（z -12）には、転がってきた物を止める低い壁があります。

剛体は始めは重力を受けません。試験のスクリプト（MeshPhysicsProbe・MainCamera に付いている）が、地形に当たるようになってから重力を入れ、始めの速さを与えます。

| 物 | 見るところ |
|---|---|
| Ground | 地形の描画とメッシュの形（三角形は「同じオブジェクトのモデル」） |
| RollBall | 台の上の球（半径 0.5m）。坂の下向きに 1.5m/s で押し出され、坂を転がり下りて床を進み、手前の壁で止まる |
| SlopeBox | 坂に面を合わせて置いた 1m の箱。摩擦（既定 0.6）で止まって眠る |
| CapsuleRoller | 坂に横へ 30 度傾けて立てたカプセル（半径 0.3m・全高 1.6m）。倒れて横になり、坂を転がり下りる |
| DropBox | 回して床へ落とす 1m の箱。角から落ちて面で止まり、眠る |
| ThinPlate・FastBallPlate | 高さ 3m の厚さの無い板（メッシュの形）と、その上から 70m/s で落とす球（半径 0.25m） |
| FastBallGround | 床へ 70m/s で斜めに落とす球（半径 0.25m） |
| MeshOnBody | 剛体に箱とメッシュの形を付けた物。メッシュの形は物理が使わず、箱の形で床に乗る |

確かめ方:

1. 再生し、コンソールの絞り込みに MeshPhysicsProbe と入れる。約 10 秒で、物ごとの OK の行が 7 つ出て、最後に「全部 OK」が出る。
   - 坂を転がる球: 坂の上と床の上で、地面からの浮き（中心の高さ − 半径）が 1cm を超えない（継ぎ目で跳ねない）
   - 坂で止まる箱: 動いた距離が 10cm 未満で止まる
   - 平地に落とした箱: 10 秒のうちに眠り、中心の高さが 0.5m（面で止まる）
   - 倒れて転がるカプセル: 地面から中心までが半径ほどになり（横になる）、坂の下へ 2m より遠く転がる
   - 速い球と厚さの無い板・速い球と地面: 中心が板や地面より下へ行かず、半径の高さで止まる
   - メッシュの形を持つ剛体: 中心の高さが 0.5m（箱の形で床に乗る）
2. コンソールの絞り込みを外すと、「MeshOnBody」のメッシュの形は物理が使わないという警告が 1 回だけ出ている。
3. 停止中に MeshOnBody を選ぶと、コライダーのメッシュの形の欄に「動く剛体には使えません」の警告が出る。
4. ツールバーの ◍ Collider を押すと、地形の三角形が線で出る。床と坂の継ぎ目の上を、球とカプセルが跳ねずに転がる。

## VolumetricFog_Basic

ボリュメトリックフォグ（カメラの近くの霧を 3D の格子で計算する）を確かめます。

高さフォグとボリュメトリックフォグを入れています。霧の濃さは 0.008（`r.Fog.Density`）です。太陽は右前の低い所（高さ約 15 度）にあり、カメラは太陽の方を向いています。

床の左右に高さ 8m の柱を 10m・25m・50m・100m・145m・155m・200m・300m に並べています。格子が届くのは 150m（`r.Fog.Volumetric.Distance`）までで、145m（左）と 155m（右）の柱はその境目をはさんでいます。

| 物 | 見るところ |
|---|---|
| 太陽のまわりの霧 | 太陽に近い方向ほど霧が明るく光る（`r.Fog.Volumetric.Anisotropy` の既定 0.6） |
| Pillar_145m・Pillar_155m | 格子の内と外。霧の掛かり方に段が無く、遠いほどなめらかに霞む |
| Pillar_300m | 格子の外。霧の色と明るさが、手前の格子の中の霧と同じ式で続く |

確かめ方:

1. Hierarchy の Environment を選ぶ。インスペクタの高さフォグに「ボリュメトリックフォグ」のチェックが入っていて、その下に「格子 160 x 90 x 64」（1920 × 1080 の画面のとき）が出る。
2. チェックを外すと今までの高さフォグに戻る。入れ直すと霧の色が太陽と空の光の色に変わり、太陽の側が明るく、反対側が暗くなる。
3. MainCamera の回転 Y を 3.14 にして太陽に背を向ける。霧は暗く、空の光の青みが強くなる。
4. 詳細設定の `r.Fog.Volumetric.Distance` を 50 にする。50m のあたりにも、145m と 155m の柱の間にも、霧の段が出ない。
5. Sun のインスペクタで光の向きを変える。霧の明るい所が太陽に付いてくる。強さを 0 にすると、霧は空の光だけで照らされる。
6. `r.Fog.Volumetric.DebugView` を変える。1 は格子の透過率（手前は白・遠いほど暗い）、2 は格子が足す光、3 は奥行きの区切り（色の帯。近いほど細かい）。0 で戻す。
7. `r.Fog.Volumetric.GridPixelSize` を 8 や 24 にすると、インスペクタの格子の数が変わる。ゲームの窓の大きさを変えても付いてくる。

DXR 1.1 に対応した GPU では、柱の陰の霧が暗くなります（物の影）。光の筋は VolumetricFog_Shafts で、雲の影は VolumetricFog_CloudShafts で、点光源・スポット・エリアライトの霧は VolumetricFog_LocalLights で確かめます。

## VolumetricFog_CloudShafts

ボリュメトリックフォグに雲の影が落ちることと、前のフレームと混ぜた霧に縞やざらつきが出ないことを確かめます。

高さフォグ（濃さ 0.01）とボリュメトリックフォグ（格子の距離 300m）と雲を入れています。雲の影が霧の範囲に入りやすいよう、雲を小さく（`r.Cloud.WeatherMapScale` 8000）、雲の影のマップの範囲を狭く（`r.Cloud.ShadowRegionSize` 10000）しています。太陽は右前の高さ約 40 度にあり、カメラは少し上を向いています。

床の左右に高さ 8m の柱を 20m・60m・120m・200m・300m に並べています。

| 物 | 見るところ |
|---|---|
| 床と霧 | 床が雲の影に入っている所では、その上の霧も同じように暗い（空の光だけの青い霧になる） |
| 柱 | 柱の陰の霧も暗くなる（物の影。VolumetricFog_Shafts で確かめる） |

確かめ方:

1. シーンを開く。雲の位置によって、手前一帯が雲の影に入って床と霧が青く暗いか、全部が日なたで白い。
2. Hierarchy の Environment を選び、ボリュメトリック雲の詳細設定「ゴッドレイ・雲影」の `r.Cloud.SceneShadowStrength` を 0 にする。手前が雲の影に入っていたときは、床が日なたになり、霧も白く明るくなる。1 に戻すと、床と霧が一緒に暗くなる。
3. 雲の「風速」を 100 m/s（上限）に上げる。雲の影が流れてきて、床の影の縁と一緒に、霧の明るい所と暗い所の境目が動いていく。終わったら 8 に戻す。
4. 高さフォグの詳細設定で `r.Fog.Volumetric.DebugView` を 4 にする。格子の奥の端（300m か、それより手前の床）での影が白黒で出る（白が日なた・黒が影。雲の影に柱の影が重なる）。0 で戻す。
5. 何も動かさずに霧を見る。縞やざらつきが出ない。`r.Fog.Volumetric.HistoryWeight` を 0 にしても、止まった絵はほとんど変わらない（前のフレームと混ぜた結果がずれていない）。0.9 に戻す。
6. MainCamera のインスペクタで回転 Y の値をドラッグして、カメラを左右に回す。霧の明るい所と暗い所が遅れて付いてきたり、残像が残ったりしない。
7. MainCamera の位置 Z を 100 にする（1 フレームで 10m 以上動かす）。前の位置の霧が残らない。

柱の陰の霧の暗さ（物の影）は VolumetricFog_Shafts で確かめます。

## VolumetricFog_Shafts

ボリュメトリックフォグに物の影が落ち、物の間から差す光が霧の中で筋になることを確かめます（DXR 1.1 に対応した GPU が要ります）。

高さフォグ（濃さ 0.015）とボリュメトリックフォグを入れています。雲・ブルーム・自動露出は切り、露出は EV 0 で固定しています。太陽はカメラの正面の奥の高さ約 22 度にあり、光は奥から手前へ進みます（逆光）。

| 物 | 見るところ |
|---|---|
| SlotWall_00〜05 | 奥 20m に並べた幅 3.4m・高さ 12m の柱。0.6m の隙間から差す光が、霧の中を手前へ伸びる筋になる |
| Fence_00〜11 | 手前 8m の細い板の柵。板の陰が霧の中に細い縞で出る |
| Lattice | 穴の開いた板（画像のアルファで抜けている。木の葉の代わり）。抜けた所から光が漏れ、霧の中に網目の筋が出る |
| Mover | 赤い箱。動かすと霧の中の影も付いてくる |

確かめ方:

1. シーンを開く。柱の隙間から手前へ光の筋が伸び、柱の陰の霧は暗い。
2. Sun のインスペクタで「霧に影を落とす」を外す。霧が一様に明るくなり、筋が消える（床の影は残る）。入れ直すと筋が戻る。
3. Sun の「霧を照らす強さ」を 0 にすると、霧は空の光だけの暗い霧になる。2 にすると霧が明るくなる。1 に戻す。
4. Mover の位置 X をインスペクタでドラッグして動かす。霧の中の箱の影が付いてくる。速く動かすと薄い尾を引く（前のフレームと混ぜる量 `r.Fog.Volumetric.HistoryWeight` 0.9 の遅れ。60fps で 0.2 秒に 7 割ほど追いつく）。HistoryWeight を 0.7 にすると尾が短くなり、霧のざらつきは少し増える。0.9 に戻す。
5. 高さフォグの詳細設定で `r.Fog.Volumetric.DebugView` を 4 にする。格子の奥の端（床）での影が白黒で出る。柱・柵・板の網目・箱の影が、床の影と同じ形で出る。5 にすると、太陽から見た深さの画像が画面の中央に正方形で出る（光の向きから見た絵なので左右は画面と逆。霧の範囲の光源側の端が黒・反対側の端と何にも当たらない所が白。物と床の差は小さく、柱と板は床の帯の上の端に小さく出る）。0 で戻す。
6. `r.Fog.Volumetric.ShadowResolution` を 256 にすると、柵の板の筋がぼけたり途切れたりする。1024 に戻す。
7. Window ▸ Rendering ▸ Ray Tracing の窓の「概要」に「霧の物の影（太陽から見た深さ）」の行が出て、解像度 1024 × 1024 とレイの数と GPU 時間が出る。GPU 時間は 0.15ms 以下が目安。その行の「ON」を外すと、2 と同じく筋が消える。「中間結果」の「太陽から見た深さ」で画像を見られる（範囲を狭めると柱や板がはっきり出る）。
8. `r.Fog.Volumetric.ShadowUpdateInterval` を 8 にして、Mover の位置 X を速くドラッグする。霧の中の箱の影が、少しずつ遅れて段々に付いてくる（太陽から見た深さの画像を 8 フレームに 1 回しか撮り直さない）。既定の 2 に戻す。

DXR 1.1 に対応していない GPU では、物の影は霧に落ちません（雲の影だけ落ちます）。

## VolumetricFog_LocalLights

点光源・スポット・エリアライトがボリュメトリックフォグを照らすことを確かめます。

夜のシーンです（平行光源は強さ 0・空の明るさ 0 の NoDefaultSun だけ）。高さフォグ（濃さ 0.04・高さの減衰 0.05）とボリュメトリックフォグを入れ、霧の色（`r.Fog.Color`）を暗くしているので、ライトの近く以外の霧はほとんど黒です。雲・ブルーム・自動露出は切り、露出は EV 2 で固定しています。

| 物 | 見るところ |
|---|---|
| StreetLamp | 高さ 4.85m の下向きのスポット（内側 25 度・外側 40 度）。霧の中に光の円錐が出て、床の光の輪とつながる |
| Lantern | 青い点光源（高さ 1.3m）。まわりの霧が丸く光り、離れるほど暗くなる |
| Window | 壁の窓のエリアライト（1.6m × 1.2m・カメラの方を向く）。窓の正面の霧が光の帯になる |
| NoFog | 手前の赤い点光源。「霧を照らす強さ」が 0 なので、床は赤く照らすが、まわりの霧は光らない |

確かめ方:

1. シーンを開く。街灯の下に光の円錐、ランタンのまわりに青い丸い光、窓の前に光の帯が霧の中に出る。手前の赤い点光源は床だけを照らす。
2. Hierarchy の Environment を選ぶ。高さフォグの「ボリュメトリックフォグ」の下に「霧を照らす点光源・スポット・エリア 3 灯」が出る（NoFog は霧を照らさないので数えない）。
3. 詳細設定の `r.Fog.Volumetric.LocalLights` を外す。円錐・丸い光・光の帯が消えて霧が黒くなり、床の照らされ方は変わらない。入れ直す。
4. StreetLamp の「霧を照らす強さ」を 0 にすると円錐だけが消え、3 にすると円錐が明るくなる。1 に戻す。NoFog の「霧を照らす強さ」を 1 にすると、赤い点光源のまわりの霧も光る。0 に戻す。
5. StreetLamp の「外側の角度」を 20 にすると、霧の円錐も床の光の輪も一緒に細くなる。40 に戻す。
6. Lantern の位置 X をインスペクタでドラッグして動かす。霧の丸い光が付いてくる（前のフレームと混ぜるので、速く動かすと少し尾を引く）。
7. MainCamera の位置を Lantern の 1m 手前（X 0.5・Y 1.3・Z 8）にする。光源のまわりの霧が、格子の形に白く尖ったりちらついたりしない。

点光源・スポット・エリアライトは霧に影を落としません（壁の向こうの霧も照らします）。

## VolumetricFog_Transparent

半透明の物・水面・パーティクルにも、不透明の物と同じボリュメトリックフォグが掛かることを確かめます。

高さフォグ（濃さ 0.01）とボリュメトリックフォグを入れています。太陽は右前の低い所（高さ約 15 度）にあり、カメラは太陽の方を向いています（VolumetricFog_Basic と同じ）。雲・ブルーム・自動露出は切り、露出は EV 0 で固定しています。風は 3 m/s にして、水面の波を低くしています。

| 物 | 見るところ |
|---|---|
| Opaque_010m〜Opaque_300m・Glass_010m〜Glass_300m | 10m・25m・50m・100m・145m・155m・220m・300m に、不透明の箱（左）と半透明の箱（右。アルファ 0.99・合成は「通常」）を並べています。同じ距離の 2 つは、霧の色と濃さが同じに見える |
| Glass_145m・Glass_155m | 格子の内（145m）と外（155m）。格子の外でも、隣の不透明の箱と同じ霧が掛かる |
| Water | 右手前の池（一辺 100m・FFT の海を切った Gerstner の波）。奥ほど、まわりの床と同じ霧に霞む |
| Particles_020m・Particles_080m | 左の 2 つの噴水（加算の粒。再生中だけ出る）。80m の粒は 20m の粒より霧に薄れる |

確かめ方:

1. シーンを開く。どの距離でも、左右の箱の霧の掛かり方が同じ（右の半透明の箱だけ暗く沈んだり、白く浮いたりしない）。
2. Hierarchy の Environment を選び、高さフォグの「ボリュメトリックフォグ」を外す。どちらの箱も今までの高さフォグの色になり、左右は同じまま。入れ直す。
3. Sun の「霧を照らす強さ」を 3 にする。霧が明るくなり、半透明の箱と水面も、隣の不透明の箱と床と同じだけ明るい霧に包まれる。1 に戻す。
4. Glass_050m の Material の色のアルファを 0.4 にする。箱の向こうの床が透け、箱の縁に明るい線や暗い線が出ない。0.99 に戻す。
5. 再生する。左の 2 つの噴水から粒が出て、80m の粒は 20m の粒より霧に薄れる。停止する。

格子はゲームのカメラで作るので、Scene のタブ（シーンビュー）の半透明の箱と水面は、今までの高さフォグの式で描きます。

## VolumetricFog_Volumes

局所の霧（FogVolume。箱と球）・霧のノイズと風・霧の発光を確かめます。

高さフォグはごく薄く（濃さ 0.002）して、ボリュメトリックフォグを入れています。カメラは高さ 12m から少し見下ろし、太陽は右前の画面のすぐ外（高さ約 27 度）にあって、霧は光の進む向きへ強く散って明るく光ります。雲・ブルーム・自動露出は切り、露出は EV 0 で固定しています。ノイズの模様の大きさ（`r.Fog.Volumetric.NoiseScale`）は 20m、風は 3 m/s です。

| 物 | 見るところ |
|---|---|
| Fog_ValleyNoise | 38m 先・左の低く平たい箱（18m × 3m × 20m・縁のぼかし 0.3・濃さ 0.06・ノイズの強さ 1）。地面に溜まった霧で、濃い所と薄い所のむらがあり、むらが風下へ流れる |
| Fog_ValleyCalm | 38m 先・右の、Fog_ValleyNoise と同じ大きさと濃さの箱（ノイズの強さ 0）。むらの無い一様な霧で、左と見比べる |
| Pillar_0〜Pillar_2 | 谷の霧の奥側を突き抜ける 3 本の柱。根元が霧に沈み、柱の影が霧に落ちる |
| Fog_Ball | 20m 先・左の球（直径 7m・縁のぼかし 1・濃さ 0.4・色は赤み）。中心ほど濃く、縁へ向けて溶ける。色の付いた霧になる |
| Fog_Glow | 20m 先・右の球（直径 6m・縁のぼかし 0.7・濃さ 0.02・発光の色は青・発光の強さ 8000 nt/m）。光が当たらなくても霧が青く光る |
| Fog_Rotated | 61m 先の薄い板の形の箱（12m × 8m × 2.5m・縁のぼかし 0.05・濃さ 0.4）。Transform で 45 度回していて、霧の形も一緒に回る |
| Fog_Disabled | 18m 先の濃い箱（4m・濃さ 1）。FogVolume を無効にしているので見えない |

確かめ方:

1. シーンを開く。Game の窓で、左右の谷の霧・赤い球・青く光る球・45 度回った板の霧が見え、Fog_Disabled は見えない。左の谷の霧にはむらがあり、右は一様。
2. Game の窓に、局所の霧の形の輪郭が薄い水色の線で重なる。Fog_Ball を選ぶと、その輪郭だけ濃くなる。無効の Fog_Disabled も、選ぶと輪郭が出る。
3. Fog_Ball を動かす・Transform のスケールを変える・「大きさ」を変える。霧が付いてくる。「形」を「箱」にすると箱の霧になる。
4. Fog_ValleyNoise の「ノイズの強さ」を 0 にする。むらが消えて右と同じ一様な霧になる。1 に戻す。再生してコンソールで `cvar r.Wind.Speed 15` を打つと、むらの流れが速くなる。`cvar r.Wind.Speed 3` で戻す。
5. Environment の高さフォグの詳細設定で `r.Fog.Volumetric.NoiseStrength` を 0.8・`r.Fog.Density` を 0.02 にする。局所の霧の外の高さフォグにもむらが付く。0 と 0.002 に戻す。
6. Fog_Glow の「発光の強さ」を 0 にする。青い光が消え、薄い霧だけが残る。8000 に戻す。
7. Fog_Disabled の FogVolume を有効にする。白く濃い箱の霧が出る。無効に戻す。
8. 高さフォグの「ボリュメトリックフォグ」を外す。局所の霧はそのまま残る（格子には局所の霧だけを入れ、ごく薄い高さフォグは高さフォグの式で掛かる）。入れ直す。

格子より遠くの局所の霧は、VolumetricFog_FarVolumes で確かめます。

## VolumetricFog_FarVolumes

局所の霧（FogVolume）が、高さフォグを切ったシーンでも、格子の届く距離（150m）より遠くでも描かれることを確かめます。

高さフォグ（`r.Fog.Enabled`）とボリュメトリックフォグ（`r.Fog.Volumetric.Enabled`）はどちらも切っています。カメラは高さ 20m から少し見下ろして奥（+Z）を見ていて、太陽は右前（高さ約 27 度）にあります。雲・ブルーム・自動露出は切り、露出は EV 0 で固定しています。床は 2400m 四方です。

| 物 | 見るところ |
|---|---|
| Marker150_0・Marker150_1 | 150m 先の左右の赤い柱。格子が届く距離（`r.Fog.Volumetric.Distance`）の目印 |
| Fog_Near | 40m 先・左の赤い球（直径 10m・縁のぼかし 1・濃さ 0.15）。格子の中だけにある |
| Fog_Long | 60m 先から 460m 先まで続く低い箱（40m × 6m × 400m・縁のぼかし 0.3・濃さ 0.05）。格子の端（柱の所）をまたいでも、霧に段や継ぎ目が出ない |
| Fog_Far | 650m 先・左の大きな球（直径 160m・縁のぼかし 0.6・濃さ 0.01・色は少し黄色）。全部が格子より奥にある |
| Fog_FarGlow | 320m 先・右の球（直径 50m・縁のぼかし 0.7・濃さ 0.002・発光の色は青・発光の強さ 1500 nt/m）。格子より奥で青く光る |

確かめ方:

1. シーンを開く。赤い球・柱をまたいで奥まで続く白い帯・遠くの大きな霧の球・右の青く光る霧が見える。帯は柱の所で明るさが途切れない。
2. Environment の高さフォグのインスペクタに「局所の霧 4 個（格子にかかる 2 個・格子より奥まで届く 3 個）」と「高さフォグは格子に入れず、局所の霧だけを格子で描いています」が出る。
3. Fog_Far を選び、Transform の位置 Z を 650 から 120 まで少しずつ下げる。霧の球が近づき、格子の中に入っても見え方が飛ばない。650 に戻す。
4. 高さフォグの「有効」を入れる（濃さ 0.002）。遠くが薄くかすみ、局所の霧はそのまま見える。「ボリュメトリックフォグ」も入れると、高さフォグも格子で描くので遠くのかすみの色は変わるが、局所の霧は同じ所に同じ形で見える。両方外す。
5. GameObject ▸ 環境 ▸ 局所の霧（FogVolume）を押す。Game ビューの中央の先の地面（このカメラのままなら約 250m 先）に、底が地面に着いた 10m の箱の霧ができて選ばれる。`Ctrl`+`Z` で消える。
6. `r.Fog.Volumetric.DebugView` を 2（格子が足す光）にすると、格子の中の Fog_Near と Fog_Long の手前だけが出る。格子より奥の霧は合成が足すので出ない。0 に戻す。

格子より奥の部分には、ノイズ・物の影・点光源・スポット・エリアライトは効きません（太陽・空の光・雲の影・発光は効きます）。

## AerialPerspective_Near

空気遠近感（遠くの物ほど大気で霞む）が、カメラの近くの物にかからないことを確かめます。

雲・レンズフレア・ローカル露出を切っています。カメラは目の高さ 1.7m で 8 度下を向いていて、地平線は画面の中央より上に来ます。太陽は右前の高い所（高さ約 27 度）にあり、物のカメラ側の面は影になります。

30m 先に幅 16m・高さ 8m の壁を置き、左右に柱を 8m・15m・80m・250m・1000m に並べています。

| 物 | 見るところ |
|---|---|
| Wall_030m | 目の高さ（地平線の高さ）の上と下で色が同じ。横に走る境目が無い |
| Pillar_008m・Pillar_015m | 地平線より上の部分も白っぽく霞まない |
| Pillar_250m・Pillar_1000m | 遠いほど空の色に溶ける。1000m の柱は手前の柱よりはっきり青白い |

確かめ方:

1. 壁と手前の柱に、地平線の高さで横に走る境目が無い。境目があり、その上だけが白っぽく霞んでいたら、近くの物に 2km 分の霞がかかっている。
2. Environment ▸ Sky Atmosphere の「大気パラメータ」で `r.Atmosphere.AerialPerspectiveKmPerSlice` を 20 にしても、壁と手前の柱は霞まない。確かめたら 4 に戻す（値はシーンに保存される）。
3. MainCamera の回転 X を 0（水平）や -0.1（上向き）にしても、境目は出ない。

## GameObject_Tags

オブジェクトのタグ（`Tags.json` の名前・インスペクタの Tag・スクリプトの `CompareTag`・`FindObjectsWithTag`・プレハブのタグ）を確かめます。

このプロジェクトのタグは `Application/Config/EngineSettings/Tags.json` の Untagged・Player・Enemy の 3 つです。

| 物 | 見るところ |
|---|---|
| Enemy_A・Enemy_B | 赤い立方体。インスペクタの Tag が Enemy |
| Plain | 灰色の立方体。Tag が Untagged |
| Probe | 試験のスクリプト（TagProbe）。再生すると、プレハブ TaggedEnemy（タグ Enemy）から右端に 1 体出し、Enemy のタグを持つ物を集めて 1.5m 持ち上げる |

確かめ方:

1. 停止中に Enemy_A を選ぶと、インスペクタの名前の下に Tag の欄があり Enemy になっている。欄を開くと Untagged・Player・Enemy が並ぶ。
2. 再生すると赤い立方体 3 つ（Enemy_A・Enemy_B・右端に出た Enemy_FromPrefab）だけが浮き上がり、Plain は床に残る。コンソールに「Enemy のタグを持つ物 3 個（期待 3）」など、TagProbe の行が 4 つ出て、どれも期待どおり。
3. 再生中に Enemy_FromPrefab を選ぶと Tag が Enemy。止めてから Plain の Tag を Enemy に変えて再生すると 4 つ浮く（再生中に変えたタグは止めると戻る。確かめたら Plain を Untagged に戻す）。
4. Project の Prefabs/TaggedEnemy を選ぶと、インスペクタの「プレハブの中身」に Tag が出る。TaggedEnemy をシーンへ置いて Tag を Player に変えると、Tag の行の左端に青い線が出る。Tag のラベルを右クリックして「プレハブの値に戻す」で Enemy に戻る（置いた物は消してから保存する）。
5. Edit ▸ Project Settings… の Tags でタグを足して「適用」すると、Tags.json に書かれ、インスペクタの Tag の欄にすぐ出る（確かめたら外して適用する）。

## Animator_StateMachine

アニメーター設定（`.animator` の状態・遷移・パラメータ）と、設定を指さない Animator を確かめます。空の環境光は入れています。

人形は `Models/AnimRobot/AnimRobot.gltf`（箱をつないだ骨 11 本の人形。クリップは Idle・Walk・Run・Jump・Attack・Fall・WalkBack・StrafeL・StrafeR・WalkForward・WalkTurn）です。設定は `Animators/Robot.animator` です。

| 物 | 見るところ |
|---|---|
| Robot | 左の人形。Animator の「設定」が Robot.animator。試験のスクリプト（AnimatorStateMachineProbe）が 15 秒ごとに同じ表でパラメータを書き、状態が移るたびにコンソールへ出す |
| Robot_NoController | 右の人形。Animator の「設定」が空で、clips の Idle・Walk・Attack を試験のスクリプト（AnimatorClipProbe）が 6 秒ごとに `SwitchWithBlend`・`Switch` で切り替える |

Robot.animator の中身:

| 遷移 | 条件 |
|---|---|
| どこからでも → Fall | Grounded が false |
| Idle → Walk・Walk → Idle | Speed > 0.1・Speed < 0.1 |
| Walk → Run・Run → Walk | Speed > 3・Speed < 3 |
| Idle → Attack・Walk → Attack | トリガー Attack |
| Attack → Idle | 終わりの時刻 0.9（条件なし） |
| Idle → Jump | トリガー Jump |
| Jump → Idle | 終わりの時刻 0.95（条件なし） |
| Fall → Idle | Grounded が true |

確かめ方:

1. 停止中、2 体とも Idle の最初のコマの姿勢で立っている（点に潰れていない）。
2. 再生すると、Robot のコンソールの行が次の順に出る（時刻は表の秒数。混ぜている間は移る先の名前になる）。15 秒ごとに同じ順でくり返す。
   - 2 秒 Idle → Walk・5 秒 Walk → Run・7 秒 Run → Walk、すぐ Walk → Idle
   - 8 秒 Idle → Attack、約 8.6 秒 Attack → Idle（終わりの時刻）
   - 10.5 秒 Idle → Fall（どこからでも）・12 秒 Fall → Idle
   - 13 秒 Idle → Jump、約 13.9 秒 Jump → Idle（終わりの時刻）
3. Robot_NoController のコンソールの行が「切り替え Walk」「切り替え Attack」「切り替え Idle」の順に出て、Attack の腕の振りは 1 回で止まる。
4. Project の Animators/Robot.animator をダブルクリックしてアニメーターの窓を開き、再生中に Hierarchy で Robot を選ぶ。今の状態の箱が光り、下に進み具合の帯が出て、遷移の途中は矢印が緑になる。
5. Robot の AnimatorStateMachineProbe の「autoDrive」を外すと、パラメータを書かなくなる。窓の左の Speed を 1 にすると Walk へ、Attack の「立てる」を押すと攻撃する（止めると戻る）。

## Animator_BlendTree

ブレンドツリー（1D・2D）・アニメーションのイベント・停止中の「シーンで見る」を確かめます。人形は Animator_StateMachine と同じで、設定は `Animators/RobotBlend.animator` です。

| 物 | 見るところ |
|---|---|
| Robot_1D | 左の人形。試験のスクリプト（AnimatorBlendProbe・strafe が false）が 12 秒ごとに Speed を 0 → 4 → 0 と往復させる（0〜2 秒 0・2〜6 秒 上げる・6〜8 秒 4・8〜12 秒 下げる） |
| Robot_2D | 右の人形。AnimatorBlendProbe（strafe が true）が向き (MoveX, MoveY) を前 → 右 → 後ろ → 左と 12 秒で 1 周させ、その向きへ 0.6 m/s で動かす |

RobotBlend.animator の中身:

| 状態 | 流すもの |
|---|---|
| Locomotion（最初の状態） | 1D ブレンド。パラメータ Speed。Idle 0・Walk 1.5・Run 4 |
| Strafe | 2D ブレンド。パラメータ MoveX・MoveY。Idle (0, 0)・Walk (0, 1)・WalkBack (0, -1)・StrafeL (-1, 0)・StrafeR (1, 0) |

遷移は Locomotion → Strafe が Strafe が true、Strafe → Locomotion が Strafe が false（どちらも 0.3 秒で混ぜる）です。

クリップのイベントは、Walk・Run・WalkBack・StrafeL・StrafeR に FootL（数 0、文字 left）と FootR（数 1、文字 right）が 1 回ずつあります。小数は Walk 0.5・Run 1.0・ほか 0.4 です。Idle にはありません。AnimatorBlendProbe は足音を数え、1 秒ごとにコンソールへ「足音 L 1・R 1（最後は Walk・数 0.50）」のように出します。

確かめ方:

1. 再生すると、Robot_2D のコンソールに「状態 Locomotion → Strafe」が出る。Robot_1D は Locomotion のまま。
2. Robot_1D の行: Speed が 0 の間は「足音 L 0・R 0」（いちばん重いのは Idle で、Idle にはイベントがない）。Speed が上がると Walk の足音が出て、2.75 を越えると「最後は Run・数 1.00」に変わる。Speed 4 の間は 1 秒に L・R が 1〜2 回ずつ（Run は 0.6 秒）。
3. Robot_2D の行: 向きが回るにつれて、最後のクリップが Walk → StrafeR → WalkBack → StrafeL → Walk と変わり、足音は 1 秒に L・R が 1 回ずつ前後。
4. Project の Animators/RobotBlend.animator を開き、再生中に Hierarchy で Robot_2D を選んで Strafe の箱を選ぶ。右の 2D の図で今の値の点が円を回り、子の割合（%）が変わる。
5. 停止中に窓の上の「シーンで見る」を入れ、Hierarchy で Robot_1D を選び、Locomotion の箱を選ぶ。窓の上に「シーンで見る: Robot_1D（Locomotion）」と出て、Robot_1D がその場で動く。右の 1D の図の値の線をドラッグすると、Idle → Walk → Run と混ざり方が変わる（保存はしない）。「止める」と「進み」のつまみで 1 コマずつ見られる。
6. Locomotion の「子」の Walk の行の左の丸を押すと、下に Walk のクリップの設定が出て、イベントの帯に FootL・FootR の印が出る。「シーンで見る」の間は帯に今の位置の線が出る。印をドラッグすると時刻が変わり、帯のダブルクリックでイベントが足せる（確かめたら保存せずに閉じる）。
7. 「シーンで見る」を外すか窓を閉じると、人形は元の姿勢へ戻る。

## Animator_Layers

レイヤー・重み・マスク（体の一部だけ別の動き）を確かめます。人形は Animator_StateMachine と同じで、設定は `Animators/RobotLayers.animator` です。

| 物 | 見るところ |
|---|---|
| Robot_Layered | 左の人形。試験のスクリプト（AnimatorLayerProbe・useLayer が true）が 12 秒ごとに、1 秒で重み 1・5 秒で重み 0.5・9 秒で重み 0 にして、そのたびに Attack のトリガーを立てる |
| Robot_BaseOnly | 右の人形。AnimatorLayerProbe（useLayer が false）が UpperBody の重みをいつも 0 にする（脚の動きを比べる見本） |

RobotLayers.animator の中身:

| レイヤー | 中身 |
|---|---|
| Base（最初のレイヤー） | 状態 Walk だけ（Walk のクリップ。足音のイベント FootL・FootR） |
| UpperBody（重み 1・マスクあり） | マスクは Spine・Head・UpperArm.L・LowerArm.L・UpperArm.R・LowerArm.R。状態 None（流すもの無し・最初の状態）と Attack（Attack のクリップ・ループしない・0.3 秒にイベント Swing）。None → Attack はトリガー Attack（0.15 秒）、Attack → None は終わりの時刻 0.95（0.25 秒） |

確かめ方:

1. 再生すると、2 体とも同じ歩きで、脚の動きが揃っている。
2. 1 秒・5 秒（と 12 秒ごと）に、Robot_Layered だけ上半身で攻撃する。脚は Robot_BaseOnly と同じ歩きのまま。5 秒の回は重み 0.5 なので腕の振りが小さい。9 秒の回は重み 0 なので見た目は変わらない。
3. Robot_Layered のコンソールの行が「重み 1.00 で Attack」「UpperBody None → Attack・Base は Walk」「Swing（レイヤー UpperBody・クリップ Attack・状態 Attack）」「UpperBody Attack → None」の順に出る。重み 0 の回は状態は移るが Swing は出ない。始めに 1 回だけ「FootL（レイヤー Base・クリップ Walk）」が出る。
4. Project の Animators/RobotLayers.animator を開く。左のレイヤーの表に Base（土台）と UpperBody（1.00・マスク）が並ぶ。UpperBody を選ぶと、キャンバスが None・Attack の表に替わり、右に重み・マスクの骨の木が出る。骨の木で Spine を外すと下の骨もまとめて外れ、Ctrl+Z で戻る（確かめたら保存せずに閉じる）。
5. 再生中に Hierarchy で Robot_Layered を選ぶと、窓の上に「再生中: Robot_Layered（None）」と出て、右に「再生中の重み」が出る。スクリプトが重みを変えると、つまみも動く。つまみを下げてから左のパラメータ Attack の「立てる」を押すと、腕の振りが小さくなる（止めると戻る）。

## Animator_RootMotion

クリップの移動（ルートモーション：クリップの中の腰の移動と向きの変化でオブジェクトを動かす）を確かめます。人形は同じで、設定は `Animators/RobotRootMotion.animator`（状態 Forward・Turn・Idle。「移動を取る骨」は（自動）で Hips になる）です。

クリップ WalkForward（1 秒）は腰が前へ 1.42m 進み、WalkTurn（2 秒）は腰が左回りに 90 度向きを変えながら半径 1.81m の弧を進みます。

| 物 | 見るところ |
|---|---|
| Robot_RootMotion | 奥の人形。Animator の「クリップの移動で動かす」が入っている。試験のスクリプト（AnimatorRootMotionProbe）が Forward を流し、始めの場所から 7m 進んだら始めの場所へ戻す |
| Robot_InPlace | 手前の人形。「クリップの移動で動かす」が切れている。Forward を流す |
| Robot_Turn | 右の人形。「クリップの移動で動かす」が入っていて、キャラクタコントローラとカプセルのコライダーが付いている。Turn を流す |

確かめ方:

1. 再生すると、Robot_RootMotion は脚の運びに合わせて床を右へ進み（足が滑らない）、約 5 秒で 7m 進んで始めの場所へ戻る。コンソールに「7.xx m 進んだので始めの場所へ戻す」が出る。

## Animator_Sprite

アニメーターでスプライトアニメ（2D のコマ）を動かす仕組みを確かめます。絵は `Textures/AnimatorSprite_Numbers.png`（横 4・縦 2 の 8 コマに 0〜7 の番号。Idle の 0・1 が青、Run の 2〜5 が緑、Jump の 6・7 が橙）です。

どちらの物にも、スプライト描画・スプライトアニメ（クリップ Idle 0〜1 の 2fps・Run 2〜5 の 8fps・Jump 6〜7 の 4fps でループなし）・Animator・試験のスクリプト（AnimatorSpriteProbe）が付いています。アニメーターの設定のクリップは、モデルのファイルの代わりにスプライトアニメのクリップの名前を指します（`{ "id": "Run", "sprite": "Run" }`）。

| 物 | 見るところ |
|---|---|
| Sprite_States | 左。設定は `Animators/SpriteStates.animator`。AnimatorSpriteProbe（mode 0）が 8 秒ごとに Speed を 0（0〜2 秒）→ 1（2〜5 秒）→ 0 にし、5 秒で Jump のトリガーを立てる |
| Sprite_Blend | 右。設定は `Animators/SpriteBlend.animator`。AnimatorSpriteProbe（mode 1）が 8 秒で Speed を 0 → 1 → 0 と往復させる |

SpriteStates.animator の中身:

| 状態 | 流すもの |
|---|---|
| Idle（最初の状態） | クリップ Idle |
| Run | クリップ Run |
| Jump（ループなし） | クリップ Jump |

遷移は Idle → Run が Speed > 0.5、Run → Idle が Speed < 0.5、どこからでも → Jump が Jump のトリガー、Jump → Idle が終わりの時刻 1 です。どれも混ぜる秒数を 0.25 にしてありますが、スプライトのクリップを使う設定では混ぜずにすぐ移ります。

SpriteBlend.animator は状態 Locomotion（1D ブレンド。パラメータ Speed。Idle 0・Run 1）だけです。スプライトは混ぜられないので、いちばん重い子のクリップのコマを出します。

クリップ Run には、0.25 秒にイベント Step（数 0.5・整数 1・文字 run）があります。Run は 1 周 0.5 秒です。

確かめ方:

1. 再生すると、コンソールに「AnimatorSpriteProbe（Sprite_States）: 状態 （始め） → Idle・クリップ Idle・コマ 0」が出て、左の絵が 0 と 1 を 0.5 秒ずつくり返す。警告は出ない。
2. 2 秒で「状態 Idle → Run・クリップ Run・コマ 2」の 1 行で移り、絵は 2 → 3 → 4 → 5 を 0.125 秒ずつくり返す（混ぜる間が無い）。1 秒ごとの行が「1 秒の Step 2」になる。
3. 5 秒で「状態 Run → Jump・クリップ Jump・コマ 6」、0.25 秒後にコマ 7、0.5 秒で「状態 Jump → Idle」に戻る。Jump と Idle の間は「1 秒の Step 0」。
4. 右の Sprite_Blend は、Speed が 0.5 より小さい間（0〜2 秒と 6〜8 秒）はクリップ Idle の 0・1、大きい間（2〜6 秒）はクリップ Run の 2〜5 を出し、Run の間は Step が出る。状態はずっと Locomotion。
5. 再生中に Sprite_States の Animator を切ると、スプライトアニメが自分で進み始める（最後のクリップのまま）。入れ直すと、またアニメーターがコマを決める。スプライトアニメのインスペクタには「今は同じオブジェクトの Animator がコマを決めています」と出る。
6. 停止中に Project の Animators/SpriteStates.animator を開き、Hierarchy で Sprite_States を選ぶ。左の「クリップ」の Run を開くと「種類」が「スプライトのクリップ」で、「スプライトのクリップ」の候補に Idle・Run・Jump が並び、イベントの帯に尺 0.500 秒と Step の印が出る。
7. 窓の上の「シーンで見る」を入れて Run の箱を選ぶと、窓の上に「シーンで見る: Sprite_States（Run）」と出て、左の絵が 2〜5 を流れる。「止める」と「進み」のつまみで 1 コマずつ見られる。「シーンで見る」を外すか窓を閉じると、元のコマへ戻る。
8. キャンバスの何も無い所を右クリックすると「スプライトアニメから状態を作る」があり、左の「スプライトアニメから足す」と同じく、選んでいる物のスプライトアニメのクリップを足す（同じ名前を指すクリップがあれば足さない。確かめたら保存せずに閉じる）。

どのドロップダウンも、GameObject ▸ UI ▸ ドロップダウン で作るものと同じ組み立てです（押す所の下に、隠した一覧のひな形 Template・中身 Content・行のひな形 Item・スクロールバー）。

確かめ方:

1. 再生すると、コンソールに「ClearOptions の後 選択肢 0 個・値 0」「AddOption を 3 回の後 選択肢 赤・緑・青・今の値の文字 赤」「options を 4 つにして値を 2 にすると 今の値の文字 秋」「RemoveOption(0) の後 選択肢 夏・秋・冬・値 1・今の値の文字 秋」「値を 99 にすると 2」「Open() の後 isOpen true」「Close() の後 isOpen false」「押せない Disabled に Open() すると isOpen false」が出る。どの行も（期待 …）と同じになる。
2. Quality を押すと一覧が下に開き、コンソールに「Quality の一覧は押す所の下・高さ 152・画面に収まる」「Quality の今の値の行は一覧の中に見えている」が出る。一覧は赤いボタンの上に描かれ、今の値（中）の行に ✓ が付く。
3. 一覧の「高」を押すと、値が 2（高）になって一覧が閉じる。赤いボタンと重なる所を押しても「BlockButton が押された」は出ない。
4. Long を開くと「高さ 320」になり、一覧の右にスクロールバー（明るい帯に濃いつまみ）が出て、項目 15 の行が一覧の中ほどに見える。ホイール・ドラッグ・スクロールバーで動かせる。
5. 一覧が開いている間に一覧の外（OutsideButton の上など）を押すと、一覧が閉じるだけでボタンは押されない（「OutsideButton が押された」が出ない）。閉じてからもう一度押すと「OutsideButton が押された」が出る。
6. Bottom を開くと「Bottom の一覧は押す所の上」が出て、一覧が押す所の上に開く。
7. Masked を開くと、一覧が枠の外まで切られずに出る。
8. キー：最初は OutsideButton が選ばれている。上下左右（パッドは十字・左スティック）でドロップダウンを選び、Enter（パッドは A）で開くと、今の値の行が選ばれる。上下で行が動き（一覧の外へは出ない）、Enter で選ぶ。Esc（パッドは B）は値を変えずに閉じる。閉じると選んでいる所がドロップダウンへ戻る。
9. Disabled は押しても開かない。

## UI_InputField

UI 入力欄（UIInputField）を確かめます。押すと文字を打てるようになり、Enter で確定、Esc で打つ前の文字に戻ります。日本語の変換（IME）もそのまま使えます。

| 物 | 見るところ |
|---|---|
| Name | なんでも入る 1 行の欄。日本語の変換もここで試す |
| Limit | 最大 8 文字の欄。9 文字目からは入らない |
| Integer | 整数だけの欄。数字と、先頭の - 1 つだけが入る |
| Decimal | 小数の欄。数字と、先頭の - と . 1 つだけが入る |
| Alnum | 英数字だけの欄。空白・記号・日本語は入らない |
| Password | 伏せ字の欄。打った文字は * で出る。コピーはできない |
| ReadOnly | 読み取りだけの欄。選んでコピーはできるが、打っても消しても変わらない |
| Disabled | 「押せる」を外した欄。押しても打てない |
| Multi | 複数行の欄（600×220）。Enter で改行し、行が増えると縦にずれる |
| Long | 長い文の入った 1 行の欄。カーソルが欄に収まるよう文字が横へずれる |
| MoverArea・Mover | WASD（移動のアクション）で動く四角。打っている間は動かない |
| Status | 右の文字。各欄の文字と、打っている欄 |
| Probe | 試験のスクリプト（UIInputFieldProbe）。最初にスクリプトからの操作を確かめ、その後は文字の変化・確定・打ち始めと打ち終わりを出す |

どの欄も、GameObject ▸ UI ▸ 入力欄 で作るものと同じ組み立てです（枠の下に、はみ出した文字を切る Text Area・置き文字 Placeholder・打った文字 Text）。

確かめ方:

1. 再生すると、コンソールに「整数だけの欄に 12a-3.4 を入れると 1234」「-42 を入れると -42」「小数の欄に -3.14.15 を入れると -3.1415」「英数字だけの欄に「abc あいう 123!」を入れると abc123」「8 文字までの欄に 10 文字を入れると あいうえおかきく」「最大の文字数を 4 にすると あいうえ」「伏せ字の欄に secret を入れると text secret・出す文字 ******」「1 行の欄に改行入りの文字を入れると 改行なし」「複数行の欄に CRLF 入りの文字を入れると 改行 2 行」「名前の欄を整数だけにすると 空」「Focus() の後 isFocused true」「Unfocus() の後 isFocused false・wasSubmitted false」「押せない Disabled に Focus() すると isFocused false」が出る。どの行も（期待 …）と同じになる。
2. Name を押すと、押した所にカーソルが出て点滅し、枠の色が変わる。打った文字が入り、←→・Home・End・押した所でカーソルが動く。Enter で「Name を確定した」と「Name を打ち終えた」が出る。
3. 日本語の変換を ON にして打つと、変換中の文字が下線付きで欄の中に出て、変換の候補の窓がカーソルの所に出る。確定すると文字が入る。変換中に Esc を押すと変換中の文字だけが消え、欄の文字は変わらない。
4. 打っている間に WASD を押しても Mover は動かない（コンソールに「打っている間に Mover が動いた」が出ない）。欄の外を押して打ち終えると、WASD で Mover が動く。
5. 文字をドラッグすると選ばれて、文字の後ろに選んだ色が付く。Shift＋←→・Shift＋押す・Ctrl+A でも選べる。選んだまま打つ・Backspace・Delete で選んだ文字が消える。Ctrl+C・Ctrl+X・Ctrl+V でコピー・切り取り・貼り付けができる。Ctrl＋←→ で単語ごとに動く。
6. Limit に 10 文字打つと 8 文字で止まる。Esc を押すと打つ前の文字（空）に戻る。
7. Integer に「a1-2b3」と打つと 123 になり、Home で先頭へ戻って - を打つと -123 になる。Decimal に「3.1.4」と打つと 3.14 になる。Alnum に「ab cd!12」と打つと abcd12 になる。
8. Password に打つと * で出る。Ctrl+C を押してもコピーされない。
9. Multi で Enter を押すと改行し、行が欄からはみ出すとカーソルの行が見えるよう縦にずれる。↑↓ で行を移る。Ctrl+Enter か欄の外を押すと「Multi を確定した」が出て、打ち終えると先頭の行へ戻る。
10. Long で End を押すと文字が横へずれて末尾が見え、Home で先頭に戻る。
11. ReadOnly は打っても Backspace を押しても変わらない。選んで Ctrl+C でコピーはできる。日本語の変換は ON にならない。
12. Disabled は押しても打てない。
13. 打っている間も、エディタの Inspector などの文字の欄は今まで通り打てる。エディタの欄で打った文字は、ゲームの欄には入らない。
