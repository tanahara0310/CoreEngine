# WaterTestScene 水面実装 質疑応答ノート（実演ベース）

## 0. この資料の前提

**シチュエーション:** 先輩に実際に動いている画面（水面デモ + ImGui操作）を見せて、その後に質疑応答を行う。

つまり先輩はまずコードではなく**画面**を見ます。質問も「これはどうやってるの？」という現象ベースで来る可能性が高いです。  
そのため、この資料は「クラス名・関数名の暗記」ではなく、**画面のどの現象について、どこまで深く答えられれば十分か**を優先順位付けして整理しています。

内部実装（変数名・関数呼び出し順など）は末尾に圧縮して残していますが、そこは**聞かれたら答える／コードを見せる**レベルでよく、暗記の優先度は低いです。

---

## 1. 知識の深さ 3段階（ここが一番重要）

質問は必ず「浅い質問→深い質問」の順で来ます。段階ごとに求められる回答レベルが違うので、まずこの3段階を意識してください。

| レベル | 求められる場面 | 答える内容 | 暗記の優先度 |
|---|---|---|---|
| **A：原理レベル** | 画面を見て一言目に聞かれる | 「何をやっているか」を一言で | 必須（即答） |
| **B：仕組みレベル** | 「それってどうやって？」と突っ込まれた | 処理の流れを3〜5ステップで | 推奨（要説明） |
| **C：実装レベル** | 「コード見せて」と言われた | クラス名・変数名・関数名 | 不要（見せればいい） |

**この資料の使い方:** 各項目で A → B の順に読み、Cは「気になったらここ」程度に流し見でOKです。

## 2. 画面で見える現象 → 説明の対応表

実演で見せるであろう項目ごとに、A/Bレベルの説明を用意しています。

### 2-0. そもそも「Gerstner Wave」と「FFT Ocean」って何？（超簡易版）

ここは、先輩に最初に聞かれたときのための**最短回答テンプレ**です。

- **Gerstner Wave って何？**  
  「波を何本か足し算して作る方法」です。  
  1本ずつに“向き・高さ・速さ”を設定して重ねるので、直感的に調整しやすいです。

- **FFT Ocean って何？**  
  「海全体を周波数ベースで作る方法」です。  
  風の情報から“どのサイズの波がどれくらいあるか”を作り、逆FFTで実際の水面形状に戻します。大きい海面に強いです。

- **使い分けを一言で言うと？**  
  - Gerstner: 軽くて分かりやすい、ローカルな演出向き  
  - FFT Ocean: より海らしい広域表現向き

- **このプロジェクトでは？**  
  ImGuiから両方を切替でき、見た目・負荷・用途で選べる構成です。

### 2-1. 水面がゆらゆら揺れている（波の動き）

- **レベルA（一言）:**  
  「波を数式で計算して頂点やテクスチャを動かしている。方式は2つ用意していて、軽量な Gerstner Wave と、本格的な FFT Ocean を切り替えられる」

- **レベルB（仕組み）:**  
  - Gerstner: 波を最大16本重ね合わせて、方向・振幅・波長・速度・急峻さのパラメータで頂点を上下左右にずらす。局所的な水面向き。
  - FFT Ocean: 風向・風速からスペクトル（周波数ごとの波の強さ）を作り、時間発展させてから逆フーリエ変換（IFFT）で実空間の波形に戻す。海全体のような広い水面向き。
  - どちらを使うかは ImGui の「描画方式」ラジオボタンで切替。切替時は内部で使用シェーダも入れ替わる。

- **レベルC（実装が気になったら）:**  
  `WaterPlaneObject::SetUseFFTOcean` / `GerstnerWaterSimulator` / `FFTOceanManager::Dispatch`

---

### 2-2. 水面に周りの景色が映り込んでいる（反射）

- **レベルA:**  
  「カメラを水面に対して鏡写しにしたもう一枚の絵を裏で描画して、それを反射テクスチャとして水面に貼っている」

- **レベルB:**  
  1. 通常カメラとは別に「反射用カメラ視点」を一時的に作る（水面の高さを基準に上下反転）
  2. その視点で裏側にもう一度シーンを描画する（水面より下は描かない）
  3. できた絵を水面のシェーダに渡して、フレネル反射として合成する
  4. 描画が終わったら元のカメラに戻す

- **レベルC:**  
  `WaterReflectionPass::SetupReflectionCamera` / `XMMatrixReflect` / clip plane

---

### 2-3. 水底や水中の地形が透けて見える／遠くほど色が濃くなる

- **レベルA:**  
  「深度情報を使って、水面から水底までの距離に応じて透明度と色を変えている（Depth Fade）」

- **レベルB:**  
  1. 深度バッファから「水面のすぐ下に何があるか」の距離を求める
  2. 距離が短い（浅瀬）ほど元の色が透けて見え、遠い（深場）ほど設定した深い色に近づける
  3. 浅瀬色・深場色・吸収係数はImGuiで調整可能

- **レベルC:**  
  `WaterFrameConstants::absorptionCoeff / shallowColor / deepColor`、Water.PS.hlsl 側の Depth Fade 計算

---

### 2-4. 水底にゆらゆら光の模様が映っている（コースティクス）

#### 原理（先にこれだけ言えば通る版）

コースティクスは、**水面を通った光が場所によって集まる（明るくなる）/広がる（暗くなる）**現象です。  
プールの底に出る“キラキラ模様”そのものです。

水面がレンズのように働くため、

- 水面法線の変化が大きい場所ほど光の進行方向が大きく変わる
- 近い方向に光が集まる場所は高輝度
- 光が拡散する場所は低輝度

になります。

- **レベルA:**  
  「光が水面で屈折して集まる/散る現象（コースティクス）を再現している。光線を飛ばして計算する版と、画面全体に後処理として合成する版の2系統がある」

- **レベルB:**  
  1. 水面の凹凸（法線の曲率）から、光が集中する場所・拡散する場所を計算
  2. レイトレーシングで水中オブジェクトに実際に光跡を落とす経路と、GBufferの情報から画面全体に模様を合成する経路がある
  3. 強度・減衰・集光の鋭さ（alignmentPower）などをImGuiで調整可能

- **レベルC:**  
  `RTWaterCausticsPass` / `WaterCausticsTechnique`

補足（実装の考え方）:

- **RT版**: レイを使って「光がどこに届くか」を幾何的に求める
- **後処理版**: GBuffer（WorldPos/Normal）と水面情報から近似的に輝度を作る
- 最終的には強度・減衰・集光パラメータで見た目を調整する

---

### 2-5. 水越しに向こう側の物体が歪んで見える（屈折）

#### 原理（先にこれだけ言えば通る版）

屈折は、**空気と水で光の進みやすさが違うため、境界面（水面）で光が曲がる**現象です。  
視点から見たとき、背景のサンプル位置がずれるので「向こう側が歪んで見える」ようになります。

直感的には以下です。

- 水面法線が傾いているほど曲がる方向が変わる
- 屈折率が高いほど曲がり量が大きくなる
- 見た目としては背景画像の参照UVがオフセットされる

- **レベルA:**  
  「レイトレーシングで実際に光を屈折させて、水面越しの見え方をピクセル単位でずらしている」

- **レベルB:**  
  1. 画面に映っている背景（コピーしておいたシーン画像）を用意
  2. 水面のどこから見ても、屈折の法則で光が曲がる方向を計算
  3. その方向にどれだけ背景をずらして表示するかを決めて合成
  4. 屈折率・最大ずれ量(px)・吸収係数をImGuiで調整可能

- **レベルC:**  
  `WaterRefractionRayTracingManager::Dispatch` / `RTWaterRefractionPass`

補足（実装の考え方）:

- 入力は WorldPosition / SceneColor / 水面情報（必要に応じてFFT法線）
- 屈折方向を計算し、背景サンプル位置を決定
- サンプル位置のずれ量には上限（px）を設けて破綻を抑える
- 吸収係数を併用して、水中を通るほど減衰する見え方にする

---

### 2-6. ImGuiで「Gerstner Wave」「FFTOcean」を切り替えるボタン

- **レベルA:**  
  「見た目の表現方式を丸ごと差し替えている。波の生成ロジックとシェーダの両方が切り替わる」

- **レベルB:**  
  内部では2つの「波シミュレーション」を両方用意しておき、今どちらを使うかのフラグで分岐しているだけ。切り替えの瞬間にGPU処理待ちを入れて、描画パイプライン(PSO)を安全に再構築している。

- **レベルC:**  
  `WaterSurfaceRuntimeController::GetActiveSimulator` / `RebuildWaterShaderPipeline`

---

### 2-7. ImGuiでパラメータ（風速・振幅・波数など）を変えると見た目が変わる

- **レベルA:**  
  「UIで変更した値をそのままGPU側の計算パラメータに送り直しているだけ。プリセット（湖・海・池・雨）も用意している」

- **レベルB:**  
  - Gerstner側は波の配列を書き換えて即座にGPUバッファへ反映
  - FFT側はパラメータが変わると一度GPU待ちをしてから、スペクトル（波の元データ）を再計算し直す
  - プリセットは「代表的な設定値のテンプレート」を適用しているだけ

- **レベルC:**  
  `WaterSurfaceParameterPanel` / `FFTOceanManager::SetSettings` / `FFTOceanSpectrumBuilder::BuildSpectrum`

---

### 2-8. デバッグ表示切替（深度・反射・フレネルなど色々な可視化モードがある）

- **レベルA:**  
  「開発用に、水面計算の途中結果をそのまま色として出せる確認モードを用意している」

- **レベルB:**  
  ピクセルシェーダの最終出力を、通常の合成結果ではなく「深度差」「反射のみ」「フレネル値のみ」などの中間値に差し替えて表示しているだけ。デバッグ用で見た目のクオリティには影響しない。

- **レベルC:**  
  `WaterDebugViewMode` / `SetDepthDebugViewMode`

## 3. 質疑応答の深堀りシミュレーション（浅い→深い）

実際にありそうな会話の深まり方を想定しています。**どの段階まで答えれば十分か**を意識してください。

**Q. 「この水どうやって作ったの？」**  
→ レベルAで即答（2-1参照）。ここで実装の詳細まで話す必要はない。

**Q. 「へえ、FFTって聞いたことあるけど何が良いの？」**  
→ レベルB。「風のパラメータから統計的に自然な波形を作れて、Gerstnerより広い海面向き」と仕組みベースで回答。

**Q. 「実際どういう計算式でやってるの？」**  
→ ここで初めて数式・アルゴリズム名（Phillipsスペクトル、逆FFT等）に触れてよい段階。この深さまで来たら「コードも見ますか？」と提案してOK。

**Q. 「変数名とか教えて」**  
→ レベルC。ここは暗記していなくても、その場でコードを開いて見せれば問題ない。

**結論:** レベルA・Bを言葉に出して説明できることが最優先。レベルCは検索・提示できれば十分で、暗記は不要です。

## 4. 「暗記しなくていい」ライン（明示）

以下は聞かれる可能性は低く、暗記の優先度を下げてよい内容です。聞かれたらコードを開いて見せれば十分。

- GPU定数バッファのバイトサイズ・アライメント
- ルートパラメータのスロット番号やバインド名の綴り
- IFFTの ping-pong バッファの変数名
- ヘルパークラスの内部関数名（`FFTOceanDispatchHelper` 等）
- ログ出力の詳細フォーマット

これらは「エンジンとして丁寧に作り込んである」ことが伝われば十分で、暗唱する必要はありません。

## 6. 60秒説明スクリプト（そのまま話せる版）

「この水面は、大きく分けて“波の形を作る部分”と“光の見え方を作る部分”に分かれています。  
波の形は Gerstner Wave と FFT Ocean の2方式を切り替えられるようにしていて、Gerstnerは波を数本重ねる軽量な方式、FFTは風のパラメータから海面全体をシミュレーションする方式です。  
光の見え方は、反射・屈折・コースティクス・深度に応じた透明度変化を組み合わせています。反射は裏でもう一度カメラを鏡写しにして描画し、屈折はレイトレーシングで背景のずれを計算し、コースティクスは水面の凹凸から光の集中具合を計算しています。  
これらは全部 ImGui からリアルタイムに調整できるようにしてあります。」

## 付録：内部実装の要点（レベルC・参照用）

聞かれたときにコードと一緒に見せるための最小限のポインタです。暗記不要。

- 水面オブジェクト本体: `WaterPlaneObject`（定数・SRV受け口・シェーダ選択）
- 毎フレーム更新の窓口: `WaterSurfaceRuntimeController`（時間更新・SRV同期・DXR入力更新）
- 波シミュレーション: `GerstnerWaterSimulator` / `FFTOceanSurfaceSimulator`（共通IF `WaterSurfaceSimulator`）
- FFT本体: `FFTOceanManager`（Evolution → IFFT → Finalize の3段Compute）
- 反射制御: `WaterReflectionPass`（鏡像カメラ＋clip plane）
- DXR屈折/コースティクス: `WaterRefractionRayTracingManager` / `WaterCausticsRayTracingManager`
- 描画順序（RenderGraph）: `FFTOceanPass` → `RTWaterCausticsPass` → `WaterCausticsPass` → `DeferredLightingPass` → `SceneColorCopyPass` → `RTWaterRefractionPass` → `WaterSurfacePass`
- 調整UI: `WaterSurfaceParameterPanel`（見た目調整）/ `WaterSurfaceDebugPanel`（診断・可視化）
