# カメラリグ

シーンの状態（誰がどこにいるか）からカメラの構図を毎フレーム決め直す設定です。
時刻で動かすカットシーンは `../CameraClips/`（シーケンス）のほうを使ってください。

エディタの `Camera Editor → リグ` タブで編集・保存します。手で書く場合、
Vector3 は **配列** `[x, y, z]` です（オブジェクトではありません）。

コードからは名前で呼びます。

```cpp
CameraRig::Activate("GameCamera");

CameraRigActivateOptions options;
options.blendSeconds = 1.5f;      // 今の構図から 1.5 秒かけて移る
options.useUnscaledTime = true;   // ヒットストップ中も進める
CameraRig::Activate("Train_CloseUp", options);

CameraRig::Deactivate();          // ゲーム側の追従へ返す
```

## GamePlay

GameScene が実際に使う俯瞰カメラです。`_camera.json` の `startupRigName` に
指定してあるので、シーン開始時に自動で動き出します（コードからの Activate は不要）。

| | 値 | ねらい |
|---|---|---|
| Body | FrameTargets{ Train, RailBuilder } | トロッコとレール先端の中点を追う |
| 寄り | (0.5, 0.5, 0.5) | 3 軸そろえる。**Aim の重みと一致させるのが必須** |
| オフセット | (0, 18.5, -11.5) | 俯角 58.1 度・注視点から 21.8m |
| オフセットの向き | ワールド軸 | 対象が向きを変えてもカメラは回らない |
| 先行 | 対象 2 件とも ずらし (2, 0, 0) | 進行方向 +X に 2 マスぶん余白を作る |
| 広がり 1m あたり引く量 | 0.3 | ビルダーが先行するほど引いて両方を収める |
| 引く量の上限 | 2.5 | ここで引きを止める（下の「外側を見せない」を参照） |
| 主対象 | **Monkey** | SpeedToFov が速度を読む先（下の注意を参照） |
| Aim | FrameTargets{ Train, RailBuilder }（重み 1:1） | Body の寄り 0.5 と同じ点になる |
| 画面内の位置 | (0.5, 0.44) | **X は 0.5 固定。** Y だけ少し上げて手前の余白を稼ぐ |
| Lens | SpeedToFov 0.5m/s→32 度 / 6m/s→35 度 | 列車が加速するほど広がる |
| 減衰 | 位置 3.5 / 注視先 4.0 / 視野角 3.0 / 向き 0 | |
| 寄せ方 | **バネ** | ビルダーがグリッド単位で飛んでもカクつかせない |
| 追従を止める軸 | 強さ (1, 0, 0) / 据え置き (0, 0.8, 5.1) | 横だけ追う。高さと奥行きは動かさない |

**縦に動かさない。** `follow` で Y と Z の追従を切ってあります。対象の座標は Body も Aim も
「高さ 0.8・奥行き 5.1 の面へ潰してから」読むので、ビルダーが奥の列へ回っても、駅や岩の上で
カーソルが持ち上がっても、カメラの高さと奥行きは動きません。カメラも注視点も同じ面に残るので
俯角まで据わり、画は横へスクロールするだけになります。

止める前は、対象の Z がそのまま画の縦位置でした。奥の列（z = 8）で作業すると画面下の距離目盛りが
下端から外れて消え、手前の列（z = 0）では逆に目盛りが画面のまん中まで上がって、いちばん奥の地形が
上で切れていました。マップの奥行きは 9 マスしかなく、この構図なら 15 m ぶん（z = -1.7 〜 13.0）が
一度に写るので、そもそも Z を追う必要がありません。

**据え置く奥行き 5.1 は「距離目盛りが下端ぎりぎり」から決めた値です。** 目盛り
（`MapViewComponent` が置く `DistanceMarker_*`）は z = -0.75 から手前へ伸びます。長さは
`x8y12pxDenkiChip` の実寸（ascender 0.9167 / descender -0.0833 / 行送り 1.0 em）と
文字の大きさ 0.45・行間 0.9・2 行から 1.9 em = 0.855 m で、下端が z = -1.605 です。
画に入る手前の端がその 0.14 m 先（z = -1.75）に来る値を選びました。据わりの構図
（引き 0・視野角 32 度）で目盛りの下端が画面の 99%、いちばん引いた状態（引き 2.5・
視野角 35 度）でも 88% に留まります。**据わりが最も詰まった状態なので、ここを 0.2 上げると
目盛りが下端で切れます。** 逆に下げると手前に余白が増え、そのぶん奥の地形が上へ詰まります。
据え置く高さ 0.8 は列車（0.625）とビルダー（1.0）の中点で、止める前の据わりの高さのままです。

**止まると画が四角く、動くと振れる。** カメラ位置（Body の寄り）と注視点（Aim の重み中心）が
同じ点なので、収束状態ではカメラが注視点の真後ろに立ち、ヨーが厳密に 0 になります。俯角は
オフセットの 58.134 度に画面内の位置ぶん 1.971 度を足した 60.105 度で据わります（`_camera.json`
に残る Release カメラのスナップショットとも一致します）。レールを敷く間はマップの格子が
画面の縦横と平行で読みやすいままです。

一方、注視先の減衰（4.0）を位置（3.5）より速くしてあるので、追従中は注視点だけが
先に目標へ着き、カメラは進行方向へ傾きます。ずれ量は `v x (1/3.5 - 1/4.0)` で、
11.5m 先の注視点に対する角度になります。**2 つを同じ値にすると振れは完全に消え、
以前の「ただ固定」に戻ります。** 以前は 4.5 と 10.0 で、この差（0.122 秒ぶん）が
大きすぎてビルダーを 1 マス動かすたびに画が振られていたので、差を 0.036 秒まで詰めました。

**寄せ方がバネなのが要点。** `RailBuilderComponent` はグリッドへスナップするので、
目標は 1 マスぶん飛びます。指数減衰は目標が飛んだ瞬間に速度が最大になるため、
飛ぶたびにそこでカクつきます（長押し中は 0.05 秒ごとなので 20Hz の揺れになります）。
臨界減衰のバネは速度を 0 から立ち上げるので、同じ寄る速さのままカクつきだけが消えます。
行き過ぎもしません。速さの意味は指数減衰と揃えてあるので、値はそのまま比較できます。

**外側を見せない。** マップとレールは `MapViewComponent` / `RailViewComponent` が
カメラ X の前後 `Game.World.RenderDistance`（既定 20 マス）だけを描き、その先で列を
生成します。つまり画にこの範囲より外が入ると、ブロックが湧く瞬間がそのまま見えます。
引く量に上限を入れてあるのはこのためで、上限 2.5m・視野角 35 度なら、いちばん遠い列
（z = mapSizeZ - 1）でも画に入る X の幅は中心から約 15m に収まり、描画の端まで 5m ほど
余ります（Z の追従を止めてカメラが手前へ寄ったぶん、止める前より 1m ほど広がりました）。
**引く量の上限・`fovMaxDegrees`・オフセットのどれかを大きくするときは、
この余りを食い潰していないか確かめてください。** `mapSizeZ` を増やしたときも同じです。
足りなくなったら `Game.World.RenderDistance` を上げるのがいちばん手っ取り早い逃げ道です。

**視野角が速度で開く。** `TrainMovementComponent` の速度は線路の横方向到達距離に応じて段階的に上昇し、
駅到着後だけ一時的に減速する。
その速度域を 32→35 度に割り当ててあります（以前は 32→41 度でしたが、開ききったときに
描画の端が画へ入るため詰めました。上の「外側を見せない」を参照）。
`fovMinDegrees` が据わりの構図そのものなので、寄せ具合を変えるときはここも一緒に
動かしてください。

> **主対象が Train ではなく Monkey なのは回避策です。**
> `CameraRigFeature::UpdateTargetVelocities` は `CollectTargetNames` が集めた名前を
> 重複を潰さずに舐めるので、同じ名前が 2 回目に処理されると
> `velocities_[name] = (position - 更新済みの position) / dt = 0` になります。
> Train は body.targets と aim.targets にも居るため、主対象に指定すると速度が常に 0 になり
> SpeedToFov が最低値に張り付きます。Monkey は Train の子（ローカル原点）で世界座標が
> 一致し、他のどこにも出てこないので、そのまま列車の速度として読めます。
> エンジン側で名前を一意化すれば Train を直接指定できます。

**このリグで作れるのはここまで。** リグは「シーンの状態 → 構図」の関数なので、
出来事（発車・駅到達・突進の開始・ゲームオーバー）に反応する演出は作れません。
揺れ（`CameraShake`）とシーケンス（`CameraSequence`）は `追従 → シーケンス → 揺れ` の順で
正しく上に乗りますが、どちらも呼び出しが要ります。

## GameCamera

`GameComponents::CameraManagerComponent` の通常追従を、そのまま写したものです。
列車とビルダーの中間を捉え、2 人が離れるほど視野角を広げます。

| | 値 | 元コードの対応 |
|---|---|---|
| Body | FrameTargets{ Train, RailBuilder } | `desiredFocusPosition` |
| オフセット | (0, 20, -18) | `cameraOffset_` の既定値 |
| 寄り | (0.4, 0.5, 0.5) | `focusRatio_ = 0.4f`（X だけに効く） |
| Aim | FrameTargets{ Train, RailBuilder } | `LookAt(smoothedFocusPosition_)` |
| Lens | DistanceToFov 5m→35 度 / 30m→70 度 | `minFov/maxFov`, `min/maxTargetDistance` |
| 減衰 | 位置 3.0 / 注視先 3.0 / 視野角 3.0 / **向き 0.0** | `followSpeed_ = 3.0f` |

**寄りが軸ごとなのが要点。** 元コードは Y と Z を常に中点にしたまま、X だけを
`focusRatio` で寄せます。3 軸そろえて 0.4 にすると Y/Z がずれるので合いません。

**向きの減衰が 0 なのも要点。** 元コードは回転を鈍らせておらず、滑らかにした注視点から
毎フレーム `LookAt` しているだけです。位置・注視先・視野角の減衰だけで同じ滑らかさに
なります。ここに値を入れると 1 フレームぶん遅れて一致しなくなります。

検証済み: 対象を動かしながら 300 フレーム突き合わせて、位置 0.00000 m /
視野角 0.00002 度 / 向き 0.00000 度。実機でも 2 つの進行状況で一致を確認しました。

## Train_CloseUp

ゲームオーバー・ゲームクリアで列車へ寄る構図です。`GameManagerComponent::BeginEnding()` が
名前で呼び出します（`blendSeconds = 1.5` / `useUnscaledTime = true`）。寄りの動きは
減衰ではなく繋ぎ（ブレンド）が作るので、リグ側の減衰はすべて 0 です。

オフセット `(0, 5.55, -3.45)` は GamePlay の `(0, 18.5, -11.5)` の 30% で、
俯角 58.1 度をそのままに距離だけ詰めた純粋なドリーインになります。GamePlay の
オフセットを変えたら、ここも同じ倍率で追従させてください。

画面内の位置は (0.5, 0.5)。GamePlay は手前を広く取るため 0.44 ですが、寄りでは
列車を中央に置きます。差は繋ぎの中で吸収されます。
