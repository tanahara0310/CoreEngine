CoreEngine の概要

CoreEngine は DirectX 12 で動く自作のゲームエンジンです。エディタでシーンを組み、ゲームの動きを AngelScript で書いて、そのまま Windows のゲームとして書き出せます。

できること

分野主な機能
エディタドッキングできるパネル、Game ビューでの選択とギズモ、Undo ／ Redo、プレハブ、再生モード（停止で元に戻る）、プロファイラ、ゲームの書き出し
スクリプトAngelScript。クラスがそのままコンポーネントになり、保存すると動かしたまま読み直す。属性でインスペクタの表示を決められる
描画PBR のマテリアル、環境光（IBL）、大気散乱の空、ボリュメトリック雲、高さフォグ、水面、レイトレーシングの影、多数のポストエフェクト
物理球・箱の当たり判定、剛体、キャラクタコントローラ、レイキャスト、レイヤーごとの当たりの組み合わせ
UI文字・画像・ボタン・スライダー・トグル、キーとゲームパッドでのメニュー操作
そのほか入力アクションとキーコンフィグ、サウンド（BGM ／ SE ／ Voice のバス）、パーティクル（CPU ／ GPU）、モデルのアニメーション、Tween、カメラの揺れ、セーブデータ

作りの考え方

ゲームは シーン の集まりで、シーンには GameObject が置かれ、GameObject には コンポーネント（見た目・当たり判定・スクリプトなど）が付きます。エンジンが用意したコンポーネントと、自分で書いたスクリプトのコンポーネントを組み合わせてゲームを作ります。

C++ でエンジンを改造しなくても、ゲームはエディタとスクリプトだけで作れます。用語は 基本の用語 にまとめています。

付属のサンプル

プロジェクト中身
Projects/Sokoban倉庫番。スクリプト 1 本（SokobanBoard.as）とプレハブ 5 つだけで、文字で書いた盤面からステージを組み立てる小さな見本。ステージはインスペクタの stages に 1 行足せば増やせます。
Projects/Sandbox機能ごとの試験場（物理・キャラクターの歩行・UI・水面・カメラの揺れ・スクリプトのシューター）

エンジンのビルドと起動

CoreEngine はソースからビルドして使います。Visual Studio でソリューションを開き、ビルド構成を選んで実行すると、エディタが起動します。

必要なもの

項目内容
OSWindows 10 ／ 11（64 ビット）
IDEVisual Studio 2026（「C++ によるデスクトップ開発」と Windows SDK を入れる）。プラットフォームツールセットは v145
GPUDirectX 12（機能レベル 12.0 以上）。レイトレーシングは対応していれば使う
そのほかPowerShell（ビルドの前処理で使う）、NuGet（WinPixEventRuntime を取得）
あると便利Visual Studio Code（スクリプトを書く）、PIX（GPU の調査）

ビルドして起動する

  1. ソリューションを開くリポジトリの Project/CoreEngine.slnx を Visual Studio で開きます。
  2. NuGet パッケージを復元するソリューションを右クリックして NuGet パッケージの復元。復元しないと「NuGet package restore required」でビルドが止まります。
  3. 構成を選ぶツールバーで Debug か Development、プラットフォームは x64 を選びます（エディタが入っているのはこの 2 つです）。
  4. 実行するF5（またはデバッグなしで Ctrl+F5）。起動するとプロジェクトを選ぶ画面が出ます。

実行ファイルは generated/CoreEngine/outputs/<構成>/CoreEngine.exe にできます。初めての起動ではシェーダのコンパイルに時間がかかります（2 回目からはキャッシュを使います）。

ゲームを作るだけなら Development が向いています。Debug は GPU の検証が入るぶん重くなります。

最初のプロジェクトを作る

エディタを起動すると、プロジェクトを選ぶ画面（「CoreEngine — プロジェクトを開く」）が出ます。ここでテンプレートから新しいプロジェクトを作り、開いて動かしてみます。

プロジェクトを作る

  1. 新規作成を開く左の 新規作成（または一覧の ＋ 新規作成）を押します。
  2. テンプレートを選ぶ3D の基本 を選びます。WASD・矢印キー・左スティックで動く箱が入っていて、スクリプトの書き方の見本になります。
  3. 名前と保存先を決める名前 はそのままフォルダ名になるので、英数字と _ - だけにします。保存先 の既定はリポジトリの Projects フォルダです。日本語などを含むパスは避けてください。
  4. 作成して開く下の 作られるフォルダ で中身を確かめ、作成して開く を押すと、エディタがそのプロジェクトで起動します。
テンプレート中身
空のプロジェクト太陽（Sun）・カメラ（MainCamera）・床だけの Main シーン。スクリプトなし
3D の基本上に加えて、オレンジの箱（Player）と、それを動かすスクリプト PlayerMover

動かしてみる

  1. 再生するツールバーの ▶ か Ctrl+P。
  2. 操作するGame ビューをクリックしてから、WASD か矢印キー（パッドなら左スティック）で箱が動きます。
  3. 止めるもう一度 Ctrl+P。箱は再生前の位置に戻ります。

箱を動かしているのは、Application/Assets/Scripts/PlayerMover.as のこのスクリプトです。

Hierarchy で Player を選ぶと、Inspector に プレイヤーの移動 があり、速さ を変えられます。スクリプトの書き方は 最初のスクリプトを書く で順に説明します。

プロジェクトを開く・切り替える

  • 選ぶ画面の プロジェクト に、リポジトリの Projects の下のプロジェクトと、最近開いたプロジェクトが並びます。ダブルクリックか 開く で開きます。
  • ほかの場所のプロジェクトは 追加… でフォルダを選んで一覧に足します（Application/Config/EngineSettings/Project.json があるフォルダがプロジェクトです）。
  • 左下の 次から前回のプロジェクトを自動で開く を入れると、次からこの画面を飛ばします（戻すには --launcher を付けて起動）。
  • エディタの中からは File▸プロジェクトを開く… ／ 新しいプロジェクト… ／ 最近のプロジェクト で切り替えます（エディタが起動し直します）。

プロジェクトのフォルダ構成

プロジェクトは 1 つのフォルダです。どこに何を置くかと、git にコミットするものをまとめます。

フォルダの中身

★ の付いたフォルダはエンジンが決めた場所です。それ以外（Models・Textures・Sounds など）は自由に名前を付けて整理できます。

設定ファイル（Application/Config/EngineSettings）

ファイル中身編集する場所
Project.jsonプロジェクト名・起動シーン（initialScene）・ローディング画面（splashImage など）。このファイルがあるフォルダがプロジェクトProject Settings ▸ Startup
Layers.json当たり判定のレイヤーの名前Project Settings ▸ Collision Layers
InputActions.json入力アクションと既定のキーテキストエディタ
CVars.json既定から変えたエンジンの設定（描画・物理など）Project Settings（自動保存）

新しく作ったプロジェクトには Project.json しかありません。ほかのファイルが無い間は、エンジンの既定（レイヤーは Default だけ、入力アクションは既定の 15 個）が使われます。

Saved と Intermediate

場所中身
Saved/EditorSettings/エディタの配置・エディタ視点・最後に開いたシーンなど
Saved/keybindings.jsonKey Config で変えたキーの割り当て
Saved/<SaveFile のパス>スクリプトの SaveFile が書くセーブデータ
Saved/Thumbnail.pngプロジェクト一覧の縮小画像（エディタを閉じるときに撮る）
Intermediate/Logs/ログのファイル（種類ごと。スクリプトのログは Script/）
Intermediate/TextureCache/テクスチャを変換したキャッシュ（消しても作り直される）

git にコミットするもの

  • コミットする：Application/Assets（.meta・ScriptComponent.as・as.predefined を含む）、Application/Config、.code-workspace、.gitignore
  • コミットしない：Application/Saved・Intermediate・Build（プロジェクトの .gitignore で外れています）

.meta ファイルには、アセットを見分ける GUID が入っています。消したりコミットし忘れたりすると、シーンやプレハブからの参照が切れることがあります。

基本の用語

CoreEngine でゲームを作るときに出てくる言葉と、座標や単位の決まりです。

用語

用語意味
シーンゲームの 1 画面（タイトル・ステージなど）。Assets/Scenes/<名前>/ のフォルダ。詳しく
GameObject（オブジェクト）シーンに置かれるもの。それ自体は名前と有効・無効だけを持ち、働きはコンポーネントが担う
コンポーネントオブジェクトに付ける部品。エンジンのもの（MeshRenderer・Collider など）とスクリプトのものがある。一覧
Transform位置・回転・拡大と親子関係を持つコンポーネント。3D のオブジェクトにはたいてい付いている
スクリプトAngelScript で書いたクラス。ScriptComponent を継ぐとコンポーネントになる
プレハブオブジェクトの雛形（.prefab）。エディタで置いたり、スクリプトで生成したりする。詳しく
アセットプロジェクトのファイル（モデル・テクスチャ・音・プレハブなど）。.meta の GUID で見分ける
再生モードエディタの中でゲームを動かす状態。停止するとシーンが再生前に戻る。詳しく
レイヤー当たり判定のグループ。どのレイヤー同士が当たるかをシーンごとに決める
入力アクション「ジャンプ」のような操作の名前。キーやボタンの割り当ては設定で変えられる
CVar名前の付いたエンジンの設定値（sys.Physics.Gravity など）

座標と単位

項目決まり
軸X が右、Y が上、Z が奥（左手系）。エディタでも X・Y・Z は赤・緑・青
長さメートル（重力は 9.81 m/s²）
回転スクリプトと保存データはラジアン。インスペクタは度で表示
回転の成分x がピッチ（上下を向く）、y がヨー（左右を向く）、z がロール（傾く）
色Vector4 の x・y・z・w が R・G・B・不透明度（0〜1）
時間秒
UIピクセル。アンカーからの位置で置く

度とラジアンの変換：ラジアン = 度 × 3.1415927 ÷ 180（90 度は約 1.5708、180 度は約 3.1416）。

エディタの画面構成

エディタは 1 つのウィンドウの中に、ドッキングされたパネルが並ぶ作りです。最初に各パネルの役割と置き場所を覚えておくと、以降の説明が追いやすくなります。

プレハブ

プレハブは、コンポーネントと値の組み合わせを持ったオブジェクトの雛形です。弾や敵のように何度も出すものをプレハブにしておき、エディタで置いたり、スクリプトの InstantiatePrefab で出したりします。

プレハブを作る

  1. オブジェクトを組むシーンでオブジェクトを作り、コンポーネントと値を整えます。
  2. 保存するHierarchy でそのオブジェクトの行を右クリックし、プレハブとして保存 を選びます。
  3. できたファイルを確かめるApplication/Assets/Prefabs/<オブジェクト名>.prefab ができ、元のオブジェクトはそのプレハブに繋がります（Hierarchy に ◈ と Prefab が付きます）。

同じ名前があれば _1・_2 … が付きます。作った後は Project で好きなフォルダへ移してかまいません（見本の倉庫番は Prefabs/ の直下に置いています）。

プレハブを置く・出す

  • エディタで置く：Project の .prefab を Game ビューへドラッグします。
  • スクリプトで出す：owner.InstantiatePrefab("Application/Assets/Prefabs/Bullet.prefab", "Bullet")。詳しく
  • スクリプトの欄で選ばせる：[Asset("Prefab")] string bulletPrefab; と書くと、インスペクタでプレハブを選べます。

プレハブを直す

プレハブは、プレハブモードで開いて直す・Project で選んで Inspector で直す・置いたオブジェクトを直してからプレハブへ書き戻すのどれかで直します。

プレハブモードで開いて直す

プレハブだけを表示して、部品の追加やコライダーの形も含めて直すモードです。

  • 開く：Project でプレハブをダブルクリックするか、プレハブを選んで Inspector の ◈ プレハブモードで開く。シーンに置いたものなら、Hierarchy の行を右クリック プレハブを開く。
  • 見分け方：Hierarchy の上に青い帯、Game ビューの外周に青い枠と PREFAB の札、上のバーに青い ◈ プレハブモード が出ます。シーンのほかのオブジェクトは表示されず、選べません。
  • 保存：直した値は、ドラッグを離した・入力欄を離れたたびにプレハブへ保存し、シーンに置いた同じプレハブのオブジェクトにも反映します（自動保存）。
  • 戻る：Hierarchy の帯か上のバーの ◀ シーンへ戻る。カメラも開く前の視点に戻ります。▶ で再生したときも、シーンへ戻ってから再生します。
  • Undo：開いている間の Ctrl+Z は、プレハブモードの中の操作を戻します。戻った後は、開いてから戻るまでの変更が ○○.prefab を編集 の 1 件になります。
  • プレハブモードの間は、シーンにオブジェクトを足す・複製する・消す操作と、シーンの保存はできません。

Project で選んで直す

Project でプレハブ（.prefab）を選ぶと、Inspector の プレハブの中身 にコンポーネントと値が出ます。値を変えると、ドラッグを離した・入力欄を離れたときにプレハブのファイルへ保存し、シーンでそのプレハブから置いたオブジェクトにもすぐ反映します（それぞれが上書きした値は保たれます）。

  • Ctrl+Z で、プレハブを編集する前の中身に戻せます。
  • コンポーネントの ⋮ から 既定値へ戻す・外す が使えます。
  • 部品を足す・コライダーの形のように専用の欄で直す部品は、プレハブモードで直してください。
  • シーンの別のオブジェクトを指す欄（[ObjectRef]）は、プレハブには保存されません。

プレハブと値が違う項目は、インスペクタの左の余白に青い縦線が出ます。適用すると、同じシーンのほかのインスタンスも新しい値にそろいます（それぞれが上書きした値は保たれます）。

シーンの作成と保存

シーンはゲームの 1 画面（タイトル・ステージ・リザルトなど）です。Application/Assets/Scenes/<シーン名>/ のフォルダに、オブジェクトごとの JSON として保存されます。

新しいシーンを作る

  1. メニューを開くFile▸新しいシーン… を選びます。
  2. 名前と中身を決める名前を入れ、空 か 基本（太陽と床）（既定）を選んで 作成。基本を選ぶと、Sun（ライト）・MainCamera・床が入ります。

名前に \ / : * ? " < > | と、先頭の _ は使えません。シーンの名前は Scene::ChangeScene("名前") でそのまま使うので、英数字にしておくと扱いやすくなります。

保存する

  • Ctrl+S（File▸シーンを保存）で保存します。画面の上に「シーンを保存しました」と出ます。
  • シーンを開く・新しく作る・プロジェクトを切り替えるときは、未保存の変更があれば 保存して続ける ／ 保存せずに続ける ／ やめる を聞かれます。
  • エディタを閉じるときは確認されず、自動保存もありません。
  • ほかの人の変更（git の pull など）とぶつかりそうなときは ほかの人の変更とぶつかります の窓が出ます。外でファイルが変わったときは自動で読み直すか、どうするかを聞かれます（チームで作る）。

起動するシーン

  • エディタは前回開いていたシーンから始まります。
  • 書き出したゲームは、Project Settings の Startup で決めた 起動シーン から始まります（Project.json の initialScene）。

元に戻す（Undo）

Ctrl+Z ／ Ctrl+Y で、エディタの操作を最大 128 回まで戻せます。戻せる主な操作：ギズモでの移動、オブジェクトの作成・複製・削除、コンポーネントの追加・削除、インスペクタの値の変更、プレハブの操作、CVar の変更。シーンを切り替えると履歴は消えます。

ゲームを書き出す

完成したゲームを、エディタの無い PC でも遊べるフォルダにまとめます。できたフォルダを丸ごと渡せば、そのまま遊べます。

書き出す手順

  1. シーンを保存する書き出すのはディスクにあるファイルです。保存していない変更は入りません（Ctrl+S）。
  2. Release をビルドするVisual Studio で構成を Release にしてビルドします。エディタからはビルドしません。generated/CoreEngine/outputs/Release/CoreEngine.exe ができていれば準備完了です。
  3. 書き出すエディタで File▸ゲームを書き出す… を開きます。書き出す先・使う Release の exe（ビルドした日時）・写すものを確かめて、書き出す を押します。画像のテクスチャを DDS に変換してから写します（テクスチャの変換）。
  4. 遊んで確かめるエクスプローラーで開く で書き出したフォルダを開き、CoreEngine.exe を起動します。

Release の exe が無いと、窓に「先に Release でビルドしてください」と出て書き出せません。書き出したゲームを動かしたままだとファイルを書き換えられないので、閉じてから書き出します。

書き出されるもの

書き出すたびに、Engine/Assets・Engine/Cooked・Application/Assets・Application/Cooked・Application/Config をいったん消してから書き直します。遊んだ人のデータが入る Application/Saved は残します。Build/ は git の対象外です。

テクスチャの変換

画像のテクスチャ（PNG・JPG・JPEG・BMP・TGA）は写さずに、GPU がそのまま読める圧縮形式（BC3 の DDS）へ変換して Cooked/ に書きます。遊ぶ人の PC では変換しないので、初めての起動でもテクスチャの変換を待ちません。元の画像は入りませんが、隣の .meta は入るので、スクリプトやシーンからは今までどおり .png などの名前で使えます。ただしローディング画面の写真（起動中のローディング画面）だけは、DirectX 12 の準備より前に読むので、元の画像のまま写します。

元の画像変換した DDS

Application/Assets/Models/Rock/Rock_Normal.pngApplication/Cooked/Models/Rock/Rock_Normal.png.linear.dds（リニア）

モデルのマテリアルで法線・メタリック/ラフネス・遮蔽に使う画像はリニア、それ以外の画像は sRGB で変換します。エディタで開いたときに作った DDS（Intermediate/TextureCache）が元の画像より新しければ、変換せずにそれを使います。初めて書き出すときや画像を描き直したあとは、変換のぶん時間がかかります。

シェーダのコンパイル

シェーダも書き出すときにコンパイルして、GPU に渡す形（DXIL）で Cooked/ に書きます。遊ぶ人の PC ではコンパイルしないので、初めての起動でもシェーダのコンパイルを待ちません。例えば Engine/Assets/Shaders/Water/Water.PS.hlsl を ps_6_0 でコンパイルしたものは Engine/Cooked/Shaders/Water/Water.PS.hlsl.ps_6_0.dxil です。出力からデバッグ情報は外します（GPU が使う中身は開発中と同じです）。

コンパイルするのは、エディタやゲームで一度でもコンパイルしたシェーダです。エンジンは使ったシェーダを Intermediate/ShaderManifest.txt に起動と終了のたびに書き足していきます。一度も動かしていない場面のシェーダは書き出しに入らず、そのシェーダだけ遊ぶ人の PC でコンパイルされます。書き出す前に、エディタで最初のシーンから最後まで通して遊んでおくと漏れません。元の .hlsl も写すので、入っていないシェーダがあってもゲームは動きます。

スクリプトの仕組み

ゲームの動きは AngelScript（C++ に近い文法の、型のあるスクリプト言語）で書きます。ScriptComponent を継いだクラスはそのままコンポーネントになり、エディタでオブジェクトに付けて使います。C++ やエンジンのビルドは要りません。

書いてから動くまで

.as を書くApplication/Assets/Scripts の下
→
保存するエディタが変更を見つけて自動でコンパイル
→
コンポーネントになるComponent メニューと ＋ コンポーネント追加 に並ぶ
→
付けて再生インスペクタで値を調整し、▶ で動かす

エディタを動かしたまま .as を保存すると、その場で読み直します（ホットリロード）。再生中でも止めずに差し替わり、インスペクタの値は引き継がれます。

スクリプトの置き場所

  • スクリプトは Application/Assets/Scripts/ の下に置きます。フォルダを分けて整理してかまいません（例：Scripts/Enemy/EnemyMover.as）。
  • 拡張子は .as、文字コードは UTF-8 です（日本語のコメントや文字列も使えます）。
  • Scripts/Editor/（Scripts の直下の Editor フォルダ）は、エディタの無いビルド（Release・書き出したゲーム）では読み込まれず、書き出しにも入りません。エディタでだけ使う道具（エディタを拡張する）を置きます。

すべてのファイルが 1 つにまとまる

Scripts の下の .as はすべてまとめて 1 つにコンパイルされます。ほかのファイルのクラス・関数・グローバル変数・enum を、#include なしでそのまま使えます（#include を書いても無視されます）。

コンポーネントのクラスの決まり

決まり守らないと
ScriptComponent を継ぐ（class Foo : ScriptComponent）ふつうのクラスとして扱われ、コンポーネントにはなりません（データの入れ物などには自由に使えます）
1 つのファイルに 1 つのクラス、ファイル名 = クラス名（Foo.as に class Foo）動きますが、Console に警告が出ます
クラス名はスクリプト全体で 1 つだけ（フォルダや名前空間が違っても）コンパイルエラー、またはそのクラスが使えなくなります
エンジンの型と同じ名前にしない（Camera・Light・Rigidbody・Transform・GameObject など）「エンジンの型と同じ名前なので使えません」というエラー
abstract を付けたクラスはコンポーネントにならない—（共通の処理をまとめた基底クラスに使えます）

クラス名は PlayerMover・EnemySpawner のように役割がわかる名前にし、エンジンの型と重ならないようにゲーム名などを頭に付けるのもおすすめです（見本の倉庫番は SokobanBoard のように Sokoban を頭に付けています）。

エディタが書き出すファイル

エディタは起動のたびに、Scripts フォルダへ次の 3 つを書き出します。どちらも手で書き換えないでください（次の起動で元に戻ります）。git にはコミットしておきます。

VS Code の準備

スクリプトは Visual Studio Code で書くのがおすすめです。プロジェクトには VS Code のワークスペースが入っていて、拡張機能を 1 つ入れるだけで、エンジンの API の補完とエラーの表示が効きます。

準備の手順

  1. VS Code を入れるcode.visualstudio.com から入れます。エディタの スクリプトを開く や Console のリンクは、VS Code が入っているとそのまま VS Code で開きます。
  2. エディタでプロジェクトを 1 回開くこのときエディタが Scripts フォルダへ as.predefined（API の宣言）と ScriptComponent.as を書き出します。
  3. ワークスペースを開くプロジェクトのフォルダにある <プロジェクト名>.code-workspace をダブルクリックするか、VS Code の File▸Open Workspace from File… で開きます。左に Scripts フォルダが出ます。
  4. 拡張機能を入れる右下に出るおすすめの通知から AngelScript Language Server（sashi0034.angel-lsp）を入れます。通知が出なければ、拡張機能の検索で angel-lsp を探します。

これで、owner. と打つとメンバーの候補が出て、間違いには波線が付くようになります。

ワークスペースの中身

angelScript.implicitMutualInclusion は、すべてのファイルがお互いを見られる設定です。エンジンがすべての .as を 1 つにまとめてコンパイルするのと同じ見え方になります。

エディタから開く

  • Inspector のスクリプトのセクションにある ◇ スクリプトを開く（見出しの ⋮ メニューにもあります）
  • Console のエラーの 発生元 のリンク（その行と桁へ飛びます）
  • スクリプトを作るときの 作ったら VS Code で開く

イベント関数とライフサイクル

スクリプトのクラスに決まった名前の関数を書くと、エンジンが決まったタイミングで呼びます。どの関数がいつ呼ばれるかを知っておくと、処理をどこに書けばよいかが決まります。

イベント関数の一覧

void LateUpdate()毎フレーム、全オブジェクトの Update の後いいえ
void OnTriggerEnter(Collision@ other) など当たり判定の結果が出たとき（LateUpdate の後）。詳しくいいえ

基底クラスに空の関数があるので、必要な関数だけ書けば十分です。書いていない関数は呼び出し自体が省かれます。

1 フレームの流れ

再生中の 1 フレームは、おおよそ次の順に進みます。

  1. フレームの始めカメラ・ライトの準備
  2. Tween を進めるTween が書き換えた値は、この後の Update から見えます。
  3. 更新Start → Update（オブジェクトごと）初めて更新されるコンポーネントは、Update の直前に Start が呼ばれます。
  4. 行列の反映Update で書き換えた位置・回転が描画と当たり判定に反映されます。
  5. LateUpdate（オブジェクトごと）
  6. Update 中に生成したオブジェクトを加える
  7. 物理と当たり判定FixedUpdate → 物理のステップ（固定ステップの回数だけ繰り返す）
  8. OnCollision* ／ OnTrigger*当たり判定の結果をまとめて通知します。
  9. 仕上げカメラの追従・シェイク → 描画
  10. フレームの終わりDestroy したオブジェクトを取り除く。エディタではスクリプトの読み直しもここで行う。

Awake と Start の使い分け

AwakeStart
呼ばれる時付いた直後（シーンの読み込み中）最初の Update の直前（再生中）
編集中呼ばれる呼ばれない
ほかのオブジェクトまだそろっていないことがあるシーンのオブジェクトはそろっている
向いている処理自分の中だけで完結する準備（フォントの登録など）ほかのオブジェクトを探して控える、ゲームの初期化、音を鳴らす

Awake はシーンを開いただけで（再生しなくても）呼ばれます。ここでオブジェクトを作ったり動かしたりすると、編集中のシーンが書き換わってしまいます。ゲームの処理は Start に書いてください。

知っておきたい決まり

  • 生成したオブジェクト：Update の中で InstantiatePrefab したオブジェクトは、そのフレームの Update・LateUpdate は呼ばれず、次のフレームに Start → Update が呼ばれます。位置などの設定は、生成した直後に呼び出し側から行います。
  • 無効なもの：オブジェクトが無効（active = false）の間は何も呼ばれません。コンポーネントの有効のチェックを外すと Update・LateUpdate・FixedUpdate・当たり判定の通知が止まります。
  • オブジェクトの順番：同じ段階の中でのオブジェクトの順番（どちらの Update が先か）に頼らないでください。先に決まっていてほしい値は Update で書き、LateUpdate で読みます。
  • 例外が起きたら：イベント関数の中で例外（null のハンドルへのアクセスなど）が起きると、Console に場所が出て、そのコンポーネントは無効になります。直して保存すれば、読み直しの後に動きます。
  • 破棄：Destroy() を呼ぶと OnDestroy が呼ばれ、実体はフレームの終わりに取り除かれます。

自分のオブジェクト（owner）

スクリプトを取り出して呼ぶ

見つけたオブジェクトに付いているスクリプトは GetComponent で取り出します。受け取る変数を @ を付けて渡すのがポイントです。取り出したら、そのクラスの公開メソッドや公開メンバ変数を直接使えます。

エンジンのコンポーネントを使う

エンジンのコンポーネントは、型名の先頭を小文字にしたプロパティで取れます（owner.meshRenderer・owner.rigidbody・owner.audioSource など）。インスペクタに出ている値は、同じ名前のプロパティで読み書きできます。

これらのプロパティは、コンポーネントが付いていなくても null ではなくハンドルを返します。付いているかは exists で確かめます。付いていないのに値を触ると、Console に 1 回だけ警告が出て、何も起きません。各コンポーネントで使える値は コンポーネント リファレンス を見てください。

ハンドルと null

  • GameObject@ のように @ が付いた型はハンドル（参照）です。何も指していないと null です。
  • null かどうかは x is null ／ x !is null で調べます（== null ではありません）。
  • ハンドルの変数に別のハンドルを入れるときは @x = y; と書きます。
  • 破棄されたオブジェクトを指すハンドルも null にはなりません。まだ使えるかは isAlive で確かめます。

詳しくは ハンドル（@）と参照 を見てください。

親子関係

子の position は親から見た位置です。ワールドでの位置は worldPosition で読めます（書き換えた直後に読むときは、先に UpdateMatrix() を呼びます）。

生成と破棄（プレハブ）

弾や敵のように、ゲームの途中で出したり消したりするものは、プレハブにしておいてスクリプトから生成します。

プレハブから生成する

  1. プレハブを作る弾のオブジェクトを組み、Hierarchy の右クリック プレハブとして保存。詳しく
  2. スクリプトに欄を作る[Asset("Prefab")] string bulletPrefab; を書き、インスペクタでそのプレハブを選びます。
  3. 生成するowner.InstantiatePrefab(bulletPrefab, "Bullet") で作り、返ってきたオブジェクトの位置を決めます。
  • パスはプロジェクトの根からの相対パスです（"Application/Assets/Prefabs/Bullet.prefab"）。
  • 生成したオブジェクトの Start と Update は次のフレームから呼ばれます。位置や初期値は、生成した側がすぐに入れます。
  • 2 つ目の引数はオブジェクトの名前です。FindObject で探すときに使います。
  • 生成したオブジェクトはシーンには保存されません（再生を止めると消えます）。

破棄する

owner.Destroy() で自分を、other.gameObject.Destroy() で相手を破棄できます。破棄は予約で、OnDestroy が呼ばれた後、フレームの終わりに取り除かれます。

  • 予約した後は isAlive が false になります。
  • 当たり判定の通知が同じフレームに何度も来ることがあります。上の Vanish() のように、1 回だけ消す印を持っておくと安全です。
  • 一時的に隠すだけなら、破棄せずに owner.active = false にします（true に戻せば再び動きます）。

Tween の基本

Tween は、値を時間をかけて変えていく仕組みです。作った時点で動き始め、最後まで勝手に進みます。

設定はつなげて書けます。

好きな値を動かす（Tween::To）

色や UI の位置など、MoveTo などで動かせない値は Tween::To で動かします。毎フレーム呼ばれる関数を渡し、その中で値を当てはめます。

  • 自分のメソッドを渡すときは TweenFloatSetter(this.SetAlpha) のように、関数の型の名前で包みます（デリゲート）。
  • Vector2・Vector3・Vector4 版もあります（TweenVector2Setter などで包む）。

自分のメソッドを渡す Tween（To・Delay・OnComplete など）には .SetLink(owner) を付けます。オブジェクトが破棄されたときに Tween も自動で止まり、消えたオブジェクトのメソッドが呼ばれるのを防げます。

順番に流す（シーケンス）

Append は前が終わってから、Join は直前と同時に動きます。イージングの種類は EaseType を見てください。

スクリプトを保存し直したとき

エディタでスクリプトを保存し直すと、それまでに Tween へ渡した関数は呼ばれなくなります（位置を動かす MoveTo などは続きます）。動き続けてほしい演出は OnScriptReloaded() で作り直します。

シーン遷移とデータの保存

タイトル → ゲーム → リザルトのようにシーンを移る方法と、シーンをまたいで値を渡す方法、ハイスコアのようにファイルへ保存する方法です。

シーンを切り替える

  • 名前は Application/Assets/Scenes の下のフォルダ名です。
  • 切り替えは次のフレームに行われ、短い読み込みの演出が入ります。
  • 今のシーンのオブジェクトはすべて破棄されます（OnDestroy が呼ばれます）。
  • 時間の速さ（Time::SetTimeScale）はシーンを移っても残ります。

次のシーンへ値を渡す（Session）

Session はシーンを切り替えても消えない値の置き場です。アプリを閉じると消えます。

ファイルに保存する（SaveFile）

SaveFile は Application/Saved/ の下に JSON で保存します。ハイスコアや設定など、アプリを閉じても残したい値に使います。

デバッグとホットリロード

うまく動かないときの調べ方と、保存したスクリプトがその場で差し替わる仕組み（ホットリロード）の決まりです。

ログを出す

Console のカテゴリを Script にすると、スクリプトのログだけを見られます。ログはファイル（Intermediate/Logs/Script/）にも残ります。

毎フレーム Log すると Console が埋まります。値を眺めたいだけなら、公開メンバ変数に [ReadOnly] を付けてインスペクタで見るほうが楽です。

コンパイルエラー

  • 保存するとコンパイルされ、エラーは Console に ファイル(行, 桁) : メッセージ で出ます。発生元 のリンクで VS Code のその行が開きます。
  • 成功から失敗に変わると Console が自動で前に出て、ツールバーは Script ✕ コンパイル失敗 になります。
  • 失敗している間も、ゲームは前のスクリプトのまま動き続けます。壊れたファイルだけが直す前の版に戻り、ほかのファイルの変更は反映されます（Console に「○○.as は直す前の版のまま動いています」と出ます）。
  • 警告もエラーになります。よくあるものは 警告もエラーになる を見てください。

実行中のエラー（例外）

null のハンドルを使った、配列の範囲外を読んだ、0 で割った、などで例外が起きると、Console に場所と呼び出しの履歴が出て、そのコンポーネントは無効になります。インスペクタで有効のチェックが外れているのが目印です。

多くは null の確かめ忘れです。ハンドルを使う前に if (x is null) return; を入れます。起きうる失敗を自分で扱うときは try ／ catch も使えます。

無限ループ

エディタのあるビルドでは、1 回の呼び出し（1 回の Update など）で 200,000 行を超えて実行すると中断し、そのコンポーネントを無効にします（エディタが固まらないように）。while の終わる条件を見直してください。エディタの道具（エディタを拡張する）の上限は 20,000,000 行です。

設計のコツと注意点

スクリプトを書くときに気をつけたいことを、サンプルのゲームで使っている書き方と合わせてまとめます。

構成

  • 1 つのクラスに 1 つの役割：自機・敵・弾・進行役・演出のように分け、進行役（Director）が全体の状態を持つ形にすると見通しがよくなります。
  • 進行役は名前で見つけられるようにする：「GameDirector」のような名前のオブジェクトに置き、ほかのスクリプトは Start で FindObject と GetComponent で取り出して控えます。
  • シーンに置く相手は [ObjectRef]、プレハブは [Asset("Prefab")] で指定し、パスや名前をコードに直接書かないようにします。
  • 状態は enum で：カウントダウン・プレイ中・終了のような状態は、スクリプトの enum と if ／ switch で分けます。

当たり判定と物理

ぶつかったことを知る（当たり判定）、重力や力で動かす（剛体）、歩くキャラクターを動かす（キャラクタコントローラ）、光線や範囲で相手を探す（レイキャスト）の 4 つを説明します。

動かし方を選ぶ

当たり判定のあるオブジェクトの動かし方は 3 通りあります。作りたいものに合わせて選びます。

動かし方付けるもの向いているもの動かすコード
位置を直接書くコライダー弾・コイン・シューティングの自機と敵など、当たったことが分かればよいものowner.transform.position = …
キャラクタコントローラコライダー（カプセル・トリガーを外す）＋ キャラクタコントローラ歩いて跳ぶプレイヤー。坂や段差を上り、壁に沿って滑るcontroller.SimpleMove(速度)
剛体コライダー（トリガーを外す）＋ 剛体転がる玉・崩れる箱・吹き飛ぶ物。重力と跳ね返りで動くものbody.AddForce(力)

迷ったら「位置を直接書く ＋ コライダー」から始めます。

当たり判定を付ける

当たり判定は、両方のオブジェクトにコライダーが付いていて、2 つのレイヤーの組み合わせが「当たる」になっているときに起きます。

  1. コライダーを付けるInspector の ＋ コンポーネント追加 から コライダー を選びます。
  2. 形を足す付けただけでは形がありません。コライダーの欄の 球を追加 か 箱を追加 を押します。足した形は、トリガーがオン・レイヤー Default です。
  3. 形を合わせる形状（Sphere・Box・Capsule）と大きさ、オフセット を見た目に合わせます。ツールバーの ◍ Collider を押すと、形が線で表示されます。
  4. 知らせを受けるメソッドを書くスクリプトに OnTriggerEnter などを書きます（下の表）。

トリガーと押し出し

コライダーの トリガー で、重なったときの振る舞いと、呼ばれるメソッドが変わります。

2 つのコライダー起きること呼ばれるメソッド
どちらかがトリガー重なったことを知らせるだけ（すり抜ける）OnTriggerEnter・OnTriggerStay・OnTriggerExit
両方ともトリガーでないめり込まないように押し出す（静止 の側は動かない）OnCollisionEnter・OnCollisionStay・OnCollisionExit
両方とも 静止判定しない（床と壁どうしなど）なし

知らせはぶつかった両方のオブジェクトのスクリプトに届きます。1 フレームの中では LateUpdate の後に呼ばれます（ライフサイクル）。名前か引数の型が上の形と違うと呼ばれません。名前の打ち間違いはエラーにもならないので注意してください。

相手を見分ける

引数の Collision から、相手のオブジェクト（gameObject）とレイヤー（layer）が分かります。相手が持っているスクリプトを GetComponent で取り出せたら、それが目当ての相手です。

レイヤーで見分けるときは if (other.layer == CollisionLayer::Enemy) のように書きます。レイヤーの名前はプロジェクトごとに違います（次の節）。

Collision のプロパティ中身

layer ／ selfLayer相手 ／ 自分のコライダーのレイヤー

レイヤーで当たる相手を絞る

レイヤーはコライダーのグループです。「自機の弾は敵にだけ当たる」のように、当たる組み合わせをシーンごとに決めます。

  1. レイヤーを足すEdit▸Project Settings… の Collision Layers で名前を足して 適用 します。スクリプトの CollisionLayer::名前 は、エディタを起動し直すと使えるようになります。
  2. コライダーのレイヤーを選ぶ各オブジェクトのコライダーの レイヤー を選びます。
  3. 当たる組み合わせにチェックを入れるScene Settings の 当たり判定のレイヤー の表でチェックを入れ、Ctrl+S でシーンを保存します。

シーンに保存された組み合わせの表が、そのシーンの当たりのすべてを決めます。テンプレートのシーンに入っているのは Default × Default だけです。エンジンが置く床（DefaultGround）も Default なので、プレイヤーを Player レイヤーにしたら、Player × Default にもチェックを入れないと床をすり抜けます。

たとえばシューティングなら、次の 3 つだけを当てれば足ります。弾どうし・敵どうしは判定しないので、スクリプトで相手を見分ける手間も減ります。

ゲームの途中で組み合わせを変えるときは Physics::SetLayerCollision を使います（シーンのファイルは書き換えません）。

剛体で動かす

剛体（Rigidbody）を付けると、重力で落ち、ほかの物とぶつかって跳ね返ります。

  1. コライダーのトリガーを外すトリガーのままだと、床をすり抜けて落ち続けます。
  2. 剛体を付ける＋ コンポーネント追加 ▸ 剛体。質量（kg）や 重力を受ける を決めます。
  3. 跳ね返りと摩擦を決める必要なら 物理マテリアル を足して、反発係数 と 摩擦係数 を変えます。
やりたいこと書き方
押し続ける（エンジン・風）body.AddForce(力) を FixedUpdate で
一瞬で弾く（ジャンプ・爆風）body.AddImpulse(撃力)
速さを直接決めるbody.velocity = Vector3(…)
回すbody.AddTorque(…) か body.angularVelocity
転ばないようにする回転を止める（freezeRotation）をオン

剛体の付いたオブジェクトは、再生を始めると向きを物理が持つ形に切り替えます。その後は transform.rotation を書き換えても向きは変わりません。回すときは angularVelocity や AddTorque を使います。

物理は決まった間隔（既定 1/60 秒、CVar sys.Physics.FixedStep）で進みます。重力の強さは Physics::gravity で変えられますが、プロジェクトの設定を書き換えるので、再生を止めても元に戻りません（Physics）。

キャラクタコントローラで歩かせる

プレイヤーのように歩いて跳ぶキャラクターには、キャラクタコントローラを使います。坂を上り、小さな段差を越え、壁に沿って滑り、押されて倒れることはありません。

  1. コライダーをカプセルにするコライダーに形を足し、形状 を Capsule にして、トリガー を外します。
  2. キャラクタコントローラを付ける＋ コンポーネント追加 ▸ キャラクタコントローラ。登れる坂（度）や 越えられる段差（m）を決めます。
  3. スクリプトから毎フレーム動かすコントローラは自分では動きません。SimpleMove を毎フレーム呼ばないと、重力も効きません。

地面に立っているかは controller.grounded で分かります。落下の速さを消したいとき（リスポーンなど）は controller.velocity = Vector3(); とします。

光線と範囲で相手を探す

「銃の先に何があるか」「爆発の範囲に誰がいるか」は、レイキャストと重なりの検索で調べます。

レイヤーを複数まとめるときは Physics::LayerMask(CollisionLayer::Enemy) | Physics::LayerMask(CollisionLayer::Boss) のように | でつなぎます。省略（-1）するとすべてのレイヤーが対象です。光線の出発点が自分のコライダーの中にあると、自分に当たることがあります。そのときは出発点を少し前にずらすか、レイヤーで自分を外します。

UI を作る

スコアや体力ゲージのような HUD、タイトル画面やポーズメニューのボタンを作ります。UI は 3D の世界とは別の、画面に重ねる平面に置きます。

UI の画面の決まり

UI の画面は 1920×1080 固定です。ウィンドウの大きさが違っても、拡大・縮小して合わせます。座標は左上が (0, 0)、右が +X、下が +Y のピクセル単位です。

UI の要素の置き場所は、UI トランスフォーム の 3 つの値で決まります。

項目意味例：右上にスコアを置く
アンカー画面のどこから測るか右上
基準点（pivot）自分のどこをその点に合わせるか。(0, 0) が自分の左上、(1, 1) が右下(1, 0)：自分の右上
位置アンカーからのずれ（px。下が +Y）(-40, 30)：左へ 40、下へ 30

右上に置くものは右上から、下の中央に置くものは下から測ると、位置の数字が小さく分かりやすくなります。UI には親子のレイアウトはなく、どの要素も画面に対して個別に置きます。重なり順は 描画順（sortOrder）が大きいほど手前です。

カメラと画面の演出

ゲームの視点を動かしてプレイヤーを追いかけ、揺れや暗転で手応えを出します。

ゲームのカメラの仕組み

  • ゲームの画面は、カメラ コンポーネントの ゲームの視点 がオンになっているオブジェクトから映します。テンプレートでは MainCamera です。
  • カメラの位置と向きは、そのオブジェクトのトランスフォームが決めます。
  • エディタでは、キー 2 でゲームの視点、1 でエディタの視点に切り替わります。

Scene::GetGameCamera() で取れる GameCamera に位置を書いても、毎フレームカメラのオブジェクトのトランスフォームで上書きされ、元に戻ります。カメラを動かすときは、カメラのオブジェクトを探して transform を書き換えます。

プレイヤーを追いかける

追いかけるカメラは、プレイヤーが動いた後に動かしたいので LateUpdate に書きます。目標の位置へ少しずつ近づけると、なめらかに付いてきます。

回転は x がピッチ（正で下を向く）、y がヨー（+Z が前）、z がロールです。atan2(d.x, d.z) で左右の向き、-asin(d.y) で上下の向きが求まります。

カメラの子に置かず、スクリプトで追いかけるのがおすすめです。カメラは自分のワールドの位置と自分の回転を使うので、親の回転は効きません。

画角を変える（ズーム）

カメラの fov（縦の画角・度）を小さくすると寄って見えます。Tween で変えると、なめらかにズームします。

画面を揺らす

名前の付いたプリセットを鳴らすのがいちばん手軽です。第 2 引数で強さを倍にできます。

プリセット向いている場面
Hit ／ HeavyHit攻撃が当たった ／ 大ダメージ
Explosion爆発
Landing高い所からの着地
Recoil撃った反動・決定の手応え
Earthquake ／ Rumble地震・長く続く揺れ
Handheld手持ちカメラのような、ゆるい揺れ

揺れが見えるのはゲームの視点のときだけです（エディタの視点では画面は動きません）。揺れ方を細かく決めるときは CameraShake と CameraShakeParams を見てください。

暗転する

Rendering::SetFadeAlpha で画面全体を黒で覆います（0 = 透明、1 = 真っ黒）。Tween と組み合わせると、なめらかに暗転できます。

Scene::ChangeScene 自体にも、短い読み込みの暗転が入ります（シーンの切り替え）。

ノードエディタ

ノード（箱）のピン（端の丸）どうしを線（つながり）で結んで組み立てる画面を作れます。会話の流れ・処理の手順・状態の移り変わりのように、順番や分かれ道のあるデータを作るのに向いています。ノードとつながりのデータはスクリプトが持ちます。ノードエディタは毎フレームそれを描き、ユーザーが何をしたか（つないだ・外した・動かした）を知らせるだけで、知らせを受けてデータを直すのはスクリプトです。

  • 番号：ノード・ピン・つながりには int の番号を付けます。同じノードエディタの中で、ノードどうし・ピンどうし・つながりどうしが重ならないようにします。ピンはノードをまたいでも重ならないようにするので、ノードの番号 * 16 + 何番目 のように作ると楽です。同じ番号を 2 回使うとスクリプトの例外になります。
  • 位置：BeginNode に渡した位置は、ノードが初めて出たときと、スクリプトが値を変えたときに使います。ユーザーがドラッグして動かした位置は、EndNode の後の GetNodePosition で受け取ってデータへ書き戻します。座標は、表示を動かしても変わらないノードエディタの中の位置です。
  • つながり：出口（OutputPin）から入口（InputPin）へドラッグするとつながります。IsLinkCreated は、どちらからドラッグしても出口・入口の順に返します。入口のピンからドラッグすると外れます（IsLinkDestroyed）。Link はノードの外（EndNode の後）で呼び、両端のピンがそのフレームに無いつながりは描かずに、Console へ一度だけ警告を出します。
  • 操作：中ボタンか Alt+左ドラッグで表示を動かす・ノードをドラッグで動かす・Ctrl+クリックで選び足す・何も無いところをドラッグして囲んで選ぶ、ができます。
  • ノードの中：部品は BeginNode の幅（既定 160）いっぱいに並びます。題名（NodeTitle）はピンより先に 1 回だけ描きます。BeginChild・BeginTable・BeginListBox・ListBox は、ノードエディタの中に置けません。
  • 見た目：SetNextNodeColor で次のノードの題名の色、SetNextPinColor で次のピンの色、Link の 4 つ目の引数でつながりの色を変えられます。ピンの形は EditorGUI::PinShape:: の Circle・CircleFilled・Triangle・TriangleFilled・Quad・QuadFilled です。BeginNodeEditor の flags には、EditorGUI::NodeEditorFlags::MiniMap（右下の全体図）と SnapToGrid（格子に合わせて動かす）を | でつないで渡せます。

シーンビューに描く・クリックを受け取る（OnSceneGUI）

ウィンドウに void OnSceneGUI() を書くと、ウィンドウを開いている間、エディタの Game ウィンドウにシーンを描くフレームごとに呼ばれます（この文書ではシーンビューと呼びます。エディタのカメラで見ているときも、ゲームのカメラで見ているときも同じです）。中で Handles:: を使ってシーンの上に線・枠・文字を重ね、SceneView:: でマウスの位置・クリック・カメラを読みます。

  • 描く：Handles:: の線・枠・円・点・文字は、シーンの物より手前に重ねて描きます（奥の物に隠れません）。色は 0〜1 の RGBA で、色見本と同じ見え方です。描いたものはそのフレームだけ出るので、毎フレーム描きます。
  • カーソルの下：SceneView::RaycastMouse(point, normal) はカーソルの下のメッシュの表面の点と向きを、SceneView::MouseToPlane(高さ, point) は決めた高さの水平な床との交点を、SceneView::GetObjectUnderMouse() はクリックしたら選ばれるオブジェクトを返します。
  • クリック：SceneView::IsMouseClicked・IsMouseDown は、カーソルがシーンビューの上にあって、ギズモやハンドルの上でないときだけ true です。Shift などは SceneView::shift・ctrl・alt、キーは SceneView::IsKeyPressed で読みます。
  • 選ばせない：シーンビューの左クリックでオブジェクトを選ばせたくない間は、毎フレーム SceneView::UseMouse() を呼びます（呼んだ次のフレームのクリックから効きます）。
  • シーンを変える操作は Editor:: の関数と Editor::RecordObject で行うと、Ctrl+Z で戻せます。

ハンドルで点を動かす

コンポーネント（ScriptComponent を継いだクラス）に void OnDrawGizmos() を書くと、エディタのシーンビューを描くフレームごとに呼ばれ、Gizmos:: で道筋・範囲・向きなどの目印を描けます。void OnDrawGizmosSelected() は、持ち主を選んでいる間だけ呼ばれます。どちらも編集中にも呼ばれ、書き出したゲームでは呼ばれません。Gizmos:: は Scripts/Editor の外でも書けて、書き出したゲームでは何もしません。

ギズモの関数で例外が起きると、そのコンポーネントのギズモだけ、直して保存するまで描かなくなります（コンポーネントは止まりません）。

  • .as を保存すると、ウィンドウを開いたまま読み直します。メンバ変数の値（数値・bool・string・Vector2〜Vector4・列挙・スクリプトのクラスと、それらの array）は、名前と型が同じなら private でも持ち越します。クラスのオブジェクトは同じ名前のクラスで作り直して中身を戻し、同じオブジェクトを 2 か所から指していれば、読み直した後も同じものを指します。GameObject@ などエンジンのオブジェクトのハンドルは初期値に戻ります。

AngelScript で最もつまずきやすいのがハンドルです。@ の付いた型は「オブジェクトを指す参照」で、C# の参照型の変数や C++ のポインタにあたります。

null の確かめ方

is ／ !is は「同じものを指しているか」を比べます。null のハンドルを使うと例外になり、そのコンポーネントが止まるので、使う前に確かめる習慣をつけてください。

ハンドルの代入は @ を付ける

自作のクラスのハンドルに @ を付けずに代入すると、中身が丸ごとコピーされます（エラーにならないことがある）。ハンドルを付け替えるつもりなら、必ず @a = b; と書きます。

GetComponent で @ を付ける理由

GetComponent は、渡されたハンドルの変数に見つかったコンポーネントを入れます。変数そのもの（ハンドル）を渡すために @ を付けます。

基底クラスから派生クラスへ

オブジェクトの寿命

  • 自作のクラスのオブジェクトは Foo@ f = Foo(); で作ります（new はありません）。誰も指さなくなると自動で片付きます。
  • エンジンの GameObject は、ハンドルを持っていても Destroy() されれば消えます。そのハンドルは null にはならないので、isAlive で確かめます。

  • コンポーネントはエンジンが引数なしで作ります。引数のあるコンストラクタだけを書くと作れません。

クラスの外に書いた変数は、すべてのスクリプトから使えます。

グローバル変数は、シーンを切り替えてもエディタで再生を止めても元に戻りません（スクリプトを読み直したときにだけ初期値に戻ります）。前回の再生の値が残って混乱しやすいので、変わる値はグローバル変数ではなく、進行役のコンポーネントのメンバか Session に持たせてください。定数（const）には問題なく使えます。

コインを集めるゲームを作る

箱を動かして、置いてあるコインを全部拾うとクリアになる小さなゲームを、最初から最後まで作ります。エディタでの配置、スクリプト、当たり判定、UI、プレハブ、シーンの読み直しまで、ゲーム作りの基本がひと通り入っています。

1. 用意プロジェクトを作る → 2. 当たりプレイヤーに形を足す → 3. コインスクリプトとプレハブ → 4. 数える点数係と UI → 5. 仕上げ遊んで直す

WASD・矢印キー・左スティックでオレンジの箱を動かし、5 枚のコインを拾います。画面の左上に枚数と経過時間が出て、全部拾うと「CLEAR!」が出て、3 秒後に最初からやり直しになります。所要時間は 30 分ほどです。

1. プロジェクトを用意する

  1. プロジェクトを作るエディタを起動し、プロジェクトを選ぶ画面で新しいプロジェクトを作ります。テンプレートは 3D の基本、名前は CoinGame にします（最初のプロジェクトを作る）。
  2. 動くか確かめるCtrl+P で再生し、WASD でオレンジの箱（Player）が動くのを確かめます。もう一度 Ctrl+P で止めます。

箱を動かしているのは、テンプレートに入っているスクリプト PlayerMover です。このチュートリアルでは、プレイヤーの目印としてこのクラスを使います。

2. プレイヤーに当たり判定を付ける

  1. Player を選ぶHierarchy で Player をクリックします。

読み込むときは、マスごとに「壁か」「ゴールか」「どの箱がいるか」の表（配列）を作り、マスの種類に合うプレハブを InstantiatePrefab で置きます。ステージを替えるときは、置いた物を全部 Destroy してから置き直します。

動けるかはマスの表で決める

当たり判定（コライダー）は使っていません。進む先のマスが壁なら止まり、箱なら、その先が空いているときだけ箱ごと進みます。

入力は Input::IsActionTriggered で押した瞬間だけを見るので、押し続けても 1 マスずつしか進みません。Restart（R）と NextStage（Space・Enter）は、このプロジェクトの InputActions.json に足した入力アクションです。

動きはイージングで補間する

マスの表はすぐ書き換え、見た目だけを Tween::MoveTo で moveTime 秒かけて追いかけさせています。前の動きが終わる前に次の手が来たら、KillByLink(object, true) で前の動きを終わりまで飛ばしてから動かします。

パーティクルで知らせる

パーティクルはシーンに 1 つずつ置いておき、出す場所へ動かして Emit(数) で粒を出します。粒の色・大きさ・速さはインスペクタで決め、スクリプトは出すきっかけと場所だけを持ちます。箱がゴールに乗るとそのマスで光の粒を、クリアすると盤面の上の 2 か所で紙吹雪を出します。

粒の飛ぶ向きは「速度」モジュールで決まります。「形」が決めるのは粒の出る位置だけなので、速度モジュールを切ると、粒は初速 0 のまま重力で落ちるだけになります。紙吹雪は速度モジュールの「ランダムな向き」で四方へはじけさせ、「外力」の重力と抵抗でゆっくり降らせています。

読み直しても続きから遊べるようにする

スクリプトを保存して読み直すと、保存されるメンバ変数は値を引き継ぎ、private のメンバ変数は初期値に戻ります（読み直しのときの値）。盤面の表を private だけで持つと、読み直した後は動けなくなります。倉庫番は、続きから遊ぶのに要る値を [Hidden]（インスペクタには出さないが、保存はする）のメンバ変数に持ち、OnScriptReloaded で盤面を組み直しています。

置いた物の控え（private の配列）も読み直しで空になるので、FindObject で名前から探して消しています。FindObject は消す予定の物を返さないので、見つからなくなるまで繰り返せば全部消えます。

自分のゲームに持ち帰ること

  • マス目のゲームは、見た目とは別にマスの表（配列）を持ち、動けるかは表で決める
  • ステージはデータ（文字や配列）にして、増やすときにコードを触らない
  • 見た目と大きさはプレハブに任せ、スクリプトは置く場所だけを決める
  • 表はすぐ書き換え、見た目は Tween で後から追いかけさせる
  • パーティクルはシーンに置いて設定し、スクリプトからは出す場所と数だけを渡す
  • 読み直しで続きを保ちたい値は、[Hidden] などの保存されるメンバ変数に持つ
  • クラス名には機能の名前を頭に付けて、ぶつからないようにする

git は、別々のファイルなら何人が同時に変えても自動でまとめます。衝突するのは、同じファイルの近い所を 2 人が変えたときだけです。

名前がぶつからないようにする

  • オブジェクト：エディタで作ったオブジェクトのファイル名には、後ろにランダムな印が付きます（Coin_7f3a91c2.json）。2 人が同じ名前のオブジェクトを作っても、ファイルは重なりません。
  • 参照：インスペクタで繋いだ [ObjectRef] は、名前ではなくオブジェクトの ID で覚えています。ただし owner.FindObject("名前") で探すオブジェクトは、シーンに 1 つだけにします（同じ名前が 2 つあると、どちらが返るか分かりません）。
  • スクリプトのクラス：クラス名はフォルダが違ってもプロジェクト全体で 1 つです。頭に機能の名前を付けます（見本の倉庫番は SokobanBoard）。Project の スクリプトを作成 は、同じ名前のスクリプトやコンポーネントがあると作らずに理由を出します。

それでも 2 人が同じクラス名を作って pull で出会うと、コンパイルに失敗し、Console に両方の場所が出ます。

まだシーンで使っていない方の、ファイル名とクラス名を変えます。シーンの JSON はコンポーネントを型の名前（"type": "Enemy"）で覚えているので、使っている方を変えると、そのコンポーネントは「読み込めない型」になります（値は残るので、名前を戻せば元に戻ります）。

pull と保存の流れ

  1. 作業の前に pull するエディタは開いたままでかまいません。
  2. 作業して保存するCtrl+S。
  3. シーンのフォルダを丸ごと commit する消したオブジェクトは JSON が消えているので、その削除も一緒に入れます。
  4. もう一度 pull してから push する

エディタを開いたまま pull したとき

エディタは、編集中は開いているシーンのフォルダを 1 秒ごとに確かめます（再生中は確かめず、止めた後に確かめます）。外でファイルが変わっていたら、次のようにします。

自分の状態エディタがすること
保存していない変更が無い何も聞かずに読み直します。エディタの視点はそのままです
保存していない変更がある「外でシーンのファイルが変わりました」と、変わったファイルの一覧を出して聞きます。このまま続ける を選ぶと、あとで保存したとき、自分が変えていないファイルは外のもの（ほかの人の変更）を残します。読み直す（自分の変更は捨てる） でファイルから読み直します

スクリプト（.as）は pull で変わると自動でコンパイルし直します。

保存でほかの人の変更を消しそうなとき

自分も変えたファイルを、ほかの人も変えていたら、書く前に「ほかの人の変更とぶつかります」と聞きます。

ボタンすること
保存をやめる何も書きません
読み直すほかの人の変更を読み込みます。保存していない自分の変更は消えます
上書きして保存自分の値で書きます。そのファイルへのほかの人の変更は消えます

保存で消す JSON は、自分がエディタで消したオブジェクトのものだけです。ほかの人が足したオブジェクトの JSON は消しません。

エンジンを更新したあと

エンジンの保存の書き方が変わると、シーンを開いて保存しただけで、触っていないオブジェクトの JSON まで書き換わることがあります。そのままだと、みんなの差分に関係の無い行が混ざります。

  1. 1 人が保存し直すFile▸すべてのシーンと設定を保存し直す… を実行します。
  2. その変更だけで commit・push する
  3. ほかの人は自分の作業を commit してから pull する

コマンドからも実行できます。全部のシーンを保存し直すと、エディタは自分で閉じます。

衝突したら

ファイル直し方
オブジェクトの JSON・_scene.json・_environment.jsonテキストなので、どちらかを選ぶか手で合わせます。git の印（<<<<<<< など）が残ったままだと、そのオブジェクトは読み込みのときに飛ばされ、Console にファイル名が出ます
バイナリ（画像・モデル・_cloudPaint.bin）まとめられないので、どちらか一方を選びます

git pull --rebase の途中では、--ours が相手（取り込んだ側）、--theirs が自分になります。

できないこと

  • 同じオブジェクトを 2 人で同時に変えると衝突します。1 個のオブジェクトは 1 ファイルなので、エンジンでは防げません。
  • バイナリはまとめられません。画像・モデル・雲の配置は、担当を決めて 1 人ずつ変えます。
  • 大きな素材を何度も上書きすると、リポジトリが重くなります。仮の素材で作り、本番の素材は数を絞って入れます。

バージョン番号の付け方

バージョンは v0.1.0 のように、3 つの数字をつないで書きます（v主.副.修正）。

上げる数字上げるとき
修正（0.1.1）不具合の修正だけで、使い方が変わらないとき
副（0.2.0）機能を足したとき。1.0 になるまでは、スクリプトの API やプロジェクトの形式が変わって、古いスクリプトやシーンがそのままでは動かなくなる変更もここで上げます
主（1.0.0）「スクリプトの API とプロジェクトの形式を勝手に変えない」と約束できる版になったとき。以後は、それが壊れる変更のときだけ上げます

先頭が 0 の間は、副の数字が上がると古いスクリプトやシーンが動かなくなることがあります。壊れる変更があるときは、その版の項目に書きます。

版を上げるとき（エンジンを触る人向け）

  1. 番号を決める上の表に従って決めます。
  2. 3 か所を同じ番号にするProject/Engine/Src/EngineSystem/EngineVersion.h の kEngineVersion、このドキュメント（Project/Engine/Docs/index.html）の先頭近くにある engine-version の値、そしてこのページの新しい項目です。
  3. PR をマージするドキュメントはエンジンと同じリポジトリに入っているので、同じ PR で一緒に直します。
  4. タグを打つマージしたあとの master に、git tag -a v0.2.0 -m "v0.2.0" を付けて、git push origin v0.2.0 で送ります。

ドキュメントはエンジンと同じタグで固定されるので、別の番号は付けません。古い版のドキュメントは、その版のタグを取り出す（git checkout v0.1.0）と読めます。

付け方スクリプトからの取り方
Inspector の ＋ コンポーネント追加、またはメニューの Component。一覧ではエディタでの名前（剛体 など）で並ぶ型名の先頭を小文字にしたプロパティ（owner.rigidbody）か GetComponent。付いていなくても null にならないので、exists で確かめる

コンポーネントのハンドルには、次の 3 つがあります（各ページの表では省いているものがあります）。トランスフォームと UI テキスト・UI 画像・UI ボタンには enabled がありません。隠すときはオブジェクトごと active を切り替えます。

メンバー中身
bool existsそのコンポーネントが付いているか（読み取り専用）
bool enabled有効か。false にすると、そのコンポーネントだけが止まる（見た目を隠す、など）
GameObject@ gameObject持ち主のオブジェクト（読み取り専用）

スクリプト API

スクリプトから使える型・名前空間・列挙の一覧です。エンジンのコンポーネントの型（Rigidbody など）は コンポーネント一覧 にあります。

目次の印種類使い方
Cクラスハンドル（GameObject@）で受け取って使う
V値の型Vector3 v; のように変数に直接持つ。代入するとコピーになる
N名前空間Input::IsActionPressed(…) のように :: で呼ぶ
E列挙EaseType::EaseOutBack のように名前で書く
Fグローバル関数Log(…)・Lerp(…) のようにそのまま呼ぶ
D関数の型Tween などへ渡す関数の形（TweenCallback など）

メンバーの表の 読み取り専用 は値を読むだけのプロパティ、メソッド ・関数 は呼び出すものです。VS Code では、プロジェクトの Scripts/as.predefined を読んで補完が出ます。
