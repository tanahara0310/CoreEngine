## 1. このロードマップの考え方

このシステムは「雲の絵を空に貼る」ためのものではない。  
**雲を密度場としてレイマーチし、太陽・月の位置から陰影と色を物理的に導出して、大気散乱と単一の空を構成する** ための実装である。

「物理的に正しい」は次の 3 段階で整理する。

1. **物理に反しない近似**  
   Beer-Lambert 減衰、HG 位相関数、エネルギーを増やさない多重散乱近似を崩さない
2. **リアルタイム向けの高忠実度近似**  
   手続きノイズによる密度場、半解像度レイマーチ、指数ステップのサンライトマーチ
3. **一貫性の統合**  
   ライト・空気遠近・映り込み・露出を大気システムと共有し、時間帯変化に自動追従させる

## 2. 全体進捗サマリー

### 2-1. 現在の実装状況
- Schneider "Nubis" 方式（Horizon Zero Dawn / Decima）をベースにした雲レイマーチを実装済み。設計書のフェーズ 0〜6（ノイズ生成 → 密度場 → レイマーチ → ライティング → 合成 → 既定背景統合・エディタ）は完了している
- **密度場**: 天候マップ（512²・カバレッジ / 雲種）× Base Shape ノイズ（Perlin-Worley 128³）− Detail ノイズ（Worley 32³）の remap 構成。すべて Compute Shader による手続き生成で、ノイズ生成時のタイル可能ドメインワープにより格子規則性を崩している（ランタイムコストゼロ）
- **雲層ジオメトリ**: 惑星中心を共有する球殻（内殻 = 惑星半径 + 雲底高度、外殻 = 内殻 + 層厚）。カメラが雲層の下・中・上のどこでも破綻しない。レイマーチは最大 120km で地平線まで雲が連続する
- **ライティング**: サンライトマーチ（セルフシャドウ・ジッタなし指数ステップ）＋ HG 位相＋ Powder ＋ **多重散乱オクターブ近似**（Hillaire/Frostbite。単一散乱のみだと濃い雲の内部が真っ黒になる）。`DirectLightLuminanceAt` の一般化により**太陽＋月の 2 光源**へ対応済みで、夜は月明かりの雲になる
- **大気との統合**: 太陽・月情報は `AtmosphereManager` から取得（単一情報源）。遠方の雲は Sky-View LUT へ距離ブレンドして空気遠近感に溶かす
- **合成**: 半解像度レイマーチ → テントフィルタでアップサンプル。不透明物が雲層より手前の画素では合成しない（輪郭ハロ回避）
- **映り込み**: `CloudCubemapCapture.CS` が空キューブマップへ雲を前乗算合成し、GGX プリフィルタ経由でモデル・水面のスペキュラ IBL に雲が映る（雲アニメ中は毎フレーム再キャプチャ）
- **エディタ**: エンジン常駐の `VolumetricCloudEditor`（Environment ツリー →「Volumetric Cloud」）。UE 風の 3 段構成（プリセット → 基本 → 上級・折りたたみ）＋天候プリセット 5 種（快晴 / 部分的な曇り / 曇天 / 高い薄雲 / 嵐の前）
- 関連機能として**ゴッドレイ**（`GodRayPass`。雲の遮蔽を使った光条）が実装済みで、調整 UI は雲エディタ内にある

## 3. 目指す見え方

### 3-1. 必須要件
- 雲が立体として陰影を持ち、太陽の位置で明暗が変わる
- 雲量（カバレッジ）の増減で快晴〜曇天まで連続的に変化し、孤立した粒にならない
- 雲が地平線まで自然に続き、遠方は霞んで空に溶ける
- 風で雲がゆっくり流れ、映り込みも追従する
- 夕焼け・夜（月明かり）にも自動で追従する

### 3-2. 最終要件
- 大気・雲・水面・オブジェクトの映り込みが単一の空を共有している
- カメラが雲層内・雲上へ移動しても破綻しない
- 天候変化がプリセット 1 クリックで成立する

## 4. 実装方針

### 4-1. 密度場は手続き生成を主軸にする
- 雲テクスチャ（絵）には依存しない。天候マップ×ノイズの remap で密度を作る
- ノイズの規則性は生成時のドメインワープで崩す（ランタイムで隠さない）
- 生成 CS 内の定数（広域変調・コントラスト remap）はテクスチャへ焼き込まれる「隠れパラメータ」であることを常に意識する

### 4-2. レイマーチはワールド固定格子に載せる
- サンプル点はワールド固定の平面格子に量子化し、ステップ伸長は基本幅の**整数倍**にする（連続倍率はカメラ移動でサンプルが滑り、雲面が振動する）

### 4-3. ライティングはエネルギーを増やさない近似で組む
- Beer-Lambert・HG 位相・Powder を基本とし、多重散乱はオクターブ近似で追加する
- 光源色・強度は大気システムから取得し、雲側で独自の色調整をしない

### 4-4. 負荷は解像度と事前計算で制御する
- レイマーチは半解像度、ノイズはダーティ時のみ再生成
- 合成はテントフィルタ＋輪郭ハロ回避を前提とする

### 4-5. チューニングの不変条件
- `globalCoverage` と `detailErosionStrength` は必ずセットで動かす（coverage を下げたら erosion も下げる）。崩すと雲塊をつなぐ「もや」が消えて丸い粒が孤立する「ポップコーン雲」になる
- 天候プリセットは「見た目」パラメータのみを適用し、マーチング予算・位相 / 多重散乱の物理定数には触れない

---

## 5. 非目標

- 積乱雲の内部飛行など、雲内部の映画品質ボリュームレンダリング
- CPU 側の流体シミュレーションによる雲生成
- 雲の絵作りのための恣意的なライティング補正（物理近似の範囲で調整する）

## 7. 最終到達点

このロードマップの最高地点は、

- **手続き密度場による立体雲**
- **大気散乱と単一情報源を共有するライティング（昼・夕・夜）**
- **水面・モデルへの映り込みを含む画面全体の空の一貫性**

を統合した **大気と一体のボリューメトリック雲システム** である。

雲は空の飾りではなく、大気・照明・映り込みと同じ物理スケールで動く空の構成要素として扱う。
