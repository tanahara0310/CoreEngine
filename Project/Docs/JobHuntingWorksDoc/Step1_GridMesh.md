# Step 1 : 水面メッシュと空間基準の整備

## ステータス
- 状態: 実装完了（検証継続）
- 優先度: 最優先
- 依存ステップ: なし
- 現在位置: 水面グリッドメッシュと水面高さ基準は実装済み。以後の波面・反射・透過処理の土台として使用中
- 完了後に着手しやすい次ステップ: Step 2, Step 3

## 目的
物理ベース水面表現の土台となる幾何、座標系、法線基準、深度基準を整え、後続の波面・反射・透過・屈折が同じ空間基準の上に乗る状態を作る。

## このステップの作業範囲
- 水面平面メッシュの生成方式
- 頂点属性の定義（位置、UV、法線、接線、インデックス）
- 水面高さの共有基準
- 反射・屈折・深度差計算が参照する空間基準の整理
- 解像度切り替え時の品質とコストの比較基盤

## このステップで扱う責務
- 水面メッシュの幾何基盤を用意する
- 水面高さを共通参照値として定義する
- 初期法線と接線の基準を固定する
- 後続ステップが再利用できる安定した頂点レイアウトを作る

## このステップの役割
物理ベース水面では、見た目の前に **幾何と空間基準の整合** が必要になる。  
ここで整えるべきものは単なる平面描画ではなく、以下である。

- 水面の幾何密度
- ワールド座標系での水面高さ基準
- 法線の初期基準
- クリップ平面や深度差の基礎となる位置情報
- 反射・屈折・泡・コースティクスの投影先としての安定したメッシュ

## 作業項目
- [x] `N × N` 分割の平面メッシュ生成方針を決める
- [x] 水面ローカル法線基準を `(0, 1, 0)` で固定する
- [x] UV、法線、接線、インデックス構成を後続利用前提で定義する
- [x] 水面高さを共通物理基準として利用する設計を明記する
- [x] 解像度変更時の見た目差分とコスト差分を評価できる基盤を持たせる

## 実施結果
- `WaterPlaneObject` が `PlaneMeshGenerator` を使って分割平面メッシュを生成する構成になった
- `WaterTestScene` では `WaterPlaneObject(100.0f, 128)` を生成し、十分な頂点密度で運用している
- 水面高さは `waterPlane_->GetTransform().translate.y` を基準に扱い、ReflectionView や clip plane が同じ Y 基準を参照している
- 後続の Gerstner Wave、Depth Fade、Planar Reflection がこの平面を前提に接続済み

## 設計要点
### 1. 水面高さを共有基準にする
- `Y = waterHeight` を共通平面として扱う
- Planar Reflection、Depth Fade、交差泡、コースティクスはこの基準を参照する

### 2. メッシュ密度は波面表現に直結する
- 近景水面では頂点密度不足がそのまま波の破綻になる
- 解像度は見た目だけでなく、Gerstner Wave の表現帯域を決める

### 3. 法線・接線の初期定義を明確にする
- 初期法線: `(0, 1, 0)`
- 接線 / 従法線は後続で再計算可能な形にしておく
- 変位後に解析法線へ置き換える前提を明文化する

## 実装要素
| 要素 | 内容 |
|------|------|
| Grid Mesh | 水面の幾何基盤 |
| Vertex Buffer / Index Buffer | 分割平面を GPU 描画する基礎 |
| World-space water height | 水面高さの共通参照値 |
| Initial normal basis | 後続の解析法線計算の出発点 |
| Forward rendering path | 波面変位や透過を扱うための描画経路 |

## 実装時の観点
- Vertex / Index Buffer は GPU 向けに配置する
- メッシュ解像度違いを切り替え可能にして、品質と負荷を比較できるようにする
- 水面オブジェクトは後続のカスタムシェーダー差し替えに対応できる構造にする
- 反射パスや深度差計算で同じ座標基準を参照できるよう、Transform の扱いを明確化する

## 期待する到達状態
- 水面平面が後続効果の土台として安定している
- 波面変位を入れても法線基準が破綻しない
- 反射・透過・深度差・泡が同じ水面高さを参照できる
