## 1. このロードマップの考え方

このシステムは「空の絵を綺麗にする」ためのものではない。  
**太陽と月の位置という単一の入力から、空の色・太陽ディスク・遠景の霞・直接光の色・環境光・露出までを物理的に一貫して導出する** ための実装である。

「物理的に正しい」は次の 3 段階で整理する。

1. **物理に反しない近似**  
   レイリー / ミー散乱、オゾン吸収、Beer-Lambert 透過、エネルギー保存積分を崩さない
2. **リアルタイム向けの高忠実度近似**  
   LUT 事前計算（Hillaire 2020）、多重散乱近似、SH 環境光、動的キューブマップ IBL
3. **一貫性の統合**  
   空・霞・ライト色・環境光・露出・水面や雲との連携を単一情報源（大気の太陽/月ライト）から駆動する

## 2. 全体進捗サマリー

### 2-1. 現在の実装状況
- Bruneton/Hillaire 方式（Hillaire 2020）の大気散乱を実装済み。**LUT 4 種**（Transmittance / Multi-Scattering / Sky-View / Camera Volume）を `AtmosphereLUTPass` で事前計算し、空の描画は Sky-View LUT 1 サンプル＋太陽ディスクの解析描画で行う
- LUT はダーティフラグで必要なものだけ再生成する（大気パラメータ変更→全 LUT / 太陽方向・カメラ高度変更→Sky-View のみ / カメラ姿勢変更→Camera Volume のみ）
- 遠景の霞は **Aerial Perspective**（Camera Volume LUT ＋合成 CS）として不透明ジオメトリへ適用済み。水面など半透明へも `AtmosphereApply.hlsli` 経由で適用できる（距離スケール調整 UI あり）
- **太陽光の透過率連動**（UE の Transmittance on Light 相当）を実装済み。CPU レイマーチで求めた透過率を GPU 転送時のライト色へ乗算し、夕方は地面・モデル・水・コースティクスの照明が一斉に赤方偏移する
- **夜間**: 月を第 2 の大気ライト（`isAtmosphereMoon`）として Sky-View LUT を 2 光源積分し、満ち欠け付き月ディスク（既定は常に満月）と手続き的星空（テクスチャ不要・空が明るいと自動消灯）を実装済み
- **露出**: 手動 EV ＋自動露出（Krawczyk 自動キー・順応）を実装済み。測光は既定で**照明駆動**（太陽・月の高度・強度から解析的にシーン照度を算出。構図による露出ポンピングを排除）。月夜は最大 +8EV
- **環境光**: Sky-View LUT → SH9（Sky Irradiance）で非 IBL サーフェスの拡散環境光を空連動化。空＋雲の動的キューブマップ（GGX プリフィルタ済み）でスペキュラ IBL も供給する
- **エディタ**: エンジン常駐の `AtmosphereEditor`（Environment ツリー →「Sky Atmosphere」）。スカイマップ（極座標ドームの太陽 / 月ハンドルドラッグ）、時刻 [h] / 緯度スライダー、プリセット（正午 / 朝 / 夕暮れ / 夜（満月））、時刻自動進行
- **全シーン既定背景化済み**。静的 HDR キューブマップ＋IBL セットアップは全シーンから廃止し、モデルの環境反射は空キューブマップが担う（キューブマップ空は `SkyBoxObject::SetTexture()` でオプトイン共存）

## 3. 目指す見え方

### 3-1. 必須要件
- 太陽を動かすだけで、青空 → 夕焼け → 薄明 → 夜が連続的に変化する
- 夕方は空だけでなく、直接光・霞・環境光・水面・雲も一緒に赤くなる
- 遠くの地形・オブジェクトほど霞んで空に溶ける
- 夜は月明かりの空・月ディスク・星空が成立し、露出で視認できる
- 空の輝度と地面・オブジェクトの明るさが単一の物理スケールで整合する

### 3-2. 最終要件
- 空・霞・照明・環境光・映り込みのすべてが「大気の太陽/月ライト」という単一情報源から導出されている
- キューブマップ空のシーンと共存でき、既定は大気散乱背景になる
- 露出を含めて、時間帯の変化がコンテンツ側の調整なしで破綻しない

## 4. 実装方針

### 4-1. 事前計算（LUT）を主軸にする
- 毎ピクセルのレイマーチはせず、LUT 4 種へ事前計算する
- LUT の再生成はダーティフラグで最小化する
- LUT には光源の色×強度を前乗算する（消費側で色を掛けない。二重適用禁止）

### 4-2. 座標系はゲームワールドを維持する
- ワールドは 1unit = 1m のまま。惑星スケールへの変換はカメラ Y 座標の高度変換のみで行う
- 惑星半径 6,360km / 大気圏上端 6,460km は大気計算専用の定数とする

### 4-3. ライトを単一情報源にする
- 大気の太陽 / 月は `DirectionalLightData::isAtmosphereSun / isAtmosphereMoon` のフラグで指定する
- 透過率はライトの authored 値を書き換えず、GPU 転送コピーへのみ乗算する
- 消費側（雲・水面・コースティクス）は同じライトを参照し、見た目の方向・色を自動一致させる

### 4-4. 露出は物理輝度の後段で解決する
- 大気パラメータで見た目の明るさを調整しない（「反太陽側が明るすぎる」等はまず露出・トーンマップを疑う）
- 自動露出は照明駆動測光を既定とし、構図依存のポンピングを避ける

### 4-5. オプトイン共存
- 大気モードは `SkyBoxObject::SetAtmosphereMode(true)` のオプトイン。キューブマップ空のシーンには影響を与えない

---

## 5. 非目標

- 惑星外（宇宙）からの眺めの正確さ（Phase 5 として保留中）
- 雲の生成・ライティングそのもの（VolumetricCloud 側の責務。大気は Sky-View・透過率・太陽情報を供給する）
- スペクトルレンダリング等のオフライン品質

## 7. 最終到達点

このロードマップの最高地点は、

- **LUT ベースの物理大気（昼・薄明・夜の連続変化)**
- **太陽・月という単一情報源からの照明・霞・環境光・露出の一貫導出**
- **雲・水面・シーンオブジェクトを含む画面全体の物理整合**

を統合した **時間帯フリーの物理ベース空システム** である。

空は背景画像ではなく、シーンの照明環境そのものとして扱う。
