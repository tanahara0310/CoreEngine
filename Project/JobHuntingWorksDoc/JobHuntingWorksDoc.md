# リアルな水面表現 実装ロードマップ

> **対象環境:** C++ / DirectX 12  
> **方針:** 動きだけの最小実装から始め、段階的にグラフィック品質を高める  
> **最終目標:** FFT Ocean + SSR + Caustics によるハイクオリティな水面レンダリング

---

## 全体マップ

```
Step 1 │ グリッドメッシュの生成と表示          ← まずここから
Step 2 │ UV スクロール（動きだけの水）
Step 3 │ Gerstner Wave（頂点変位による波）
Step 4 │ Planar Reflection + Fresnel（反射・屈折）
Step 5 │ Normal Map + PBR ライティング
Step 6 │ FFT Ocean（本格的な海洋シミュレーション）
Step 7 │ SSR / Caustics / Foam（最高品質の演出）
```

## STEP 1 : グリッドメッシュの生成と表示

### 目標
水面の土台となる `N × N` 分割の平面ポリゴンを生成し、青い単色でレンダリングする。  
このメッシュが以降すべてのステップの土台になるため、分割数（resolution）の設計を最初に決める。

### 方針
- 頂点を格子状に生成し、隣接する 4 頂点を 2 枚の三角形（クワッド）で構成する
- `resolution` を変数として持ち、後から変更できる設計にする
- 頂点データには **座標・UV・法線** の 3 要素を持たせる
- Index Buffer を使って重複頂点を削減する

### 使用技術

| 技術名 | 役割 |
|--------|------|
| **Grid Mesh（グリッドメッシュ）** | 格子状に頂点を並べた平面ポリゴン。分割数が高いほど後のステップで波の表現が細かくなる |
| **Vertex Buffer** | GPU に頂点データ（座標・UV・法線）を渡すバッファ |
| **Index Buffer** | 頂点の描画順（三角形の組み合わせ）を定義するバッファ。重複する頂点データを削減できる |
| **Input Layout** | 頂点シェーダーに渡す頂点構造体のメモリレイアウト定義 |

### メッシュの構造

```
[N=3 の場合のグリッドイメージ]

(0,3)-(1,3)-(2,3)-(3,3)
  |     |     |     |
(0,2)-(1,2)-(2,2)-(3,2)
  |     |     |     |
(0,1)-(1,1)-(2,1)-(3,1)
  |     |     |     |
(0,0)-(1,0)-(2,0)-(3,0)

頂点数        : (N+1) × (N+1)
三角形数      : N × N × 2
インデックス数 : N × N × 6
```

### 確認ポイント
- [ ] 青い平面が画面に表示される
- [ ] `resolution` の値を変えるとポリゴン密度が変わる
- [ ] ワイヤーフレームモードで格子が確認できる

## STEP 2 : UV スクロール（動きだけの水）

### 目標
テクスチャの UV 座標を時間でオフセットし、水が流れているように見せる。  
この段階ではメッシュ形状に変化はなく、見た目の動きだけを追加する。

### 方針
- CPU から GPU へ `time`（経過時間）を Constant Buffer で毎フレーム渡す
- Pixel Shader 上で UV に `time × speed` を加算してスクロールを実現する
- 2 方向・2 速度の UV スクロールを重ね合わせることで単調さを排除する
- テクスチャは `D3D12_TEXTURE_ADDRESS_MODE_WRAP` でタイリング設定する

### 使用技術

| 技術名 | 役割 |
|--------|------|
| **UV スクロール** | `uv += time * speed` で毎フレームテクスチャ座標をずらす最もシンプルな水演出 |
| **Tiling（テクスチャタイリング）** | `uv * tiling` で 1 枚のテクスチャを繰り返して大きな水面に対応する |
| **Constant Buffer（cbuffer）** | CPU → GPU へ毎フレーム値（時間・行列など）を渡す定数バッファ。D3D12 では **256 バイトアライメント**が必須 |
| **Sampler State（サンプラーステート）** | テクスチャのフィルタリング方法・ラッピング方法を設定するオブジェクト。タイリングには `D3D12_TEXTURE_ADDRESS_MODE_WRAP` を使用 |

### D3D12 における Constant Buffer の注意点
D3D12 では Constant Buffer のサイズを **256 バイト境界にアライメント**する必要がある。  
`CreateCommittedResource` でヒープを確保し、データの更新は `Map / Unmap` で行う。  
D3D11 の `UpdateSubresource` に相当する便利 API は存在しないため、自前で管理する。

### 確認ポイント
- [ ] テクスチャが流れるように動いている
- [ ] `tiling` 値を変えるとテクスチャの繰り返し間隔が変わる
- [ ] 複数方向にスクロールすると乱雑さが増す

## STEP 3 : Gerstner Wave（頂点変位による波）

### 目標
GPU の Vertex Shader 上で頂点 Y 座標（および XZ 座標）を時間に応じて動かし、  
物理的に自然な波形を生成する。

### 方針
- 複数の Gerstner Wave を定義し、重ね合わせることで複雑な波形を作る
- すべての計算を Vertex Shader 上で行い、CPU 負荷をゼロにする
- 変位後の法線を接線・従法線の外積から再計算し、後工程のライティングに備える
- 波のパラメータ（振幅・波長・方向・速度）は Constant Buffer で渡し、実行時に調整できるようにする

### 使用技術

| 技術名 | 役割 |
|--------|------|
| **Gerstner Wave（ガースナー波）** | 物理的に正確な波の数式。振幅・波長・速度・方向の 4 パラメータで 1 つの波を定義する。波の頂点がとがる（cycloidal）特徴がある |
| **Wave Superposition（重ね合わせ）** | 複数の Gerstner Wave を加算して複雑で自然な波形を作る原理。波の本数を増やすほどリアルになる |
| **Vertex Displacement（頂点変位）** | Vertex Shader 上で頂点座標を数式で動かす手法。CPU 処理ではなく GPU で並列実行するため高速 |
| **法線の再計算** | 変位した頂点に合わせて法線を更新する必要がある。接線（Tangent）と従法線（Binormal）を波の偏微分から求め、外積で法線を算出する |

### Gerstner Wave の数式

```
入力パラメータ:
  pos       : 頂点の元の XZ 位置
  dir       : 波の進行方向（正規化ベクトル）
  amplitude : 振幅 A（波の高さ）
  wavelength: 波長 L
  speed     : 位相速度倍率

中間計算:
  k = 2π / L                        波数（単位距離あたりの波の繰り返し数）
  ω = sqrt(g * k)  ※g = 9.8 m/s²   角周波数（重力による分散関係式）
  f = k * dot(dir, pos.xz) - ω * t  位相（時間と位置によって変化する値）
  q = Steepness（急峻さ係数, 0〜1）  1 に近いほど波の頂点がとがる

出力（頂点変位）:
  Δx = q * dir.x * A * cos(f)       水平変位 X（波の進行方向に沿った横揺れ）
  Δz = q * dir.y * A * cos(f)       水平変位 Z（波の進行方向に沿った横揺れ）
  Δy = A * sin(f)                   垂直変位 Y（上下の波高）
```

> **重力分散関係式 `ω = sqrt(g * k)` について**  
> 深水波では波長が長い波ほど速く伝播する（分散性）。  
> この式はその物理現象を正確に再現している。

### パラメータチューニング目安

```
穏やかな湖  : 振幅 0.05〜0.2、波長  3〜10、波 2〜3 本
荒れた海面  : 振幅 0.5〜2.0、波長 10〜30、波 4〜6 本
嵐の海      : 振幅 2.0〜5.0、波長 20〜50、波 8 本以上
```

### 確認ポイント
- [ ] メッシュの頂点が波打って動いている
- [ ] 複数の波を重ねると自然な複雑さが増す
- [ ] 法線が正しく更新されているか（ライティングで確認）

## STEP 4 : Planar Reflection + Fresnel（反射・屈折）

### 目標
水面に空やオブジェクトが映り込む反射と、  
見る角度によって反射率が変わる Fresnel 効果を実装する。

### 方針
- 反射・屈折それぞれ専用の **Render Target** にシーンを事前描画しテクスチャとして保持する
- 反射描画時は水面に対して鏡像したカメラ行列を使用する
- クリップ平面（水面境界）は D3D12 では API 設定が不可のため、**Vertex Shader の `SV_ClipDistance0`** セマンティクスで実装する
- 最終描画で反射・屈折テクスチャを Fresnel 係数でブレンドする

### 使用技術

| 技術名 | 役割 |
|--------|------|
| **Planar Reflection（平面反射）** | カメラを水面に対して鏡像した位置・向きから全シーンを別途描画し、その結果を反射テクスチャとして水面に貼る手法 |
| **Render Target Texture（RTT）** | シーンを画面（スワップチェーン）ではなくテクスチャに描画する仕組み。反射・屈折画像の生成に必須 |
| **Clip Plane（クリップ平面）** | 反射描画時に水面の片側だけを描画するための数学的な切り捨て平面 `ax + by + cz + d = 0`。D3D12 では `SV_ClipDistance0` セマンティクスで Vertex Shader に実装する |
| **Refraction（屈折）** | 水中方向へ向かう光が水面で進行方向を変える現象。屈折用 RTT の UV をノーマルマップでずらすことで近似する |
| **Fresnel Effect（フレネル効果）** | 水面を浅い角度で見ると反射が強くなり、真上から見ると透けて見える物理現象 |
| **Schlick's Approximation（シュリックの近似）** | Fresnel 係数を高速に計算するための近似式。`F = F0 + (1 - F0) * pow(1 - dot(V, N), 5)` が基本形。水の F0 は約 0.02 |

### Planar Reflection の描画フロー

```
[毎フレームの処理]

1. 鏡像カメラ行列を計算
   └─ XMMatrixReflect() で水面平面に対してカメラ位置・向きを反転

2. Clip Plane を cbuffer に設定
   └─ 反射パス : 水面より上だけを描画 ( 0,  1, 0, -waterHeight)
   └─ 屈折パス : 水面より下だけを描画 ( 0, -1, 0,  waterHeight)
   └─ Vertex Shader の SV_ClipDistance0 で dot(worldPos, clipPlane) を出力

3. 反射用 Render Target にシーンを描画
   └─ 鏡像カメラ行列 + 水面上 Clip Plane を使用

4. 屈折用 Render Target にシーンを描画
   └─ 通常カメラ行列 + 水面下 Clip Plane を使用

5. 通常描画パスで水面を描画
   └─ 反射テクスチャ・屈折テクスチャを Fresnel 係数でブレンド
   └─ ノーマルマップのゆらぎで UV を歪ませてリアリティを上げる
```

### 確認ポイント
- [ ] 反射用 RTT に空が描画されている
- [ ] 水面に反射が映り込む
- [ ] 真上から見ると水中が透けて見え、斜めから見ると反射が強くなる

## STEP 5 : Normal Map + PBR ライティング

### 目標
物理ベースのライティングモデルと法線マップを組み合わせて、  
光沢感のあるリアルな水面の質感を表現する。

### 方針
- メッシュの分割数を増やさずに凸凹の表現を行うため、法線マップを使用する
- 2 枚の法線マップを異なる速度・方向でスクロールして重ね合わせることで（Dual Normal Map）、複雑な水面のゆらぎを表現する
- ライティングは PBR（Cook-Torrance モデル）で計算し、物理的に正確な光の振る舞いを再現する
- 遠景の映り込みに IBL（環境マップ）を併用する

### 使用技術

| 技術名 | 役割 |
|--------|------|
| **Normal Map（法線マップ）** | RGB テクスチャに法線ベクトルを格納し、ポリゴン数を増やさずに細かい凸凹の光計算を行う手法 |
| **Tangent Space（接線空間）** | 法線マップの法線が定義されている座標系（接線・従法線・法線の 3 軸）。Vertex Shader で TBN 行列を構築してシェーダーに渡す |
| **TBN 行列** | Tangent（接線）・Binormal（従法線）・Normal（法線）で構成される変換行列。接線空間 → ワールド空間への法線変換に使う |
| **PBR（Physically Based Rendering）** | 物理的に正確な光の反射モデル。Roughness・Metallic・Albedo の 3 パラメータで光の振る舞いを制御する |
| **Cook-Torrance BRDF** | PBR で使われる反射モデル。**D**（法線分布関数）・**G**（幾何減衰関数）・**F**（フレネル項）の積で鏡面反射を計算する |
| **Dual Normal Map Scroll** | 2 枚の法線マップを異なる速度・方向でスクロールして重ね合わせ、複雑な水面のゆらぎを表現する手法 |
| **IBL（Image Based Lighting）** | HDR 環境マップから環境光・環境反射を計算する手法。水平線付近の映り込みをより自然に見せる |

### Cook-Torrance BRDF の各項の役割

| 項 | 関数名 | 役割 |
|----|--------|------|
| **D** | GGX / Trowbridge-Reitz | マイクロファセットの法線分布。Roughness が高いほど広い範囲にハイライトが広がる |
| **G** | Smith / Schlick-GGX | マイクロファセット同士の自己遮蔽・自己シャドウ。斜め方向の光の減衰を表現 |
| **F** | Schlick Approximation | 視線角度による反射率変化（Fresnel）。STEP 4 と同じ式を使用 |

### 水面向け PBR パラメータ目安

```
Roughness       : 0.03〜0.15  滑らかな水面。波が荒れるほど高くする
Metallic        : 0.0         水は非金属
Albedo          : 暗い青緑 (0.05, 0.15, 0.25) 程度
F0（基礎反射率）: 0.02        非金属の水面の標準値
```

### 確認ポイント
- [ ] 太陽光方向にスペキュラハイライトが出る
- [ ] 法線マップが揺れると光の反射が細かく動く
- [ ] 角度によって反射の強さが変わる（Fresnel）

## STEP 6 : FFT Ocean（本格的な海洋シミュレーション）

### 目標
海洋観測データに基づいた統計モデルと FFT を使い、  
本物の海に近い大規模で複雑な波形を GPU 上でリアルタイム生成する。

### 方針
- 初期化時に Phillips Spectrum からランダムな初期スペクトル `H₀(k)` を生成しテクスチャに格納する
- 毎フレーム Compute Shader 上で時間発展を計算し、IFFT で空間ドメインの変位マップを生成する
- 生成した変位マップを Vertex Shader で参照し、頂点を 3 軸方向に変位させる
- 同時に法線マップと Jacobian マップも生成し、ライティングと泡判定に使用する

### 使用技術

| 技術名 | 役割 |
|--------|------|
| **Phillips Spectrum** | 風速・風向から海の波のエネルギー分布（周波数スペクトル）を定義した統計モデル。実際の海洋観測データを基にした数式 |
| **JONSWAP Spectrum** | Phillips Spectrum より精度が高い海洋スペクトルモデル。うねりの集中度合いや発達段階を制御できる |
| **初期スペクトル H₀(k)** | ガウス乱数と Phillips スペクトルの平方根を掛け合わせた複素数テクスチャ。シミュレーション開始時に 1 度だけ生成する |
| **時間発展 H(k,t)** | 初期スペクトルに時間項 `e^(iωt)` を掛けて時刻 t の周波数スペクトルを得る。ω は重力分散関係式から計算 |
| **IFFT（逆高速フーリエ変換）** | 周波数ドメインのスペクトルデータを空間ドメインの波形（高さ場・変位場）に変換するアルゴリズム。計算量 O(N log N) |
| **Butterfly FFT（Cooley-Tukey アルゴリズム）** | IFFT を GPU 上で効率よく実行するための分割統治アルゴリズム。`log₂N` ステージの Butterfly 演算を繰り返す |
| **Compute Shader** | GPU 上で FFT などの汎用計算を大規模並列実行するシェーダー。HLSL の `[numthreads]` 属性でスレッド数を制御する |
| **Displacement Map（変位マップ）** | FFT 結果の X・Y・Z 変位量を格納したテクスチャ（3 チャンネル）。Vertex Shader で頂点に適用する |
| **Jacobian（ヤコビアン）** | 変位場の偏微分から計算される行列式。値が 1 以下になった箇所が波の「崩れ」（白波・泡）の発生点を示す |

### FFT Ocean のデータフロー

```
[初期化時（1 回のみ）]
┌──────────────────────────────────────────────┐
│ ガウス乱数テクスチャ生成 (N×N 複素数)        │
│     ↓                                        │
│ Phillips Spectrum E(k) の計算                │
│   E(k) = A × exp(-1/(k×L)²) / k⁴ × |k̂·ŵ|² │
│     ↓                                        │
│ 初期スペクトル H₀(k) = √(E(k)) × gaussian   │
│     ↓                                        │
│ H₀ テクスチャを GPU に格納                   │
└──────────────────────────────────────────────┘

[毎フレーム（Compute Shader）]
┌──────────────────────────────────────────────┐
│ 時間発展: H(k,t) = H₀(k) × e^(iω(k)t)       │
│     ↓                                        │
│ 変位 X スペクトル: Dx(k) = -i(kx/|k|) H(k)  │
│ 変位 Z スペクトル: Dz(k) = -i(kz/|k|) H(k)  │
│     ↓                                        │
│ 2D IFFT（Row 方向 → Column 方向 の 2 パス）  │
│   高さ場    H(x,t) = IFFT( H(k,t))          │
│   変位 X   Dx(x,t) = IFFT(Dx(k,t))          │
│   変位 Z   Dz(x,t) = IFFT(Dz(k,t))          │
│     ↓                                        │
│ Displacement Map に書き出し（RGB 3 チャンネル）│
│ 法線マップを偏微分から生成                   │
│ Jacobian マップを変位の微分から生成          │
└──────────────────────────────────────────────┘

[描画パス]
┌──────────────────────────────────────────────┐
│ Vertex Shader: Displacement Map を参照し     │
│   頂点を XYZ 方向に変位                      │
│ Pixel Shader: 法線マップ・Fresnel・PBR 適用  │
│   Jacobian マップを泡判定（STEP 7）に使用    │
└──────────────────────────────────────────────┘
```

### Butterfly FFT の実装方針

```
N = 256 の場合:
  log₂(256) = 8 ステージ分の Compute Shader ディスパッチ
  各ステージで Butterfly 演算（回転因子 W = e^(-2πi/N) の掛け算）を実施
  Row 方向（横）→ Column 方向（縦）の 2 パスで 2D IFFT を完成させる

Compute Shader スレッドグループサイズ例:
  [numthreads(N/2, 1, 1)]  // N=256 なら 128 スレッド
```

- **Jerry Tessendorf, "Simulating Ocean Water" (2001)**  
  FFT Ocean のすべての数式の出典となる教科書的論文  
  https://people.computing.clemson.edu/~jtessen/reports/papers/coursenotes2004.pdf

## STEP 7 : SSR / Caustics / Foam（最高品質の演出）

### 目標
スクリーンスペースの高度な演出技術を追加し、  
映像作品レベルのウォーターレンダリングを実現する。

---

### 7-A : SSR（Screen Space Reflection）

#### 方針
- Planar Reflection では映らない動的オブジェクトや複雑な地形の反射を補うため SSR を追加する
- G-Buffer（法線・深度）を利用してポストプロセスとして実装することで、描画パスの追加を最小限に抑える
- 反射が画面端で消える場合は環境マップでフォールバックする

#### 使用技術

| 技術名 | 役割 |
|--------|------|
| **SSR（Screen Space Reflection）** | 既にレンダリング済みの画面バッファを使って反射を計算するポストプロセス手法。Planar Reflection では映らない動的オブジェクトも反射に映る |
| **Ray Marching** | スクリーン空間でレイを 1 歩ずつ進めて深度バッファとの交差点を求めるアルゴリズム。SSR の反射先ピクセル探索に使用する |
| **Depth Buffer（深度バッファ）** | 各ピクセルの深度値を格納したバッファ。Ray Marching の衝突判定に使う |
| **G-Buffer（ジオメトリバッファ）** | 法線・深度・アルベドなどを別々のテクスチャに書き出す Deferred Rendering の中間バッファ群。SSR に必要な情報を揃える |
| **Binary Search（二分探索）** | Ray Marching で大まかに衝突点を見つけた後、より正確な交点を二分探索で絞り込む最適化手法 |
| **環境マップ フォールバック** | 画面外に反射先がある場合にキューブマップで補完し、反射が途切れる破綻を防ぐ |

#### SSR のアルゴリズム概要

```
1. 水面ピクセルの法線から反射レイ方向を計算
   reflect_dir = reflect(-viewDir, normal)

2. ビュー空間で反射レイをスクリーン空間に投影

3. Ray Marching（粗いステップで進む）
   └─ 現在位置の深度と深度バッファの値を比較
   └─ ray の深度 > バッファの深度 → 大まかな衝突点発見

4. Binary Search で交点を精度よく絞り込む

5. 交点のカラーバッファ色を反射色として使用
   └─ 画面外・精度不足の場合は環境マップでフォールバック
```

### 7-B : Caustics（コースティクス）

#### 方針
- 水面で屈折した光が水底に作るゆらめく光のパターンをリアルタイムで表現する
- 実装コストに応じて 2 段階のアプローチを使い分ける
  - **軽量版:** 事前生成したコースティクステクスチャをアニメーションさせる
  - **高品質版:** Compute Shader でレイトレーシングによる正確なコースティクスを計算する

#### 使用技術

| 技術名 | 役割 |
|--------|------|
| **Caustics（コースティクス）** | 水面で屈折した光が水底や水中に作る揺れる光のパターン。水中表現の最も特徴的な視覚効果 |
| **Caustics Texture Animation** | 事前生成したコースティクステクスチャを時間でアニメーションさせる軽量な近似手法。2 枚を min ブレンドすることで輝点を作る |
| **Photon Mapping（フォトンマッピング）** | 光子をシーンに飛ばして屈折を追跡する物理的に正確な手法。高コストのためオフライン・プリベイク向け |
| **Shadow Map Caustics** | シャドウマップを応用してリアルタイムコースティクスを近似する手法。光源から屈折レイを飛ばして輝点テクスチャを生成する |

### 7-C : Foam（泡・白波）

#### 方針
- STEP 6 で生成した Jacobian マップを使い、物理的に正しい場所（波が崩れる箇所）に泡を発生させる
- Jacobian 値が閾値を下回ったピクセルに泡テクスチャをブレンドする
- 泡は時間とともに発生・蓄積・消滅するサイクルを Compute Shader の Foam Accumulation テクスチャで管理する

#### 使用技術

| 技術名 | 役割 |
|--------|------|
| **Foam（フォーム）** | 波の頂点付近に発生する白波・泡の表現 |
| **Jacobian 判定** | FFT 変位場のヤコビアン行列式が閾値以下（波が崩れる箇所）を泡エリアとして判定する物理ベースの手法 |
| **Foam Texture Blend** | 判定した泡エリアに白い泡テクスチャをアルファブレンドする |
| **Foam Accumulation** | 泡の発生・蓄積・消滅を管理するテクスチャ。Compute Shader で前フレームの値に新たな泡を加算し、減衰させることで自然な消え方を表現する |

### 7-D : Depth Fade & Sub-surface Scattering

#### 方針
- 水深に応じて色・透明度を変化させることで、浅瀬と深海の視覚差を作る
- 波の頂部で光が内部散乱することで緑〜ターコイズに透けて見える現象（SSS）を近似する

#### 使用技術

| 技術名 | 役割 |
|--------|------|
| **Depth Fade（深度フェード）** | シーン深度バッファと水面深度の差から水深を計算し、色と透明度を制御する。浅い場所では水底が透け、深い場所では暗い青になる |
| **Sub-surface Scattering（表面下散乱）** | 光が水の内部に侵入して散乱する現象の近似。ライト方向と視線方向の内積・波の高さを使って輝き具合を計算し、ターコイズ系の色を加算する |
