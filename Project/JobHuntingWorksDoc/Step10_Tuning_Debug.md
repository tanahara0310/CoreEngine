# Step 10 : デバッグ / 検証 / RT 最終段

> **状態:** 設計更新済み  
> **目的:** 物理ベース水面の品質確認手段を揃え、最終到達点としてレイトレーシング統合を定義する  
> **位置付け:** 仕上げと将来拡張の接続点

---

## このステップの役割

水面表現は見た目だけでは評価できない。  
反射・透過・吸収・屈折・泡・コースティクスが正しく働いているかを確認するための
**可視化・調整・検証基盤** が必要になる。

さらにこのステップでは、ロードマップの最高地点として
**レイトレーシング統合** を定義する。

---

## 目標

- ImGui / Debug UI を物理パラメータ単位で整理する
- 波高、法線、Fresnel、透過率、吸収量、泡、コースティクス、SSR を可視化する
- 品質確認チェックリストを整備する
- RT 反射、RT 屈折、水中減衰、水中影を最終段として整理する

---

## デバッグで見るべきもの

### 表面系
- 解析法線
- roughness
- Fresnel 係数
- 反射ソース内訳（Planar / IBL / SSR / RT）

### 透過系
- transmittance
- absorption
- shallow / deep color mask
- refraction offset

### 効果系
- foam mask
- caustics intensity
- SSR hit mask
- reflection fallback mask

---

## レイトレーシングを最高地点に置く理由

ラスタライズだけでは次に限界がある。

- 画面外反射
- 正しい屈折経路
- 水中シャドウ
- 複雑な自己反射
- 反射・透過の長経路

これらを高忠実度で扱う最終段がレイトレーシングである。

---

## 最終段で目指すもの

| RT 要素 | 目的 |
|--------|------|
| RT Reflection | 画面外も含めた正確な反射 |
| RT Refraction | 屈折方向に沿った背景取得 |
| Underwater shadowing | 水中へ届く光の減衰と影 |
| Hybrid reflection composition | Planar / SSR / IBL / RT の最適統合 |
| Validation tooling | 各経路の寄与確認 |

- [ ] 反射・透過・吸収・泡・コースティクスを個別可視化できる
- [ ] 品質確認項目がドキュメント化されている
- [ ] RT 反射 / RT 屈折 / 水中影を最終到達点として整理できている
